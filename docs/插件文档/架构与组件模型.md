## 2. `ComponentServices`：10 个端口成员与方法白名单

**记录形态**（`core/ports/ComponentServices.java:10-21`）：`record ComponentServices(Self self, EnergyPort energy, SanTEPort sante, VitalsPort vitals, CooldownPort cooldowns, BuffPort buffs, FactionPort factions, DamagePort damage, TimerPort timers, ComponentLookup components)`。
设计硬约束：**恰好 10 个成员，一个都不许多**（`ComponentServices.java:3-9`）；被删掉的三个成员与理由是 `keys`（组件侧零命中）、`log`（会鼓励就地吞异常）、`hotbar`（渲染是框架职责），见设计 `docs/组件系统设计-Unity风格.md:386-394`。

## 3. 组件模型与生命周期钩子

### 3.1 新基类 `RoleComponent`（已落地）

`roleComponent/RoleComponent.java` 只允许出现三样东西：① `svc` 字段 ② 钩子方法 ③ `getComponent`——任何"顺手加个 helper"都属越界（`:5-16`、设计 `:106`）。

**5 个 default 钩子（框架无条件广播）**：

| 钩子 | 语义 | 出处 |
|---|---|---|
| `awake()` | 装配阶段：只解析跨组件依赖并缓存引用；**幂等**，不得改动任何玩家可见状态 | `RoleComponent.java:72-74` |
| `start()` | 开始生效：初始化数据、发放装备、登记定时器 | `:76-78` |
| `stop()` | 停止生效：**与 start 严格对称**；返回后框架自动回收本组件登记的资源 | `:80-82` |
| `update()` | 20 Hz；禁止阻塞、**禁止直接写热键栏**（渲染由框架负责） | `:86-88` |
| `onSanTEChange(int pre, int now)` | 只在 SanTE **真变化**时派发（`pre == now` 不派发） | `:92-94` |

`svc` 的注入是**过渡期形态**（`bind(ComponentServices)`，`:37-63`）：容器在创建组件后**立刻** `bind`、只允许一次、未绑定时 `svc()` 抛 `IllegalStateException`、组件构造点唯一；**终态要切回构造期注入并删除 `bind`**（五条件见 `:8-15`，设计放行见 `docs/组件系统设计-Unity风格.md:55-61`）。

### 3.2 三个薄基类与能力接口

| 类型 | 形态（现状） | 出处 |
|---|---|---|
| `PassiveSkill` | `extends RoleComponent`，只保留 `displayName`/`description`；**不实现** `HotbarItem`/`HotbarActionable` ⇒ "能不能被施放"是**编译期事实** | `core/PassiveSkill.java:12-25` |
| `ActiveComponent` | `extends RoleComponent implements HotbarItem, HotbarActionable`；持有 6 个 final 字段（displayName/description/icon/cooldownTicks/energyCost/kind）+ 6 个 `final` getter + 默认 `onCast` | `roleComponent/ActiveComponent.java:15-92` |
| `Skill` | `extends ActiveComponent`（kind = `SKILL`），构造参数顺序 `cooldown, energyCost, icon` 未变；保留旧回调 `onRightClick/onLeftClick/onDrop` | `core/Skill.java:22-38` |
| `MainWeapon` | `extends ActiveComponent implements CombatHook`（kind = `MAIN_WEAPON`，**energyCost 恒传 0**）；构造参数顺序 `icon, cooldown` 未变；`onAttack(AttackSignal)` 默认 `CastResult.CAST` | `core/MainWeapon.java:24-49` |
| 能力接口 | `HotbarItem`（7 个 getter）、`HotbarActionable.onCast`、`CombatHook.onAttack` | `core/hotbar/HotbarItem.java:10-24`、`core/dispatch/HotbarActionable.java:4-8`、`core/dispatch/CombatHook.java:4-7` |

**`ItemKind`**（`SKILL` / `MAIN_WEAPON`）只用于两处差异：渲染文案词、是否受沉默影响（`core/hotbar/ItemKind.java:4-7`）。

## 4. 派发管道：`onCast` / `onAttack` / `CastResult`

### 4.1 唯一的结果语言

`core/dispatch/CastResult.java:7-19`：

| 值 | 语义 | 框架动作 |
|---|---|---|
| `CAST` | 施放成功 | **按 `HotbarItem.getCooldownTicks()` 启动冷却** |
| `NO_COOLDOWN` | 组件已自行处理（含"不做事"） | 框架不动冷却 |
| `REJECTED_DISABLED` | 被沉默/眩晕禁用 | 框架给反馈（action bar；冷却中静默） |
| `REJECTED_NO_ENERGY` | 能量不足 | 框架给反馈 |

信号对象只带"这一次的数据"：`CastSignal(CastTrigger trigger)`（`core/dispatch/CastSignal.java:4`）、`AttackSignal(Player victim)`（`AttackSignal.java:6`）；触发来源枚举 `CastTrigger = RIGHT_CLICK / LEFT_CLICK / DROP`（`CastTrigger.java:4-8`）。**施动者永远是 `svc.self().player()`**，不再出现在参数里。

### 4.2 冷却声明值是唯一真值源（设计 4.7 / O-13）

框架在收到 `CAST` 后统一执行 `componentServices.get(component).cooldowns().start(...getCooldownTicks())`（`RoleInstance.java:192` 技能侧、`:211` 攻击侧；两处都在 `handleCast`/`handleAttack` 内）⇒ 组件**不再自己** `startSkillCooldown(getId(), <字面量>)`。今天之所以有这条要求：技能侧 7 处都写自己的字面量，构造参数里的 `cooldown` **从未被技能读取**（设计 `:286` 的陷阱②）。

### 4.3 新旧两条路径与"混合派发"（**这是当前最重要的现状**）

| 路径 | 入口 | 生效条件 | 冷却由谁启动 | 现状 |
|---|---|---|---|---|
| **旧路径** | `listener/SkillListener`、`listener/MainWeaponListener` → `RoleInstance.castSkillRightClick/…` → 组件旧回调 `onRightClick/onLeftClick/onDrop/onAttack` | 该 id 的组件**未迁移**（`isMigrated() == false`） | 组件自己 | 当前 10 个组件里 9 个走这里 |
| **新路径** | **唯一入口** `RoleInstance.handleCast(CastTrigger, Player)`（`:178-196`）；6 个旧入口内部的 `runComponentPipeline(...)`（`:346-350`）**只做委派** `return handleCast(trigger, caster);` | 该 id 的组件**已迁移**（`isMigrated() == true`） | 框架（`CAST` → 声明值） | B① 的 `RedEvilShockSkill` 走这里 |

- 迁移标记：`ActiveComponent.markMigrated()` / `isMigrated()`（`ActiveComponent.java:44-52`，默认 `false`）。**严禁**用 `instanceof ActiveComponent` 当判据：三个基类改基后 **10 个组件都会 instanceof**，未迁移组件会被送进新管道而其 `onCast` 默认是 `NO_COOLDOWN` ⇒ 旧回调永不触发 = 行为静默回归（`:24-31` 的注释原文）。
- **混合期判据只有 `isMigrated()`，没有任何全局开关**：`RoleInstance.java:92` 的注释写明"阶段 4 硬约束 §20：不再有任何全局开关"；原有 `private static final boolean USE_COMPONENT_PIPELINE` **已删除**（全仓 `USE_COMPONENT_PIPELINE` 零命中）。同一判据也在 `handleCast:187` 与 `handleAttack:207` 上重复施加（后者顺带 `((ActiveComponent) component).isMigrated()` 转型判定）。
- 攻击路径：`handleAttack(Player victim, Player attacker)`（`:199-215`）与 `runComponentPipeline` 同构；目前它**没有调用点**（主武器的攻击入口仍由 `MainWeaponListener.onAttackPlayer` 直接走旧回调），因此"主武器迁移"（B⑦）必须同时处理这一入口 —— 属未完成事项。

### 4.4 渲染契约（框架统一渲染，组件不参与）

- 状态判定顺序固定：**冷却 → 禁用 → 能量不足 → 就绪**（`core/hotbar/HotbarRenderer.java:38-49`，状态枚举 `core/hotbar/IconState.java:7-12`）。
- 主武器 `energyCost` 恒为 0 ⇒ 永不进入 `ENERGY_LACK`（`HotbarRenderer.java:33-37`）。
- **空闲 tick 零 setItem**：只有 `markDirty()` 之后帧末 flush 才写物品；刷新触发五类（施放 / 冷却启动 / 冷却到点 / 能量变化 / buff 变化）由端口适配器内部置脏；**组件侧没有 `markDirty` 通道，也没有 `HotbarPort`**（`HotbarRenderer.java:1-14`）。
- **冻结的玩家可见差异**：**技能**冷却名带 `x.xs` 秒数，**主武器**不带（设计 `:206-214`；当前实现 `core/Skill.java:99-108` vs `core/MainWeapon.java:107-110`）。
- **现状**：`HotbarRenderer` 是**骨架**（`dirty` 标志 + 状态判定，**不写任何物品**）；真正的渲染仍由组件的 `createIconItem(RoleInstance)` / `getDisplayName(RoleInstance)` 完成（`core/Skill.java:43-110`、`core/MainWeapon.java:52-118`，以及两个技能各自的覆写 `MeiqiheziBloodySlashSkill.java:100/156`、`MeiqiheziCircleSlashSkill.java:106/162`）。接管属设计 4.4，**尚未落地**。

## 5. 容器的资源回收与生命周期（已落地部分）

- `core/dispatch/ComponentRegistry`（设计 §5.1/§9）：组件集合 + **每组件资源表**（`IdentityHashMap<RoleComponent, List<Task>>`）+ 查找。
  - `register` 只允许在 `freeze()` 之前（`ComponentRegistry.java:25-38`）；
  - `get(Class)` / `getById(String)` 在**冻结前调用 → 抛 `IllegalStateException`**（`:50-79`），把"过早查询"变成响亮的错误；
  - `track(component, task)` 登记资源；`cancelAll(component)` / `cancelAllAndClear()` 在 `stop()` 返回后兜底取消（`:82-112`）。
- `RoleInstance` 侧接线：`initComponents()` 逐组件 `bindAndRegister`（`:221-245`，唯一创建点之后**紧邻** `bind`（`:152-158`））→ `componentRegistry.freeze()`（`:111`）→ `awake`/`start`（`:127-128`）→ ticker（`:130-134`）→ 渲染（`:136`）。
- `clear()`：`triggerLifecycleStop()` → `componentRegistry.cancelAllAndClear()`（`:846`）→ 取消 ticker（`:848-851`）→ 清热键栏 → 移除生命修饰符 → **只回收记账内的药水** → 清 buff / 冷却表 / 上下文（`:840-869`）。
- `TimerPortImpl` 把 `run/runLater/runRepeating` 每个都 `track`（`core/TimerPortImpl.java:24-50`），因此组件即使忘了取消也不会泄漏 —— 但**当前只有端口实现存在，还没有组件在使用它**（见 §6 的计数）。
