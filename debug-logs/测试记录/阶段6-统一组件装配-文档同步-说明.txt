第 0 节 · 一句话
────────────────────────────────────────────────────────────────
把活文档从旧口径（三个窄类型入口 addSkill / addMainWeapon / addPassive、靠继承三个基类获得能力、
"技能 → 被动 → 主武器"三段派发序）同步到统一组件装配口径：

  1. `Role.Builder.addComponent` 的两个重载（带槽位 / 不带槽位）是推荐入口，三个旧方法已标
     `@Deprecated`、仍可用、与新入口走**同一条内部路径**；
  2. `HotbarSpec`（表现规格）+ 能力接口（`HotbarPresentable` / `CooldownBearing` / `EnergyCosting`，
     以及既有的 `HotbarItem` / `HotbarActionable` / `CombatHook`）+ `HotbarPresentable` 的
     **一个实现点 `spec()`**；
  3. **不必继承**三个基类（三者降级为可选的便利实现、未删除），并给出"不属于这三支"的组件组合例；
  4. **权威 kind 在注册处**（`Role.componentKindOf(String)`），理由 = 服务集先于组件构造；
  5. **派发序 = 纯注册序**（不再是三段序）；
  6. 把**已获用户批准**的那条玩法差异落到玩家可见处：`SanTE = 9` 且与「黯然销魂」同 tick 双写时，
     归零惩罚由【触发】变为【不触发】，tick 末 SanTE 由 4 变 3。

零 git 写；零 src 改动；未改任何既有证据与冻结件。
