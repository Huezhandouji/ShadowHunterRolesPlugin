# 初学者指南：看懂这个插件的第一段代码

## 这份文档给谁看

如果你刚开始学编程，会的只有这些 —— **创建变量、给变量赋值、用列表装东西、写 `if`、写循环、写带参数和返回值的函数** —— 那这份文档就是写给你的。

读完它你能做到三件事：

1. 说清楚这个插件在游戏里到底做了什么（不看代码也能说得出来）；
2. 打开仓库里一个**真实的技能文件**，一行一行看懂它在写什么；
3. 亲手改一个数值，把它构建出来，进游戏看见行为变化。

这不是一本参考手册。命令清单、全部角色数值、内部结构这些"查得到"的东西在另外几份文档里，本文最后会告诉你去哪看。

**假定你会**：变量与赋值、列表 / 数组、`if`、循环、函数（带参数与返回值）、基本算术、字符串。

## 一、这个插件在游戏里做了什么

先完全不看代码，只看玩家能看见的四步：

1. 玩家进服，输入一条命令选角色，例如 `/role set meiqihezi`；
2. 屏幕下方的**快捷栏**立刻被摆好：第 0 格是主武器，第 1、2、3 格是三个技能；
3. 玩家拿着某个技能，按右键（或左键、或丢弃键 `Q`）就能把它放出去，屏幕上出现音效与粒子；
4. 放完之后，那一格的图标**变灰**、名字后面开始**倒数**；数到 0 之后图标恢复成原来的样子，又能再放一次。这个"暂时不能再放"的状态就是**冷却**。

所以：这个插件给玩家一套"技能包"，并负责技能什么时候可以放、放完要等多久、图标长什么样。这就是它全部的对外表现。

## 二、代码里的三层：角色 → 组件 → 技能 / 被动 / 主武器

### 先用一张清单来理解

想象你写过一个函数来管理背包：

```
背包 = 空列表
背包.添加("铁剑", 位置=0)
背包.添加("火球术", 位置=1)
```

这个插件里的**角色**就是这种东西：一张清单。清单上写着"这个角色的 0 号位放哪个主武器、1 到 3 号位放哪些技能、另外还挂上哪些被动"。

清单本身真的就写在代码里。打开 `src/main/java/com/shadowHunterRolesPlugin/registry/RoleLoader.java`，你会看到一个列表，里面有两项（两个角色）：

```java
return List.of(
        new Definition("meiqihezi", RoleLoader::meiqiheziBuilder),
        new Definition("red", RoleLoader::redBuilder)
);
```

`List.of(...)` 就是"造一个列表"，列表里两项分别是 `meiqihezi` 与 `red`。往下看 `meiqiheziBuilder()`，你会看到那个清单是怎么被填的：

```java
return new Role.Builder("meiqihezi")
        .addSkill(ID_MEIQIHEZI_UNCONCERN, MeiqiheziUnconcernSkill::new, 1)
        .addSkill(ID_MEIQIHEZI_BLOODY_SLASH, MeiqiheziBloodySlashSkill::new, 2)
        .addSkill(ID_MEIQIHEZI_CIRCLE_SLASH, MeiqiheziCircleSlashSkill::new, 3)
        .addMainWeapon(ID_MEIQIHEZI_JUEJUE_MAIN_WEAPON, MeiqiheziJuejueMainWeapon::new, 0)
        .addPassive(ID_MEIQIHEZI_EQUIPMENTS, MeiqiheziEquipmentsPassive::new);
```

读法：`addSkill(某个名字, 用哪个类来造, 放在第几格)`。`addMainWeapon` 比技能多写了一个数字 `0`，意思就是"放 0 号位"。`addPassive` 后面没有格子号 —— 被动不占快捷栏。

### 三层关系

| 层 | 是什么 | 在哪里 |
|---|---|---|
| 角色模板 | "清单"本身：有哪些技能、哪些被动、哪个主武器、血量能量上限 | `src/main/java/com/shadowHunterRolesPlugin/registry/RoleLoader.java` |
| 组件 | 清单上的每一件东西（技能 / 被动 / 主武器） | `src/main/java/com/shadowHunterRolesPlugin/roleComponent/` 目录下 |
| 关系 | 玩家输入 `/role set meiqihezi` 时，程序照清单给**这个玩家**每一件东西各造一个副本挂上去 | `manager/RoleManager.selectRole` → `core/RoleInstance` 的构造流程 |

三类组件的分工：

- **技能**：玩家按键才动，有冷却、可能有能量消耗；
- **被动**：玩家不按键也一直在后台干活（例如"周围没有敌人时每秒回能量"）；
- **主武器**：占 0 号位，攻击玩家或左键时动。

## 三、读代码前先补六个词

下面每个词都配一个**本仓库真实文件里的最短例子**。想亲眼看到那一行，把命令粘进仓库根目录的 PowerShell（`--` 后面的 `src/main/java` 表示"只在这个目录里找"）。

### 类（class）

**打比方**：你写过函数 `计算伤害(目标, 数值)`。**类是一张"模板 + 造物机"的合体**：它既描述"这种东西内部有哪些变量、能调用哪些函数"，又能照着自己造出一个一个具体的这种东西。

例子：`src/main/java/com/shadowHunterRolesPlugin/roleComponent/RoleComponent.java` 里的

```java
public abstract class RoleComponent {
```

命令：`git grep -n "public abstract class RoleComponent" -- src/main/java`

（开头的 `public abstract` 现在只要理解成"这是一张模板，而且不能直接拿它造东西，只能被别人继承"。）

### 对象（object）

**打比方**：类 = 表格模板，对象 = 照模板填出来的一张具体的表。你写循环 `for 每个物品 in 列表`，列表里的每一项就是一个对象。

例子：`src/main/java/com/shadowHunterRolesPlugin/core/hotbar/HotbarRenderer.java` 里的

```java
ItemStack stack = new ItemStack(material);
```

`new` 这个动作就是"照模板造一个出来"，`stack` 是用来接住它的变量。

命令：`git grep -n "new ItemStack(material)" -- src/main/java`

### 方法（method）

**打比方**：方法**就是函数**，唯一的区别是它挂在某个对象（或类）身上，用点号调用 —— `对象.方法(参数)`。你写的 `回血(玩家, 4)` 在这里会写成 `vitals.heal(4)`。

例子：`src/main/java/com/shadowHunterRolesPlugin/roleComponent/RoleComponent.java` 里的

```java
public final String getId() {
```

命令：`git grep -n "public final String getId" -- src/main/java`

### 字段（field）

**打比方**：字段**就是变量**，只是它不写在函数里面，而是写在类里面，跟着对象一起存在。函数里的局部变量，函数一结束就没了；字段会一直留着。

例子：`src/main/java/com/shadowHunterRolesPlugin/roleComponent/RoleComponent.java` 里的

```java
private final String id;
```

每个组件对象都有自己的一份 `id`（比如 `meiqihezi_skill_unconcern`）。

命令：`git grep -n "private final String id;" -- src/main/java`

### 继承（inheritance）

**打比方**：**继承 = "把别人的定义整个抄过来，再写自己不同的部分"**。你写过一个通用函数 `伤害计算(目标, 数值)`；继承就像新函数默认就拥有它，你只要再补额外步骤。

例子：`src/main/java/com/shadowHunterRolesPlugin/roleComponent/meiqiHezi/skill/MeiqiheziUnconcernSkill.java` 里的

```java
public class MeiqiheziUnconcernSkill extends Skill {
```

读作"`MeiqiheziUnconcernSkill` 是一种 `Skill`（技能）"。因为是技能，它自动就有了技能的字段和方法（比如上面那个 `getId()`），自己只需要写"这个技能具体干什么"。

命令：`git grep -n "class MeiqiheziUnconcernSkill" -- src/main/java`

### 接口（interface）

**打比方**：**接口是一张"必须提供的函数清单"**，只写函数名和参数，不写做法。谁照着它写，谁就必须把这些函数都提供出来。

例子：`src/main/java/com/shadowHunterRolesPlugin/core/ports/VitalsPort.java` 里，整个接口只有一行函数：

```java
public interface VitalsPort {
    void heal(double amount);
}
```

命令：`git grep -n "interface VitalsPort" -- src/main/java`

## 四、游戏是怎么"走"起来的：tick 和事件

### tick

**打比方**：把服务器想成一台不停转的唱机，**每 1/20 秒转一圈**。每转一圈，插件就把它该做的事做一遍。这一圈就叫一个 **tick**（可以理解成"一帧时间"）。

代码里对应的两件事：

- 谁在转圈：`src/main/java/com/shadowHunterRolesPlugin/core/RoleInstance.java` 里注册了一个"每 1 tick 执行一次"的任务：

```java
updateTask = platform.scheduler().runRepeating(this::triggerUpdate, 1L, 1L);
```

`this::triggerUpdate` 的意思是"把 `triggerUpdate` 这个函数本身交出去"（就像你把函数名当参数传给闹钟），后面的两个 `1L` 是"第一次等 1 tick、之后每 1 tick 一次"。

- 每转一圈被调用的方法：**`update()`**。它定义在 `roleComponent/RoleComponent.java`：

```java
public void update() {
}
```

基类里它是空的（什么都不做），某个组件需要"每 tick 干活"就重写它。真实的例子：`src/main/java/com/shadowHunterRolesPlugin/roleComponent/AutoRecoverEnergyPassive.java` 的 `update()` —— 它每 tick 检查周围有没有敌人、默默数秒，攒够时间就给自己加 3 点能量。

### 事件

**打比方**：**事件就是门铃**。插件不会一直盯着"玩家有没有按右键"，而是在门铃上登记一条："门铃响了，就执行这个函数。"玩家按下右键，门铃响一次，你写的那段代码才被调用一次。

代码里对应的动作：

- 登记门铃的函数，头上有一个注解 `@EventHandler`；
- 例子：`src/main/java/com/shadowHunterRolesPlugin/listener/SkillListener.java` 的

```java
@EventHandler
public void onPlayerRightClickSkillItem(PlayerInteractEvent event){
```

读作"当玩家右键时，执行 `onPlayerRightClickSkillItem`"，参数 `event` 是这次事件的详细信息（谁按的、手里拿的什么）。

- 另一个例子：`listener/PlayerListener.java` 的 `onPlayerQuit(PlayerQuitEvent event)` —— 玩家退出时被调用，这个插件在它里面清掉该玩家的角色。

## 五、逐行读一个最短的技能

打开 `src/main/java/com/shadowHunterRolesPlugin/roleComponent/meiqiHezi/skill/MeiqiheziUnconcernSkill.java`。这是仓库里最短的完整技能之一：游戏里叫「漫不经心」，效果是给自己加速 2 秒。

### 开头两行

```java
public class MeiqiheziUnconcernSkill extends Skill {
```

"这是一个技能"（继承自 `Skill`）。它因此自动拥有技能该有的东西：id、显示名、描述、冷却、能量消耗、图标，以及 `getId()`、`getCooldownTicks()` 这些方法。

### 构造函数：造对象时自动执行

```java
    public MeiqiheziUnconcernSkill(String id, ComponentServices services){
        super(
                id,
                services,
                Component.text("漫不经心"),
                Component.text("获得2秒速度5"),
                100,
                0,
                Material.BLAZE_POWDER
        );
    }
```

逐行读：

- 这个函数的名字和类名一模一样 —— 这种函数叫**构造函数**，造对象时自动执行一次，用来把对象初始化好；
- `super(...)` 的意思是"把这些信息交给我继承的那套模板（`Skill`）去存好"；
- `id` 与 `services` 是框架传进来的：`id` 是这个组件在清单上的名字，`services` 是稍后会讲到的"工具箱"；
- `Component.text("漫不经心")` 是显示名，`Component.text("获得2秒速度5")` 是描述 —— 玩家在图标上看到的字就是这两个；
- `100` 是**冷却**，单位是 tick：100 ÷ 20 = **5 秒**；
- `0` 是**能量消耗**，这个技能不耗能量；
- `Material.BLAZE_POWDER` 是图标用的物品材质（烈焰粉）。

想看这些参数在模板里怎么被接收，可以看 `src/main/java/com/shadowHunterRolesPlugin/core/Skill.java` 的构造函数 `public Skill(String id, ComponentServices services, Component displayName, Component description, int cooldown, int energyCost, Material icon)`。

### 施放函数：玩家按下技能时发生什么

```java
    @Override
    public CastResult onCast(CastSignal signal){
        Player caster = svc().self().player();
        if(!svc().buffs().canCastSkill()) return CastResult.NO_COOLDOWN;

        svc().buffs().applyPotionEffect(PotionEffectType.SPEED, 40, 4);

        caster.getWorld().playSound(
                caster.getLocation(),
                Sound.ITEM_TRIDENT_RIPTIDE_1,
                1f,
                1f
        );

        caster.getWorld().spawnParticle(Particle.EXPLOSION, caster.getLocation(), 1);

        svc().cooldowns().start(getCooldownTicks());
        return CastResult.SUCCEED;
    }
```

逐行读：

- `@Override` 是一个**注解**，意思是"我在这里重写父类里同名的函数"。名字或参数写错时编译器会报错，相当于给你的实现盖了个章；
- `onCast(...)` 是技能被触发时框架**会来调用**的函数（名字固定，不能随意改）；
- `CastResult` 是"这次施放的结果"，是一个只能取几个固定值的类型（下面两个都在用）；
- `Player caster = svc().self().player();` —— 这一行要单独讲，见下一小节；
- `svc()` 是"向框架要工具箱"，`svc().buffs()` 是工具箱里管**控制效果**的那一格；
- `canCastSkill()` 问的是"现在允许放技能吗"（被沉默或被眩晕时不允许）。不允许就 `return CastResult.NO_COOLDOWN;` —— 返回"什么都没做，也别进冷却"；
- `applyPotionEffect(PotionEffectType.SPEED, 40, 4)` 给自己施加**速度**效果：40 tick = 2 秒；（第 3 个参数 `4` 是游戏里的增幅档位，游戏内的等级显示为 5 级 —— 这个插件里"增幅 0"对应游戏里的 I 级）；
- `playSound(...)` 与 `spawnParticle(...)` 是音效与粒子，给玩家的即时反馈；
- `svc().cooldowns().start(getCooldownTicks())` 是**开始冷却**：`getCooldownTicks()` 是继承来的方法，读出来的正是构造里写的那个 `100` —— 这就是"字段"的意义：写一次，之后谁都读得到；
- `return CastResult.SUCCEED;` 表示"这次施放成功了"（框架据此给玩家反馈，并让图标进入冷却态）。

一句话总结这个文件的形状：**在构造函数里声明自己的名字与数值，然后写"被按下时做什么"**。仓库里其它技能都是这个形状，只是中间那段更长。

### 为什么要"每次现取玩家"

```java
Player caster = svc().self().player();
```

这行做的是：每次施放，都当场问一句"我这个组件现在挂在哪个玩家身上"，把答案放进一个**局部变量** `caster`，只在本次函数里用。

**不要把玩家对象存进字段。** 因为：

- 玩家会掉线。这个插件在玩家退出时就把角色清掉了（`listener/PlayerListener.java` 的 `onPlayerQuit`）；
- 字段会一直留着，于是里面握着的可能是"已经不在这一局里的玩家"；
- 之后你用它做任何事（加血、放音效），都可能在对着一个不存在的人操作。

所以规矩是：**用的时候现取；真要长期记住一个人，就记住不会变的编号**（例如玩家的 `UUID`）。真实的对照例子：`src/main/java/com/shadowHunterRolesPlugin/roleComponent/red/RedBleedPassive.java` 里用 `Map<UUID, Integer> playerBleedRecord` 记"谁身上有几层流血" —— 键是编号，不是玩家对象。

同样的写法在别处也能看到：`roleComponent/meiqiHeZi/passive/MeiqiheziEquipmentsPassive.java` 的 `start()` 与 `stop()` 都是第一行就 `Player player = svc().self().player();`。

## 六、动手改第一个数值

目标：把「漫不经心」的冷却从 5 秒改成 10 秒，然后在游戏里亲眼看见图标倒数变长。

### 第 1 步：改代码

打开 `src/main/java/com/shadowHunterRolesPlugin/roleComponent/meiqiHezi/skill/MeiqiheziUnconcernSkill.java`，在构造函数里找到那个 `100`（第 5 个参数），改成 `200`：

```java
                200,          // 原来是 100
                0,
                Material.BLAZE_POWDER
```

`200` tick ÷ 20 = **10 秒**。

> 改数值时记住单位是 tick：**1 秒 = 20 tick**。

### 第 2 步：构建

```powershell
cd ShadowHunterRoles
$env:GRADLE_USER_HOME = "$PWD\.gradle-work"
.\gradlew build -x copyPluginJar --console=plain
```

- 第一行进入仓库目录；第二行把构建工具的缓存放在仓库内（避免写系统目录，也可以不写）；
- 第三行开始构建。看到 `BUILD SUCCESSFUL` 就算成功，产物是 `build/libs/ShadowHunterRolesPlugin-1.0.0.jar`；
- `-x copyPluginJar` 表示跳过"自动把 jar 拷到服务端目录"这一步。如果你在 `gradle.properties` 里配置过 `pluginCopyPath` 指向服务端的 `plugins` 目录，去掉这个参数就会顺手帮你拷贝。

### 第 3 步：起本地服务端

```powershell
.\gradlew runServer
```

- 它会拉起一个 Paper 1.21.11 调试服，服务端目录是仓库里的 `run/`；
- **端口是 25566**（写在 `run/server.properties` 的 `server-port`），客户端连 `localhost:25566`；
- 控制台出现 `ShadowHunter Character System enabled.` 表示插件已加载；
- 这一步是阻塞的：服务端在跑，这个窗口就一直在。结束时在服务端控制台里输入 `stop` 回车。

### 第 4 步：进游戏验证

1. 进服后输入 `/role set meiqihezi`；
2. 按 `1` 选中快捷栏第 1 格（「漫不经心」），**右键**放一次；
3. 看那一格图标：它变灰，名字后面开始显示剩余秒数；
4. 对比：改之前是从大约 5 秒开始倒数，改之后从大约 10 秒开始 —— 这说明你改的数值生效了；
5. 等倒数走完，图标恢复成原来的样子，可以再放一次。

### 第 5 步：改回去

把 `200` 改回 `100`，再执行第 2 步的构建即可。代码改回去、服务端重启后，行为也跟着回去。

## 七、常见困惑问答

**问：我改了代码，游戏里却一点变化都没有，为什么？**

最常见是三个原因：① 忘了重新构建（第 2 步）；② 构建了但服务端还在跑旧的那份，需要重启；③ 你以为 jar 会自动拷到服务端，其实只有在 `gradle.properties` 里配置了 `pluginCopyPath` 才会（`build.gradle.kts` 的 `copyPluginJar`）。

**问：为什么技能图标是灰的，名字后面还跟着一串秒数？**

它在冷却中。冷却中的图标会被换成灰色虚空方块，名字后面追加剩余秒数（形如 ` x.xs`）；这一整套图标外观由 `src/main/java/com/shadowHunterRolesPlugin/core/hotbar/HotbarRenderer.java` 的 `applySkill` 生成。

**问：为什么图标变成了红色、名字后面写着 DISABLED？**

你被**沉默**或**眩晕**了。技能是否允许施放由 `manager/BuffManager.java` 的 `canCastSkill()` 判断（眩晕或沉默都不许），渲染器据此给出红色 ` DISABLED` 外观。

**问：图标上写着 ENERGY LACK 是什么意思？**

能量不够放这个技能。判定在 `core/hotbar/HotbarRenderer.java` 的 `stateOf(...)`。顺带一提：**主武器永远不会**出现这个状态 —— 它的能量消耗恒为 0（见 `core/MainWeapon.java` 的构造函数）。

**问：我按了技能，却什么也没发生？**

一般是这四种：① 被沉默 / 眩晕；② 冷却还没走完；③ 能量不够；④ **这个技能只认某一种按键**。第 ④ 种很容易被忽略，例如 `roleComponent/red/RedDeeplySorrowSkill.java` 的 `onCast(...)` 开头就要求触发来源必须是右键，用左键或 `Q` 不会生效。

**问：为什么我掉线再上来，角色没了？**

这个插件的设计就是"掉线即清除角色"。玩家退出时 `listener/PlayerListener.java` 的 `onPlayerQuit(...)` 会调用 `RoleManager.clearRole(...)`，角色连同它的技能、被动一起被回收；重新进服要再 `/role set` 一次。

**问：为什么技能物品丢不掉？**

丢不掉是故意的：`listener/SkillListener.java` 的 `onPlayerQDropSkillItem(...)` 会把"丢弃"取消掉，并把这次按键当成一次施放。主武器同理（`listener/MainWeaponListener.java` 的 `onQDrop`）。
