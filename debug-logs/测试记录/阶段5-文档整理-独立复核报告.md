## §1 复核方法、仪器与自曝（先说会骗人的地方）

**仪器清单（全部先证可调用 + 打印两侧计数/非空样本）**：

| 用途 | 仪器 |
|---|---|
| 文本检索（权威） | `git grep -nE -f <模式文件>`（**大小写敏感**、**模式先落盘**，避开命令行 CJK 转码）· `git grep -o` 取出现次数 |

| 身份 | `[System.IO.File]::ReadAllBytes` / `Get-Item` / `Get-FileHash` / `git hash-object` |

| 结构与集合 | `git diff --numstat <commit> -- <path>` / `git ls-files` / `git check-ignore --no-index -v` |

**⚠️ 本轮我自己踩到并当场纠正的 3 个仪器坑（如实自曝，均不影响最终结论；每一处都打印了可复现的两侧读数）**：

1. **`git show <rev>:<path> | Set-Content` 会静默丢字节** ✗：首次提取旧侧 5 份得到 14212 / 35382 / 52711 / 40325 / 20991 B，比 blob 尺寸（14402 / 35808 / 53075 / 40724 / 21211）**各少 190~426 B**（PowerShell 管道解码/重编码所致）。⇒ 改为 **`git cat-file blob <sha>` + `cmd /c` 原始重定向**后，**5/5 与 blob 尺寸逐字节相同**，且 `git hash-object` 复算的 SHA 与 blob 名逐条相同。**纪律**：取"某一代"的**内容本体**必须走 blob/重定向，不得走 PowerShell 文本管道。
2. **`git grep` 不搜未跟踪/被忽略件 ⇒ 对 `.scratch/` 里的旧侧样本返回假 0** ✗：同一命令对同一模式，**不加 `--no-index` 时 = 0 行**、加上后 = **63 行**（两条读数都在 §3.1 表里）。⇒ 我的旧侧一律 `--no-index`；这正是 `git grep` 族的假绿（台账 §7 族 8/20）。
3. **脚本执行环境 = Windows PowerShell 5.1（非 pwsh 7）**：`pwsh` 不存在、`ExecutionPolicy` 禁止 `.ps1`；且 5.1 对**无 BOM** 的 UTF-8 脚本按 ANSI 解码（CJK 会错）。⇒ 我把脚本写入 `.scratch/t10/` 后**补 UTF-8 BOM** 并用 `Invoke-Expression ([IO.File]::ReadAllText($p, UTF8))` 执行；`Get-FileHash`/`git cat-file` 属程序输出，不受影响。
