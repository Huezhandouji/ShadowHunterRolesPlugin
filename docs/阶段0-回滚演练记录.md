## 2. 演练步骤（**逐步命令**，可复现）

```powershell
$root  = "C:\Users\ROG\Desktop\插件\ShadowHunterRoles"
$snap  = "$root\docs\回滚快照"
$drill = "$snap\drill"; $restored = "$drill\restored"

# 步骤 1：逐文件拷回（模拟真实回滚；本次落在 drill\restored\ 下，保持与真实目标相同的相对路径）
$beforeFiles = Get-ChildItem -LiteralPath "$snap\before" -Recurse -File | Sort-Object FullName
foreach ($f in $beforeFiles) {
  $rel  = $f.FullName.Substring("$snap\before".Length + 1)   # 形如 src\main\java\...
  $dest = Join-Path $restored $rel
  New-Item -ItemType Directory -Path (Split-Path $dest) -Force | Out-Null
  Copy-Item -LiteralPath $f.FullName -Destination $dest -Force
}

# 步骤 2：三方比对 —— drill 副本 == before 副本 == integrity-sha256.txt 登记值
$rec = @{}
foreach ($line in Get-Content -LiteralPath "$snap\integrity-sha256.txt" -Encoding utf8) {
  if ($line -match '^([0-9A-F]{64})\s{2}(\S+)\s+OK$') { $rec[$Matches[2]] = $Matches[1] }
}
# 逐文件 Get-FileHash -Algorithm SHA256 比对（完整代码见 drill\SHA256-selfcheck.txt 表头口径）
```

**真实回滚时**把步骤 1 的目标换成仓库根即可（**只对本次实际改动过的文件执行**，不要整目录覆盖 —— 整目录覆盖会连带重置未改动文件的 mtime）：

```powershell

Copy-Item "ShadowHunterRoles\docs\回滚快照\before\$rel" "ShadowHunterRoles\$rel" -Force
```

## 4. 判定标准（**拷回后逐文件哈希一致** 且 **构建可重建**；**真要回滚时**照此判定，缺一不可）

| # | 标准 | 判据 | 失败处置 |
|---|---|---|---|
| ① | **逐文件哈希一致** | 对每个还原文件 `Get-FileHash -Algorithm SHA256`，与 `docs\回滚快照\integrity-sha256.txt` 的登记值**逐条相等** | 任一处不等 → 还原失败，重做该文件（不要继续往下走） |
| ② | **构建可重建** | `cd ShadowHunterRoles; $env:GRADLE_USER_HOME="$PWD\.gradle-work"; .\gradlew build -x copyPluginJar --console=plain` → 输出含 **BUILD SUCCESSFUL**，且 `build\libs\ShadowHunterRolesPlugin-1.0.0.jar` 与 `build\classes` 的 mtime **已刷新**（**不得以退出码判定**，见 §6.3） | 构建失败 → 还原不成立，回滚到 `after-baseline/` 再排查 |
| ③ | **新增文件已删除** | 还原前先记录 `git status --porcelain` 得到"本次新增文件"清单（**新增文件不在 `before/` 中**，还原不会覆盖它们）→ 逐个删除 | 漏删会导致"旧代码 + 新文件"混合态 |
| ④ | **不改快照本身** | `before/` 与 `after-baseline/` 的**逐文件哈希与最大 mtime**在还原前后不变 | 若变化 → 立即停止，快照被污染 |

> ⚠️ **不得**用 `git checkout <文件>` / `git restore` / `git stash` 作为回滚手段（§6.1 第 2 条：工作树含作者未提交改动，且其中 3 个文件与重构范围重叠，整体还原会抹掉作者的工作）。
