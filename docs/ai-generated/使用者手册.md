## 1. 这个插件在游戏里做什么

一段话：**ShadowHunterRolesPlugin 给玩家"上角色"。** 一个角色 = 一套**数值**（生命上限、基础攻击、能量上限、SanTE 上限）
+ 一套**组件**（3 个主动技能 + 1 把主武器 + 若干被动，如自动回能、自动回 SanTE、穿戴护甲、流血、SanTE 归零惩罚）。
管理员用 `/role set <角色id> [玩家名]` 把角色装到某个在线玩家身上，**立刻**生效：生命上限被改、护甲被穿上、
屏幕下方的热键栏 0–3 槽出现该角色的技能与主武器物品（物品名、图标、说明、就绪/冷却/禁用状态都是插件写的）。
玩家用**右键 / 左键 / Q 丢**去使用这些物品。清角色（`/role clear`）会把上面这些**全部收回**。

- 插件本身**只做角色系统**；"谁该被分到什么角色"通常由别的游戏插件决定 —— 本插件把公开接口注册为服务
  （`RoleAPI`，来源：`ShadowHunterRolesPlugin.java:107`；接口定义：`api/RoleAPI.java`），
  也可直接用指令装配（§3）。
- 角色是**跟着人**的：**死亡**与**掉线**都会自动清掉角色（来源：`listener/PlayerListener.java:21-28`（死亡）、`:39-43`（掉线）），
  **重生**会再清一次热键栏（来源：`listener/PlayerListener.java:30-34`）。详见 §6 Q5。
- 插件**没有**"角色列表"指令；角色 id 见 §4，或直接 `/role set ` 之后按 **Tab**（补全读的是注册表里的 id，来源：`command/SetRoleCommand.java:59`）。

## 3. 指令

### 3.1 先读这一节：谁能敲 `/role`

本插件的**唯一权限口径**是**等级（op level）**，不是权限节点（来源：`command/CommandAccess#check()`）：

| 发送者 | 是否放行 | 依据 |
|---|---|---|
| 玩家，且 `ops.json` 里等级 **≥ 要求等级** | ✅ 放行 | `command/CommandAccess#check()` |
| 玩家，等级 < 要求等级（**含不在 `ops.json` 里**） | ❌ 拒绝 | 同上（不在表里按等级 0 计） |
| **控制台 / RCON** | ✅ 放行（等价等级 4） | `command/CommandAccess#check()` |
| 其它（如命令方块） | ❌ 拒绝 | `command/CommandAccess.java:125-126` |

- **要求等级默认 = 3**（来源：`ConfigurationManager#COMMAND_PERMISSION_LEVEL`）。
- 要求等级是**配置字段** `command-permission-level`，写在插件数据目录的 `config.yml` 里：
  取值域 **0–4**（越界自动夹取），默认 **3**（来源：`ConfigurationManager#COMMAND_PERMISSION_LEVEL`）。
  **改完不需要重启**：配置带 5000 ms 缓存 + 文件一变动立即失效 ⇒ 最迟约 5 秒生效
  （来源：`ConfigurationManager#TTL_MILLIS`；★ 两个符号各覆盖一段：`command/CommandAccess#check()`（**门禁判定**，实现见 `CommandAccess.java:110-127`；★ 类级 javadoc 的「生效时效」段 = `CommandAccess.java:44-46`）与 `command/CommandAccess#refreshIfStale()`（**带缓存的 ops.json 读盘**，`:156-160` 的缓存失效段；`:176-186` 是 **catch 的失败关闭段**，不是缓存段））。
- **判定结果每次都写服务端日志**，形如 `[command-access] allowed /role for <玩家> (level=4, required=3)`
  （来源：`command/CommandAccess.java:117-118`）⇒ 排查"为什么我被拒"直接看这一行。
- 玩家侧被拒时只看到一句：`You do not have permission to use this command.`
  （来源：`CommandAccess#NO_PERMISSION`）。
- **同门禁也管 Tab 补全**：等级不够时连子指令名都不会补出来（来源：`command/RoleCommand.java:101`、`DebugCommand#onTabComplete`）。
- ⚠️ **失败关闭**：`ops.json` 缺失 / 读不动 / 内容不是合法 JSON / 有条目缺 `name` 或 `level`
  ⇒ **该文件整体视为不可信 ⇒ 所有玩家一律拒绝**，并在服务端日志打一条含原因的 `SEVERE`
  （来源：`command/CommandAccess#parse()`）。

   该指令的注册点在 `command/RoleCommand.java:51`，名字 `operation` 在

5. `/role help` 打 **9 行**：1 行标题 + 8 行用法（`set`×2 / `clear`×2 / `energy`×2 / `debug` / `operation`）

   以外的一级子指令细节**，也不列角色 id（见 §6 Q10 与 §3.2 上表）。

## 5. 机制分节

### 5.1 能量

**玩家看到什么**
- 能量是一个 0 到"角色能量上限"之间的整数。**任何写法都改不出范围外的值**：设 999 会变成上限，设 −5 会变成 0。
- 需要能量的技能在能量不足时，物品材质变成**结构空位（STRUCTURE_VOID）**，名字后面多一个 ` ENERGY LACK`，
  而且**这一态没有状态行**（即：只有说明文字，没有"Skill is ready."那类一行）
  （来源：`roleComponent/base/Skill.java:191-192`；材质映射 `roleComponent/frameworkLevel/hotbar/IconState.java:42-48`）。
- 能量一变，热键栏就重画一次 ⇒ 你会**当场**看到上面那个状态变化（来源：`core/RoleInstance.java:190` ——
  容器注册的那条监听器无条件置脏）。
- 能量的每次变化（**包括"没有真变化"的写入**）都会通知容器注册的监听器一次；
  组件自己的监听器列表是**唯一**的变更通道 ✓ —— 本插件**不再发布 Bukkit 事件**，
  所以没有"供别的插件监听的事件"这一类挂点（来源：`roleComponent/frameworkLevel/EnergyComponent.java:186-190`
  的 `set` 与 `:168-172` 的 `notifyListeners`）。

### 5.2 SanTE 与「归零惩罚」

**玩家看到什么**
- SanTE 同样是 0 到上限（本仓库三个角色上限都是 100）之间的整数，**同样会被夹取**。
- **SanTE 归零**会触发「惩罚」，现象是（来源：`roleComponent/builtin/DefaultSanTEZeroPunishment.java`）：
  1. **屏幕中央出现一行字**：阵营是 HUNTER 的角色看到 `⊠恐惧正在注视着你⊠`（浅紫色），
     阵营是 SHADOW 的角色看到 `⊠痛苦摸上脊背⊠`（黄色），持续 **5 秒**
     （来源：`:213-247`；两种阵营各自的分支在 `:223-232` / `:233-242`）。
  2. **被眩晕（STUN）5 秒**：不能放技能、也不能用主武器；伴随**失明（blindness）**与**黑暗（darkness）**两个原版效果，
     并把移动速度压到底（来源：`:201` 施加 `BuffType.STUN, 100`（100 刻 = 5 秒）；
     眩晕的两个原版效果见 `manager/BuffManager.java:120-130`，移动速度修饰符见 `:54-58`）。
  3. **期间会持续掉血**：每 40 刻（2 秒）一次**真实伤害**，每次约为**最大生命的 10%**
     （= `最大生命 × 0.3 × 0.33333`），共 **3 次**
     （来源：`:164` 每 40 刻一跑、`:169-170` 计算单次量、`:254` 结算、`:187-192` 第 4 跳前收尾）。
  4. **整个惩罚期间 SanTE 被"钉"在 0**：每一刻都被写回 0，期间别的组件想把它抬起来也会立刻被按回去
     （来源：`:134-139`）。
  5. **眩晕结束那一刻 SanTE 一次性回满**（不是第 3 跳回满）：回满安排在施加 STUN 的同一跳，延后 100 刻执行
     （来源：`:206-212`）。
  6. **惩罚进行中不会重复触发 / 不会延长**（来源：`:152-153` 的重入守卫）。
- 有 10 秒钟"周围 10 格没有敌人"的条件才会自动回 SanTE（见 §4.2 被动），而且 **SanTE 已经是 0 时不回**
  （来源：`roleComponent/builtin/AutoRecoverSanTEHealthPassive.java:57`、`:59-66`）。

### 5.3 阵营与敌对

**玩家看到什么**
- 阵营有三档：**SHADOW（暗影）/ HUNTER（猎人）/ UNKNOWN（未定）**
  （来源：`core/Faction.java:3-7`）。本仓库三个角色的阵营见 §4.1。
- **判定规则**（两处判定口，口径一致）：**阵营不同 ⇒ 敌对**；**自己是 UNKNOWN ⇒ 对谁都敌对**
  （来源：`ShadowHunterRolesPlugin.java:64-68`：`self != otherFaction || self == Faction.UNKNOWN`）。
- ★ **没有选角色的玩家也算敌人**：未选角色的玩家阵营 = UNKNOWN ⇒ 对任何有阵营的角色来说都是"不同阵营"
  ⇒ **敌对**（来源：`ShadowHunterRolesPlugin.java:53-62` 取不到角色即 `Faction.UNKNOWN`；
  `core/RoleInfoImpl.java:84` 的注释原文就是"没有选角色的玩家也要算进来"）。

  3. **归零惩罚的标题文案**按自己的阵营分叉（见 §5.2 第 1 条）。

- **秒数只在技能名上**：技能的冷却名带 ` x.xs`（来源：`Skill.java:181-183`，格式串 `"%.1f"`），
  主武器的冷却名**不带**（来源：`MainWeapon.java:157-160`）。冷却期间技能物品**每刻**都会被重画，秒数才会逐刻递减
  （来源：`core/RoleInstance.java:916-929`）。
- **物品不能被随便弄走**（保护是"取消事件"式的）：
  - 背包里**点击**技能 / 主武器物品 ⇒ 取消（来源：`listener/SkillListener.java:149-163`、`listener/MainWeaponListener.java:143-157`）；
  - **Q 丢** ⇒ 取消，并**被复用为"Q 释放技能/攻击"**（来源：`listener/SkillListener.java:111-144`、`listener/MainWeaponListener.java:107-139`）；
  - **拖拽 / F 键换手 / 漏斗等容器搬运 / 放进合成格** ⇒ 新增的四类保护
    （来源：`listener/hook/HotbarItemProtectionListener.java:71-118`）。
    ⚠️ **未实测**：该文件自己的注释就申报了"不起服、不进档 ⇒ 上述四个事件在真实交互下是否真的被拦，
    以及取消是否影响既有 Q 丢链路，均无运行级读数"（来源：`listener/hook/HotbarItemProtectionListener.java:55-57`）。
    另：**合成格**那一项只做"把结果置空"，**不构成硬保护**（该事件本身不可取消，来源：`:100-118`）。
- **清角色 / 死亡 / 重生会清掉热键栏里的这些物品**（来源：`core/RoleInstance.java:684-693`（静态清除）、
  `listener/PlayerListener.java:21-34`）。

## 6. 常见问题（每条含**可自检步骤**）

### Q1 为什么我的技能没反应？

按下面顺序自检（每步都能自己看到结果）：

1. **看物品名**：
   - 名字灰色 + 后面有 ` x.xs` ⇒ **在冷却中**，说明区会有 `Skill is on cooldown.`（§5.5）。
     等它数到 0；或用 `/role debug cooldown status <槽位>` 看剩余刻数。
   - 名字红色 + ` DISABLED`、材质是**屏障** ⇒ **被禁用**（眩晕/沉默）⇒ 转 Q3。
   - 名字带 ` ENERGY LACK` ⇒ **能量不够** ⇒ 转第 3 步。
   - 名字绿色加粗 ⇒ 就绪，往下走。
2. **确认你确实有角色**：`/role energy get` —— 若回 `<你的名字> has no role!`，就是没角色；
   点击技能物品时聊天栏也会出现 `You have no role yet, but trying to cast a skill!`
   （来源：`listener/SkillListener.java:51-56`）。
3. **看能量**：`/role energy get` 与 §4.2/§4.3 表里的"耗能"比一下。
   能量不足时物品会显示 ` ENERGY LACK`（来源：`roleComponent/base/Skill.java:191-192`）。
   ⚠️ **`red` 的能量上限是 0** ⇒ 它永远没有能量；但 red 的四个主动件耗能声明值全是 0 ⇒ 不受影响（§4.1）。
4. **确认点击方式对**：技能侧接受 **右键 / 左键 / Q**；主武器侧也是这三种
   （来源：`listener/SkillListener.java:35-38,75-79`、`listener/MainWeaponListener.java:58,87`）。
5. **确认手上拿的是"插件认得的"物品**：把物品拿在**主手**（攻击与施法读的是主手，
   来源：`core/RoleInstance.java:474-476`、`listener/MainWeaponListener.java:33`）。
6. **看服务端日志**：`/role debug cooldown status <槽位>` 这一行会**同时**写进 `logs/latest.log`，
   前缀 `[command-debug]`（来源：`command/DebugCooldownCommand.java:122-125`）。

> 若 1–6 都正常还是没反应，多半是"物品的识别键被覆写掉了"—— 那是**改过代码**的人自负其责的形态
> （来源：`roleComponent/base/Skill.java:137-140` 的覆写者须知）。

### Q2 为什么 PvP / 范围技能打不到人（或者打到了不该打的人）？

- **范围技能只打"敌对"目标**：判定 = 阵营不同。**同阵营 ⇒ 不打**；
  **没选角色的玩家 ⇒ 算敌人 ⇒ 会被打**（来源：§5.3，判定实现在 `ShadowHunterRolesPlugin.java:64-68`、
  `core/RoleInfoImpl.java:71-90`）。
- **自检步骤**（用 `meiqihezi` 的圆弧斩当"探针"：它对 **7 格内**每个敌对目标造成 20 真实伤害，
  来源：`roleComponent/custom/meiqiHezi/skill/MeiqiheziCircleSlashSkill.java:110-117`）：
  1. 准备三名测试玩家：`/role set red A`、`/role set red B`、`/role set meiqihezi C`。
  2. **C** 站到 A、B 中间（7 格内），用圆弧斩（槽位 3）⇒ A、B 与 C **不同阵营** ⇒ **两人都会掉血**。
  3. 让 C 变成同阵营：`/role set red C` ⇒ 再放一次圆弧斩 ⇒ **A、B 都不掉血**（同阵营 ⇒ 非敌对），这是**正确**行为。
  4. 再让某个人 `/role clear`（变成无角色）站进 7 格内 ⇒ **他会掉血**（**正确**行为，见 §5.3 的 ★）。
  5. ⚠️ **未实测**：以上四步是**可自检的验证路径**，不是本手册已有的运行级读数 ——
     判定逻辑本身由代码给出（`ShadowHunterRolesPlugin.java:64-68`、`core/RoleInfoImpl.java:71-90`；见 §9）。
- **近身普攻**：拿着主武器打玩家时，原版伤害会被**取消**并改由武器组件结算自己的伤害
  （来源：`listener/MainWeaponListener.java:46-49`）⇒ 所以"原版那一刀"的伤害数字与平时不一样，属正常。

### Q3 为什么我的技能/主武器变成屏障（用不了）？

- 屏障 = **被禁用**状态（来源：`roleComponent/frameworkLevel/hotbar/IconState#of()`）。
- 原因：**眩晕（STUN）** ⇒ 技能与主武器**都**不可用；**沉默（SILENCE）** ⇒ **只有技能**不可用
  （来源：`manager/BuffManager.java:88-94`）。
- **自检步骤**：
  1. 看身上有没有**失明（blindness）/ 黑暗（darkness）**两个原版效果与移动速度骤降 —— 眩晕会同时给这两个效果并压低移动速度
     （来源：`manager/BuffManager.java:118-125`、`:54-58`）。
  2. 想一下最近是否 **SanTE 归零**（屏幕中央出现过 `⊠痛苦摸上脊背⊠` / `⊠恐惧正在注视着你⊠`）
     ⇒ 那是 5 秒眩晕（§5.2）。
  3. 等 5 秒后看物品是否自己变回正常材质（每次 buff 被移除都会重画热键栏，
     来源：`manager/BuffManager.java:109-112`）。

### Q4 为什么我 SanTE 归零之后又被眩晕又掉血？这不是 bug 吗？

不是。这是**归零惩罚**，三件事同时发生：5 秒眩晕 + 每 2 秒一次真伤共 3 次（每次约最大生命 10%）+ 期间 SanTE 被钉在 0，
**眩晕结束那一刻 SanTE 一次性回满**（来源与逐条行号见 §5.2）。
- **自检步骤**（SanTE 是**可以**直接读的 —— 它作为框架服务组件 id `sante` 登记在实例容器里，
  来源：`core/RoleInstance.java:87`（id 常量）、`:369-376`（登记））：
  1. `/role operation query @s sante current` ⇒ 回 `OK: <当前 SanTE>`；`/role operation query @s sante max` ⇒ 回上限。
     （语法依据：`roleComponent/frameworkLevel/SanTEComponent.java:43` 声明实现组件操作面、
     `:252` 的 `current`、`:253` 的 `max`、`:244-268` 整体实现；
     权限依据：等级 ≥ 3（§3.1）+ 权限节点 `shadowhunterroles.operation.sante`，对 op **默认放行**
     —— 来源：`command/ComponentOperationDispatcher.java:123-125` 的注释原文"对 op/控制台默认放行 ⇒ 不改变既有可用性"。
     ⚠️ **未实测**：本手册写作时没有跑过这条指令，上述结论来自代码。）
  2. 记下触发时刻，**5 秒后**再读一次 ⇒ 应已回满（回满安排在 STUN 结束那一跳，§5.2 第 5 条）。
  3. 观察掉血节奏：约 2 秒一次、共 3 次。
  4. 观察是否**只触发一次**（惩罚期间再归零不会刷新）⇒ 符合 §5.2 第 6 条。

### Q5 为什么我死了 / 掉线之后角色没了？

**设计如此**（来源：`listener/PlayerListener.java`）：
- **死亡** ⇒ 清角色 + 清热键栏物品（`:21-28`）；
- **重生** ⇒ 再清一次热键栏（`:30-34`）；
- **掉线** ⇒ 清角色（`:39-43`）；插件被禁用 / 重载 ⇒ 所有在线玩家角色被回收
  （来源：`ShadowHunterRolesPlugin.java:113-123`）。
- **自检步骤**：死后重连，敲 `/role energy get` ⇒ 应回 `You have no role yet!`；
  再让管理员 `/role set <角色id> <你的名字>` 即可恢复。

### Q6 为什么清角色后我原来穿的装备也没了？

这是**已知代价**，不是误删：穿戴装备的被动在 `stop()` 里**无条件清空头盔 / 胸甲 / 护腿 / 靴子四个槽**
（来源：`roleComponent/custom/meiqiHezi/passive/MeiqiheziEquipmentsPassive.java:77-87`、
`roleComponent/custom/red/RedEquipmentsPassive.java:77-87`；两处注释 `:80-82` 都写明了"不判断归属、
不加标记（已知代价：玩家原本穿在这 4 个槽位的其它装备会被一并删除）"）。
- **自检步骤**：清角色前先把想保留的装备放进**背包其它格子**（不是穿在身上）。
- ★ **这不是"违规写背包"，而是**有边界的例外**（口径详见 `组件模型.md` §2「背包写点两分」）：
  **判据「唯一物品写点 = 帧末 flush」管的是热键栏物品，不是玩家装备** ⇒ 两者**分开判**：
  ① **热键栏槽位**写点**必须唯一**（帧末 flush 经渲染器的那一次）；② **装备槽**（`helmet` / `chestplate` / `leggings` / `boots`）
  的写入**属穿戴装备被动的本职**（它 `start()` 就是穿、`stop()` 就是脱）⇒ **不作为违规**。
  上面那句"已知代价"依然成立、依然只针对**玩家自己原本穿在 4 个槽位的装备会被一并删除**。
  - **可复核命令**（照跑应得同数）：
  ```powershell
  $S = 'ShadowHunterRoles\src\main'
  # ① 热键栏写点：期望恰好 2 处（写入 1 + 清空 1）
  Get-ChildItem $S -Recurse -File -Filter *.java | ForEach-Object {
    $n = [IO.File]::ReadAllLines($_.FullName)
    for ($i = 0; $i -lt $n.Count; $i++) {
      if ($n[$i] -cmatch 'inv\.setItem\(') { "$($_.FullName.Substring((Get-Location).Path.Length+1)):$($i+1)" } } }
  # ② 装备槽写点：期望恰好 16 处（两件被动 × 4 槽 × 穿/脱两个方向）
  Get-ChildItem $S -Recurse -File -Filter *.java | ForEach-Object {
    $n = [IO.File]::ReadAllLines($_.FullName)
    for ($i = 0; $i -lt $n.Count; $i++) {
      if ($n[$i] -cmatch 'getInventory\(\)\.set(Helmet|Chestplate|Leggings|Boots)\(') { "$($_.FullName.Substring((Get-Location).Path.Length+1)):$($i+1)" } } }
  ```
  （★ 别用宽口径 `getInventory\(\).set*` —— 它还会捞到 `listener/hook/HotbarItemProtectionListener.java:114` 的 `event.getInventory().setResult(null)`，
  那是**事件背包**的结果格，既非玩家装备也非热键栏 ⇒ 宽口径得 **17**，用它判装备槽会多数 1 处。）

### Q7 为什么我敲 `/role` 说我"没有权限"？

- 门禁是**等级 ≥ 3**（默认），等级来自**服务端根目录的 `ops.json`**，不是权限节点（§3.1）。
- **自检步骤（管理员）**：
  1. 看服务端日志里那一行 `[command-access] …`：`level=<你的等级>, required=<要求等级>`
     （来源：`command/CommandAccess.java:117-118`）。
  2. 检查 `ops.json`（位置 = 世界目录的父目录，来源：`command/CommandAccess.java:94-96`）：
     每个条目必须有 `name` 和整数 `level`；**任一条件不满足 ⇒ 所有人一律被拒**并打 `SEVERE`
     （来源：`:189-215`、`:176-186`）。
  3. 想放宽：在插件数据目录的 `config.yml` 里改 `command-permission-level`（0–4），
     **最迟约 5 秒生效、不用重启**（来源：`config/ConfigurationManager.java:38-43`）。
  4. 想确认"是等级问题还是别的问题"：用**控制台**执行同一条指令 —— 控制台总是放行
     （来源：`command/CommandAccess#check()`）。

### Q8 为什么我拖不动 / 丢不掉技能物品？

**故意保护的**：点击与 Q 丢会被取消，拖拽 / F 键 / 容器搬运 / 合成格另有保护（来源见 §5.5）。
其中 **Q 丢会被当成"用技能"**（来源：`listener/SkillListener.java:133-143`）⇒ 你按 Q 时看到物品没掉出去、
而是技能触发了，是**正常**的。
- **自检步骤**：拿技能物品按 Q ⇒ 物品应留在原地并触发技能；在背包里拖拽它 ⇒ 应整次拖拽被取消。

### Q9 为什么技能名字上的秒数不跳 / 卡住不动？

- 秒数**只在冷却期间**显示，并且冷却期间物品**每刻重画**才会逐刻递减（来源：`core/RoleInstance.java:916-929`、
  `roleComponent/base/Skill.java:181-183`）。
- **自检步骤**：`/role debug cooldown status <槽位>` 看 `cooling=` 与 `remainingTicks=`：
  - `cooling=true` 而秒数不动 ⇒ 记录该现象 + 当时的 `remainingTicks` 前后两次读数；
  - `cooling=false` ⇒ 名字上**本来就不该有秒数**，属正常。
- ⚠️ **未实测**：本手册没有运行级的"秒数逐刻递减"读数，依据是代码（上列行号）。

### Q10 怎么知道有哪些角色 id 可以选？

- 看 §4 的三张表；或在游戏里敲 `/role set ` 后按 **Tab**（补全读注册表里的 id，
  来源：`command/SetRoleCommand.java:57-61`）。
- ⚠️ 注意 `/role help` **不列角色 id**，只列各子指令的用法（来源：`command/HelpCommand.java:33-41`）。
