## 3. 渲染器接管前的等价性要求（判定表）
| 维度 | 今日实现 | 渲染器接管后必须满足 |
|---|---|---|
| 技能四段顺序 | 冷却→禁用→能量不足→就绪 | 与骨架 `IconState` 顺序**一致**（`ENERGY_LACK` 必须在 `DISABLED` 之后、`READY` 之前） |
| 材质映射 | 冷却/能量不足 → `STRUCTURE_VOID`；禁用 → `BARRIER`；就绪 → `getIcon()` | 逐字一致 |
| 文案 | `" {%.1f}s"`（**含前导空格**）/ `" DISABLED"` / `" ENERGY LACK"` | 逐字一致（含空格与 `s`） |
| lore | `"Skill is on cooldown."` / `"Skill has been disabled."` / `"Skill is ready."` / `"===================="` + description；**能量不足不加 lore** | 逐字一致 |
| 颜色/装饰 | GRAY/RED/GREEN + `TextDecoration.BOLD` | 逐字一致 |
| PDC | `meta.getPersistentDataContainer().set(Utils.SKILL_KEY, STRING, getId())` | 保留（物品识别依赖它） |
| 主武器 | **无秒数后缀**、`isMainWeaponReady`/`canUseMainWeapon` 语义、冷却名不带秒 | 不得"顺手统一"成技能形态（**冻结差异**） |
| null 语义 | `instance == null` → 物品返回 `null` / 名返回 `"RoleInstance is Null!"` | 渲染器应无 null 分支（渲染器只对已注册物品生效）；差异须申报 |

## 4. 两段式执行建议（含前置与编译不过诱因）
| 段 | 批次 | 动作 | 前置 | 判据 |
|---|---|---|---|---|
| ① | **B⑧（已批准）** | 删两份组件覆写（`BloodySlash` / `CircleSlash`），基类补 `ENERGY LACK` | 无（基类先落地） | `roleComponent/**` 的 `createIconItem\|getDisplayName(RoleInstance)` **= 0** |
| ② | **T 块 ⑦** | 渲染器接管：`updateHotbar`/`updateSkillItemMeta` 改走 `HotbarRenderer`；**然后**删基类四条方法 | **必须先处理 §1 的三处调用点**（`:388/:395/:422`） | 全仓 `createIconItem\|getDisplayName(RoleInstance)` = **0**（含调用点口径 10 → 0），且渲染四段等价性表逐条通过 |

**顺序红线（做错即编译不过）**：
1. **先改调用点，后删方法**：`:388/:395/:422` 仍引用基类方法 ⇒ 先删方法必然 `找不到符号`；
2. **接管与删除必须同批**（渲染器真正产出物品后，基类方法才可删；否则物品渲染整体失效 ⇒ **玩家可见**的静默失效）；
3. **`HotbarRenderer` 骨架补齐是前置**（它现仅 10 处 `stateOf/markDirty` 命中）⇒ 接管前必须证明"四段状态可表达"（§3 判定表全绿）。
