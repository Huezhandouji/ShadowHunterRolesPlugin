# 架构总览（写给 AI 读）

> 只描述**当前代码形态**；**与代码不一致处以代码为准**。路径为**仓库相对**（POSIX）；所有读数都附**可复跑命令**。
> **本文件与 `组件模型.md` 的现算基线**：顶层 11 包 · `core/` 16 件 · `roleComponent/` 33 件 · `core/ports/` 4 件（端口接口 3 + 服务集记录 1）。

## 1. 一条链路：从角色模板到玩家身上

```
registry/RoleRegistry ← registry/RoleLoader 装配
        ↓
   core/Role（模板：组件条目 + 描述符 + 依赖 + 角色级展示信息）
        ↓  selectRole
   manager/RoleManager（Map<UUID, RoleInstance>）
        ↓
   core/RoleInstance（聚合根：组件容器 + 两阶段生命周期 + 受保护派发入口）
        ↓
   roleComponent/**（组件：skill / passive / mainWeapon / frameworkLevel 服务组件）
```

**做**：新增角色 → 只加 `registry/RoleLoader` 的一条定义 + 若干组件文件。
**不做**：不改框架去适配某个角色（扩展性审查要求"第三个实例测试"）。

## 2. 关键设施（AI 改代码前必须知道的三件）

| 设施 | 现算位置 | 为什么必须知道 |
|---|---|---|
| **受保护的派发入口** | `core/RoleInstance.java`（`guardedCall`） | 组件钩子抛异常时走**故障隔离**语义；**绕开它 = 破坏隔离** |
| **唯一物品写点** | 帧末 flush（`inv.setItem(` 现算 3 行 = 真写点 1 + 清栏位 2） | 组件**只能请求**重绘，不得直接写背包 |
| **两阶段生命周期** | 容器广播（`awake`/`start` … `stop`） | 组件的"取用入口"应在**自己的 `start()`** 里建立，避免"首次使用早于 `start()`" |

```powershell
git -C ShadowHunterRoles grep -n 'guardedCall' -- src/main/java
git -C ShadowHunterRoles grep -n 'inv.setItem(' -- src/main/java
```

## 3. 分层与依赖方向（做 / 不做）

- **做**：`registry → manager → core → roleComponent`；组件经 `svc()` 取平台能力。
- **不做**：`core` 依赖 `command`/`listener`；组件直接 import Bukkit 之外的可变全局；为"已是组件的关注点"新造接口或端口。

```powershell
git -C ShadowHunterRoles grep -n '^import com.shadowHunterRolesPlugin' -- src/main/java/com/shadowHunterRolesPlugin/core | Measure-Object
```

## 4. 目录职责（现算 11 个顶层包）

| 包 | 职责（一句话） |
|---|---|
| `api` / `internal/api` | 对外公开面（签名**只增不改**） |
| `registry` | 模板注册表 + 装配入口（`RoleLoader`） |
| `manager` | 玩家 ↔ 实例管理（`RoleManager`）、异常隔离通报 |
| `core` | 聚合根与端口面（`ports/` 4 件） |
| `roleComponent` | 组件基座（根 6）+ `base/` 3 + `builtin/` 4 + `custom/**` 11 + `frameworkLevel/` 8 |
| `listener` / `command` | 事件入口 / 命令入口 |
| `event` | 平台事件类型 |
| `platform` | 平台适配（调度等） |
| `config` | 配置读取与回落 |

```powershell
Get-ChildItem src/main/java/com/shadowHunterRolesPlugin -Directory | Select-Object -ExpandProperty Name
```
