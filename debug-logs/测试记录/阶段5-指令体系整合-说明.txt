§3 op 门控与 Tab 补全
--------------------------------------------------------------------------------
[3.1] **op 门控位置迁移的等价性（逐条论证，不是"看着像"）**：
      老：门控是 `handleDebugCooldown` 的**第一条语句**（:238-241），而 `handleDebugCooldown` 在 `case "debug"` 里
      **先于** `handleDebugSched` 被调用（:103 → :105）⇒ 非 op 玩家在**任何** `/role debug …`（含无话题、未知话题）下
      都只会拿到权限文案，**永远走不到** :106 的 `Wrong arguments…`。
      新：`DebugCommand` 在**任何话题解析之前**门控 ⇒ **同一可见行为**。
      两处门控文案同为 `You do not have permission to use this command.`（同一字符串，见 §5.2 去重）。
[3.2] **Tab 补全是本卡唯一的新增可见能力（已申报）**：老 `RoleCommand` 只实现 `CommandExecutor` ⇒
      `PluginCommand` 无 `TabCompleter` ⇒ 补全为空；新 `RoleCommand` 实现 `CommandExecutor, TabCompleter`。
      补全清单：一级 = 子指令名（`clear/debug/energy/help/set`）；`set` → 角色 id（`RoleRegistry.ids()`）；
      `energy` → `get|set`；`debug` → `cooldown|sched`（**非 op 一律不给**，与执行同一道门）；
      `cooldown` → `status|end|restart`；`sched` → `all`。其余位置不补全。
[3.3] **主类零改动的依据（离线核实证据）**：`javap -c -p` 反汇编 paper-api 的 `org.bukkit.command.PluginCommand#tabComplete`，
      在 `completer == null` 时会回退到 `executor instanceof TabCompleter` 分支
      （字节码 `:46` 取 `completer` 字段 → `:67` 判空 → `:76 instanceof TabCompleter` → `:86 checkcast` → `:93 invokeinterface onTabComplete`）
      ⇒ `setExecutor(new RoleCommand(...))` **足以**启用子指令补全，**无需** `setTabCompleter`、**无需**动主类。
      （工具可用性已断言：`Test-Path javap` = True、反汇编输出 289 行非空 —— 防"工具缺失 ⇒ 空输出假通过"那族陷阱。）

§4 探针关键输出行"逐字保留"的机械证据

[4.2] 结果：**老 26 条 vs 新 26 条 ⇒ 多重集完全相等（无一条增删改）** ✓
      —— 覆盖 `probe start`、①～④p 全部行、`[sched] ⑤ raw | …`、`[sched] ⑤ verdict | …`。
[4.3] 关键键名（在 `DebugSchedCommand.java` 内的现算命中数）：
      `matrixAllPairsMatch=` **2** · `portLegEquivalent=` **1** · `CONCLUSION=` **1** · `portFirstSecond=` **3** ·
      `[sched] ⑤ verdict` **1** · `[sched] ⑤ raw` **1** ⇒ 既有证据（t51/t55/t56 等）仍可按原键名引用 ✓
[4.4] 搬迁范围 = 方法体**整体**（:342-679，含观测数组、8 组归一化矩阵 `mPairs`、`portLeg` 候选组件列表、
      自取消计数与 50L/60L 延迟结论点）；仅两处适配子指令口径：`args[1]=="sched"` 判定 → 路由已剥离
      （`args.length>=1 && !"all".equals(args[0])`）、`player` 来自 `execute` 的 `instanceof`（同 `Player`）。
      **op 门控**移出到 `DebugCommand`（§3.1），其余判定、字符串、延迟、取消语义**一字未动**。
[4.5] 关键行与"既有证据仍可引用"的边界：**键名与行文本不变** ⇒ 旧证据里的引文比对仍成立；
      但**行号必然变化**（文件与类都换了）⇒ 引用时按"类 + 键名"引用，不要按行号引用（见 §9.3）。
