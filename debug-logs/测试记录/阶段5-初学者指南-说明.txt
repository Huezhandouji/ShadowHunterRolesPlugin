**仪器侧证（两条，都是本卡实测）**：

1. **卡面 verify(3) 的字面命令对新件是结构性盲区**。新件在本卡内**未被 git 跟踪**（`git status` 显示 `??`），
   而 `git grep` 默认只搜已跟踪文件 ⇒ 字面命令恒返 0，**不能**作为"0 命中"的证据。实测：
   ```
   git -C ShadowHunterRoles grep -nE "<合并模式>" -- "docs/插件文档/初学者指南.md"
   exit=1 lines=0        ← 字面命令（对未跟踪文件无判别力）
   ```
   修正命令（本卡采用）：
   ```
   git -C ShadowHunterRoles grep --untracked --no-exclude-standard -n -E -f <模式文件> -- "docs/插件文档/初学者指南.md"
   exit=1 lines=0        ← 真实 0 命中
   ```
2. **修正命令的正对照**（证明它不是假绿）：在同一条命令下换一个确实含痕迹的未跟踪文件（旧侧命中留档），
   仍能报出命中：
   ```
   git -C ShadowHunterRoles grep --untracked --no-exclude-standard -n -E -f .scratch/t8/p-verify.txt -- ".scratch/t8/old-verify.out"
   exit=0 lines=208
   ```
3. **第三条尺子（独立仪器）**：按卡面 verify(4) 的样式把旧版文档从提交里取出落盘
   （`git show 0c6930d:docs/插件文档/架构与组件模型.md > $env:TEMP\old-arch.md`，53075 B / 367 行），
   再用**不依赖 git** 的仪器（`[System.IO.File]::ReadAllLines(…, UTF8)` + 逐行 `-match` 同一份模式文件）统计：
   **58 行命中 / 共 367 行** —— 与 `git grep` 在同一个 blob 上得到的 58 行一致（两种仪器同值）。
   同一仪器对新件统计 = 0 行。
