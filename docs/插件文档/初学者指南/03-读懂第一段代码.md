# 03 · 读懂第一段代码

## 先补两个词：tick 与事件

### tick

**打比方**：把服务端想成一台不停转的唱机 —— **每 1/20 秒转一圈**。每转一圈，插件就把它该做的事做一遍。这一圈就叫一个 **tick**（可以理解成"一帧时间"）。

代码里对应的两件事：

- **谁在转圈**：`src/main/java/com/shadowHunterRolesPlugin/core/RoleInstance.java` 注册了一个"每 1 tick 执行一次"的任务：

```java
updateTask = platform.scheduler().runRepeating(this::triggerUpdate, 1L, 1L);
```

`this::triggerUpdate` 的意思是"把 `triggerUpdate` 这个函数本身交出去"（就像你把**函数名**当参数递给一个闹钟），后面两个 `1L` 是"第一次等 1 tick、之后每 1 tick 一次"。

- **每转一圈被调用的方法**：叫 `update()`，写在 `roleComponent/RoleComponent.java`：

```java
public void update() {
}
```

模板里它是空的（什么都不做）；某个组件需要"每 tick 干活"就重写它。真实例子：`src/main/java/com/shadowHunterRolesPlugin/roleComponent/AutoRecoverEnergyPassive.java` 的 `update()` —— 它每 tick 检查周围有没有敌人、默默数秒，攒够时间就给自己加 3 点能量。

### 事件

**打比方**：**事件就是门铃**。插件不会一直盯着"玩家有没有按右键"，而是在门铃上登记一条："门铃响了，就执行这个函数。"玩家按下右键，门铃响一次，你写的那段代码才被调用一次。

代码里对应的两个例子：

- `src/main/java/com/shadowHunterRolesPlugin/listener/SkillListener.java`：

```java
@EventHandler
public void onPlayerRightClickSkillItem(PlayerInteractEvent event){
```

（`@EventHandler` 是一个**标记**，意思是"把下面这个函数登记到门铃上"。参数 `event` 是这次事件的详细信息：谁按的、手里拿的什么。）

- `src/main/java/com/shadowHunterRolesPlugin/listener/PlayerListener.java` 的 `onPlayerQuit(PlayerQuitEvent event)` —— 玩家退出时被调用，这个插件在它里面清掉该玩家的角色。

## 逐行读一个最短的技能

打开 `src/main/java/com/shadowHunterRolesPlugin/roleComponent/meiqiHeZi/skill/MeiqiheziUnconcernSkill.java`。这是仓库里最短的完整技能之一：游戏里叫「漫不经心」，效果是给自己加速 2 秒。

> **节选说明**：下面按三段引用这个文件。原文件在类声明上方还有一段说明文字（本页不引用它），**其余代码与源文件逐字相同**，可以逐行对照。每段的末尾都写了它在原文件里的位置。

### 第一段：文件开头与类声明

```java
package com.shadowHunterRolesPlugin.roleComponent.meiqiHeZi.skill;

public class MeiqiheziUnconcernSkill extends Skill {
```

- 第一行的 `package ...` 是"这个文件住在哪个文件夹"，内容与路径一致；
- 第二行读作"`MeiqiheziUnconcernSkill` 是一种 `Skill`（技能）" —— 它因此自动拥有技能该有的东西：id、显示名、描述、冷却、能量消耗、图标，以及 `getId()`、`getCooldownTicks()` 这些方法。

### 第二段：构造函数（造对象时自动执行）

```java
    public MeiqiheziUnconcernSkill(String id, ComponentServices services){
        super(
                id,
                services,
                Component.text("漫不经心"),
                Component.text("获得2秒速度5"),
                100,
                0,
                Material.BLAZE_POWDER
        );
    }
```

逐行读：

- 这个函数的名字和类名一模一样 —— 这种函数叫**构造函数**：造对象时自动执行一次，用来把对象初始化好；
- `super(...)` 的意思是"把这些信息交给我继承的那套模板（`Skill`）去存好"；
- `id` 与 `services` 是框架传进来的两个参数：`id` 是这个组件在清单上的名字；`services` 是一个**工具箱**（下面会讲）；
- `Component.text("漫不经心")` 是显示名，`Component.text("获得2秒速度5")` 是描述 —— 玩家在图标上看到的字就是这两个（`Component.text(...)` 的意思就是"造一段游戏里显示的文字"）；
- `100` 是**冷却**，单位是 tick：100 ÷ 20 = **5 秒**；
- `0` 是**能量消耗**，这个技能不耗能量；
- `Material.BLAZE_POWDER` 是图标用的物品（烈焰粉）。

想看模板是怎么接收这些参数的，可以看 `src/main/java/com/shadowHunterRolesPlugin/core/Skill.java` 的构造函数 `public Skill(String id, ComponentServices services, Component displayName, Component description, int cooldown, int energyCost, Material icon)`。**你以后写自己的技能时，要照着这个顺序传参。**

### 第三段：施放函数（玩家按下技能时发生什么）

```java
    @Override
    public CastResult onCast(CastSignal signal){
        Player caster = svc().self().player();
        if(!svc().buffs().canCastSkill()) return CastResult.NO_COOLDOWN;

        svc().buffs().applyPotionEffect(PotionEffectType.SPEED, 40, 4);

        caster.getWorld().playSound(
                caster.getLocation(),
                Sound.ITEM_TRIDENT_RIPTIDE_1,
                1f,
                1f
        );

        caster.getWorld().spawnParticle(Particle.EXPLOSION, caster.getLocation(), 1);

        svc().cooldowns().start(getCooldownTicks());
        return CastResult.SUCCEED;
    }
```

逐行读：

- `@Override` 是一个**标记**，意思是"我在这里重写父类里同名的那个函数"。名字或参数写错时，构建会直接报错 —— 相当于给你的实现盖了个章；
- `onCast(...)` 是技能被触发时框架**会来调用**的函数（名字固定，不要改）；
- `CastResult` 是"这次施放的结果"，只能取几个固定值（下面用到两个）；
- `Player caster = svc().self().player();` —— 这一行要单独讲，见下面「为什么要每次现取玩家」；
- `svc()` 是"向框架要工具箱"（`services` 那个工具箱的取用口）；`svc().buffs()` 是工具箱里管**状态效果**的那一格；
- `canCastSkill()` 问的是"现在允许放技能吗"（被沉默或被眩晕时不允许）。不允许就 `return CastResult.NO_COOLDOWN;` —— 返回"什么都没做，也别进冷却"；
- `applyPotionEffect(PotionEffectType.SPEED, 40, 4)` 给自己施加**速度**效果：40 tick = 2 秒（第 3 个参数 `4` 是增幅档位，游戏里显示为 5 级：这个插件里"增幅 0"对应游戏里的 I 级）；
- `playSound(...)` 与 `spawnParticle(...)` 是音效与粒子，给玩家的即时反馈；
- `svc().cooldowns().start(getCooldownTicks())` 是**开始冷却**：`getCooldownTicks()` 是继承来的方法，读出来的正是构造函数里写的那个 `100` —— 这就是"字段"的意义：写一次，之后谁都读得到；
- `return CastResult.SUCCEED;` 表示"这次施放成功了"（框架据此让图标进入冷却状态）。

一句话总结这个文件的形状：**声明自己的名字与数值（构造函数），然后写"被按下时做什么"（`onCast`）**。仓库里其它技能都是这个形状，只是中间那段更长。`04` 要你写的自己的角色，用的就是这个形状。

### 为什么要"每次现取玩家"

```java
Player caster = svc().self().player();
```

这行做的是：每次施放，都当场问一句"我这个组件现在挂在哪个玩家身上"，把答案放进一个**局部变量** `caster`，只在本次函数里用。

**不要把玩家对象存进字段。** 因为：

- 玩家会掉线。这个插件在玩家退出时就把角色清掉了（`listener/PlayerListener.java` 的 `onPlayerQuit`）；
- 字段会一直留着，于是里面握着的可能是"已经不在这一局里的玩家"；
- 之后你用它做任何事（加血、放音效），都可能是在对着一个不存在的人操作。

所以规矩是：**用的时候现取；真要长期记住一个人，就记住不会变的编号**（玩家在服务端里的唯一编号叫 `UUID`）。真实的对照例子：`src/main/java/com/shadowHunterRolesPlugin/roleComponent/red/RedBleedPassive.java` 里用 `Map<UUID, Integer> playerBleedRecord` 记"谁身上有几层流血" —— 键是编号，不是玩家对象。

同样的写法在别处也能看到：`roleComponent/meiqiHeZi/passive/MeiqiheziEquipmentsPassive.java` 的 `start()` 与 `stop()` 都是第一行就 `Player player = svc().self().player();`。

## 动手改第一个数值

目标：把「漫不经心」的冷却从 5 秒改成 10 秒，然后在游戏里亲眼看见图标倒数变长。

**开工前先做一件事**：把要改的文件复制一份放在别处（例如把这个文件复制到桌面，命名成 `MeiqiheziUnconcernSkill.java.bak`）。下一步要讲"改坏了怎么退回"，有副本就有底气。

### 第 1 步：改代码

打开 `src/main/java/com/shadowHunterRolesPlugin/roleComponent/meiqiHeZi/skill/MeiqiheziUnconcernSkill.java`，在构造函数里找到那个 `100`（第 5 个参数），改成 `200`：

```java
                200,
                0,
                Material.BLAZE_POWDER
```

`200` tick ÷ 20 = **10 秒**。

> 改数值时记住单位是 tick：**1 秒 = 20 tick**。

### 第 2 步：构建

```powershell
cd ShadowHunterRoles
$env:GRADLE_USER_HOME = "$PWD\.gradle-work"
.\gradlew build -x copyPluginJar --console=plain
```

- 第一行进入仓库文件夹；第二行把构建工具的缓存放在仓库内（不写也行）；
- 第三行开始**构建** —— 把源码翻译并打包成一个服务端能读的文件（叫 `jar`）。看到 `BUILD SUCCESSFUL` 就算成功，成品是 `build/libs/ShadowHunterRolesPlugin-1.0.0.jar`；
- `-x copyPluginJar` 表示跳过"自动把 jar 拷到服务端文件夹"这一步。如果你在 `gradle.properties` 里配置过 `pluginCopyPath` 指向服务端的 `plugins` 文件夹，去掉这个参数就会顺手帮你拷贝。

### 第 3 步：起本地服务端

```powershell
.\gradlew runServer
```

- 它会拉起一个 Minecraft 1.21.11 的调试服务端，服务端文件夹是仓库里的 `run/`；
- **连进来的号码是 25566**：这个号码写在 `run/server.properties` 里，字段名是 `server-port`，客户端填 `localhost:25566` 就能进；
- 控制台出现 `ShadowHunter Character System enabled.` 表示插件已经加载；
- 这一步会一直占着这个窗口（服务端在跑）。结束时在服务端控制台输入 `stop` 回车。

### 第 4 步：进游戏验证

1. 进服后输入 `/role set meiqihezi`；
2. 按 `1` 选中快捷栏第 1 格（「漫不经心」），**右键**放一次；
3. 看那一格图标：它变灰，名字后面开始显示剩余秒数；
4. 对比：改之前是从大约 5 秒开始倒数，改之后从大约 10 秒开始 —— 这说明你改的数值生效了；
5. 等倒数走完，图标恢复原样，可以再放一次。

### 第 5 步：改回原值（或退回）

**方法一（最省事）**：把 `200` 改回 `100`，再跑一次第 2 步的构建。

**方法二（通用退路，改坏了都能用）**：用开工前复制的副本盖回去 —— 把桌面上那份 `MeiqiheziUnconcernSkill.java.bak` 复制回来、覆盖原文件，再去掉 `.bak` 后缀。构建一次即可。

**方法三（如果你用 git 管理这份代码）**：让版本库把文件还原成上次提交时的样子：

```powershell
git checkout -- src/main/java/com/shadowHunterRolesPlugin/roleComponent/meiqiHeZi/skill/MeiqiheziUnconcernSkill.java
```

（这条命令会**丢掉你自己在这个文件里的改动**，所以只在确实想还原时用。）

三种方法做完都要**重新构建**，并且**重启服务端**，改动才会生效。

## 常见问题

**问：我改了代码，游戏里却一点变化都没有，为什么？**

最常见是三个原因：① 忘了重新构建（第 2 步）；② 构建了但服务端还在跑旧的，需要重启；③ 你以为 jar 会自动拷到服务端，其实只有配置过 `pluginCopyPath` 才会（`build.gradle.kts` 的 `copyPluginJar`）。

**问：为什么技能图标是灰的，名字后面还跟着一串秒数？**

它在冷却中。冷却中的图标会被换成灰色虚空方块，名字后面追加剩余秒数（形如 ` x.xs`）；这一整套图标外观由 `src/main/java/com/shadowHunterRolesPlugin/core/hotbar/HotbarRenderer.java` 的 `applySkill` 生成。

**问：为什么图标变成了红色、名字后面写着 DISABLED？**

你被**沉默**或**眩晕**了。是否允许放技能由 `manager/BuffManager.java` 的 `canCastSkill()` 判断（两者任一都不许），渲染器据此给出红色 ` DISABLED` 外观。

**问：图标上写着 ENERGY LACK 是什么意思？**

能量不够放这个技能。判定在 `core/hotbar/HotbarRenderer.java` 的 `stateOf(...)`。顺带一提：**主武器永远不会**出现这个状态 —— 它的能量消耗恒为 0（见 `core/MainWeapon.java` 的构造函数）。

**问：我按了技能，却什么也没发生？**

一般是这四种：① 被沉默 / 眩晕；② 冷却还没走完；③ 能量不够；④ **这个技能只认某一种按键**。第 ④ 种很容易被忽略，例如 `roleComponent/red/RedDeeplySorrowSkill.java` 的 `onCast(...)` 开头就要求触发来源必须是右键，用左键或 `Q` 不会生效。

**问：为什么我掉线再上来，角色没了？**

这个插件的设计就是"掉线即清除角色"。玩家退出时 `listener/PlayerListener.java` 的 `onPlayerQuit(...)` 会调用 `RoleManager.clearRole(...)`，角色连同它的技能、被动一起被回收；重新进服要再 `/role set` 一次。

**问：为什么技能物品丢不掉？**

丢不掉是故意的：`listener/SkillListener.java` 的 `onPlayerQDropSkillItem(...)` 会把"丢弃"取消掉，并把这次按键当成一次施放。主武器同理（`listener/MainWeaponListener.java` 的 `onQDrop`）。

准备好了就去 `04-如何创建一个自己的角色.md`，把那套形状用在自己的角色上。
