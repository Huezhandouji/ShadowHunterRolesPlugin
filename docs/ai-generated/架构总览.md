# 架构总览（写给 AI 读）

> 只描述**当前代码形态**；**与代码不一致处以代码为准**。路径为**仓库相对**（POSIX）；所有读数都附**可复跑命令**。
> **本文件与 `组件模型.md` 的现算基线**（口径 = 顶层目录**含直属 `.java`** 才算「包」）：顶层 **9 包**（顶层目录共 **10** 个，其中 `internal/` 无直属 `.java`、只有 `internal/api/` 子包）· `core/` **13 件** · `roleComponent/` **38 件**（根 8 + `base/` 3 + `builtin/` 4 + `custom/**` 11 + `frameworkLevel/` 12）· `core/ports/` **4 件**（端口接口 3 + 服务集记录 1）· `src/main` **89 件**。取数命令见 §2 与 §4。

## 1. 一条链路：从角色模板到玩家身上

```
registry/RoleRegistry ← registry/RoleLoader 装配
        ↓
   core/Role（模板：组件条目 + 描述符 + 依赖 + 角色级展示信息）
        ↓  selectRole
   manager/RoleManager（Map<UUID, RoleInstance>）
        ↓
   core/RoleInstance（每实例容器：组件表 + 两阶段生命周期 + 受保护派发入口）
        ↓
   roleComponent/**（组件：skill / passive / mainWeapon / frameworkLevel 服务组件）
```

**做**：新增角色 → 只加 `registry/RoleLoader` 的一条定义 + 若干组件文件。
**不做**：不改框架去适配某个角色（扩展性审查要求"第三个实例测试"）。

## 2. 关键设施（AI 改代码前必须知道的三件）

| 设施 | 现算位置 | 为什么必须知道 |
|---|---|---|
| **受保护的派发入口** | `core/RoleInstance.java`（`guardedCall`） | 组件钩子抛异常时走**故障隔离**语义；**绕开它 = 破坏隔离** |
| **唯一物品写点** | 帧末 flush（`inv.setItem(` 现算 **2 行** = 真写点 1 + 清栏位 1）：真写点 `roleComponent/frameworkLevel/hotbar/HotbarRenderer.java:136` · 清栏位 `roleComponent/HotbarItems.java:40` | 组件**只能请求**重绘，不得直接写背包 |
| **两阶段生命周期** | 容器广播（`awake`/`start` … `stop`） | 组件的"取用入口"应在**自己的 `start()`** 里建立，避免"首次使用早于 `start()`" |

```powershell
git -C ShadowHunterRoles grep -n 'guardedCall' -- src/main/java
git -C ShadowHunterRoles grep -n 'inv.setItem(' -- src/main/java   # 期望 2 行：HotbarRenderer.java:136（写入）+ HotbarItems.java:40（清空）
```

★ **写点现算 2 行不是 3 行**：本表的旧读数写 **3 行 = 真写点 1 + 清栏位 2**，与现树不符（上面的命令一跑即得 **2 行**）。成因 = **旧读数是更早的树上的口径**：热键栏渲染器接管那一步把旧写路整体删除（该步的提交说明即"the legacy write path removed"），此后全库只剩这两处；两处**都不产生新写路**（写入 = 唯一的物品渲染写路径；清空 = **只清本系统写进去的**、走识别键判定，不是第二条写路径）。
```powershell
#把两处逐行打印出来（含"哪一处是写入、哪一处是清空"），不必只信行数
$repo = (Resolve-Path 'ShadowHunterRoles').Path
Get-ChildItem "$repo\src\main" -Recurse -File -Filter *.java | ForEach-Object {
  $n = [IO.File]::ReadAllLines($_.FullName)
  for ($i = 0; $i -lt $n.Count; $i++) {
    if ($n[$i] -cmatch 'inv\.setItem\(') { "$($_.FullName.Substring($repo.Length+1)):$($i+1)  $($n[$i].Trim())" } } }
#期望恰 2 行：…/roleComponent/frameworkLevel/hotbar/HotbarRenderer.java:136  inv.setItem(written.getKey(), written.getValue());
#           …/roleComponent/HotbarItems.java:40                            inv.setItem(i, null);
#把 'inv\.setItem\(' 换成 'setItem\(' 是同数（无隐藏的第二写路）
```

## 3. 分层与依赖方向（做 / 不做）

- **做**：`registry → manager → core → roleComponent`；组件经 `svc()` 取平台能力。
- **不做**：`core` 依赖 `command`/`listener`；组件直接 import Bukkit 之外的可变全局；为"已是组件的关注点"新造接口或端口。

```powershell
git -C ShadowHunterRoles grep -n '^import com.shadowHunterRolesPlugin' -- src/main/java/com/shadowHunterRolesPlugin/core | Measure-Object
```

## 4. 目录职责（现算 9 个顶层包）

| 包 | 职责（一句话） |
|---|---|
| `api` / `internal/api` | 对外公开面（签名**只增不改**） |
| `registry` | 模板注册表 + 装配入口（`RoleLoader`） |
| `manager` | 玩家 ↔ 实例管理（`RoleManager`）、异常隔离通报 |
| `core` | **聚合根 `Role`**（阵营真值所在）+ 端口面（`ports/` 4 件）|
| `roleComponent` | 组件基座（根 8）+ `base/` 3 + `builtin/` 4 + `custom/**` 11 + `frameworkLevel/` 12（直属 9 + `hotbar/` 3）= 38 |
| `listener` / `command` | 事件入口 / 命令入口 |
| `platform` | 平台适配（调度等） |
| `config` | 配置读取与回落 |

```powershell
$S = (Resolve-Path 'ShadowHunterRoles/src/main/java/com/shadowHunterRolesPlugin').Path
Get-ChildItem $S -Directory | Select-Object -ExpandProperty Name                        # 期望 10 个目录名
(Get-ChildItem $S -Directory | Where-Object { (Get-ChildItem $_.FullName -File -Filter *.java).Count -gt 0 }).Name   # 期望 9 个包名（internal 不在内）
Get-ChildItem "$S\roleComponent" -Directory | Select-Object -ExpandProperty Name        # 期望：base builtin custom frameworkLevel
```
