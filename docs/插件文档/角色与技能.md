## 2. 角色的装配与生效时序（玩家视角："/role set" 之后发生了什么）

`manager/RoleManager.java:27-41`（`selectRole`）→ `core/Role.java:67-69`（`createInstance`）→ `core/RoleInstance.java:98-137`（构造器）：

1. 复制模板的阵营、把 `currentEnergy`/`currentSanTE` 初始化为**满值**（`RoleInstance.java:102-104`）；
2. 创建全部组件实例（技能 → 被动 → 主武器，`RoleInstance.java:221-245`）；
3. 冻结组件注册表（`:111`，之后 `getComponent` 才合法，见架构文档）；
4. 建 `BuffManager`（`:113`）、写生命属性修饰符并把血量设满（`:115-124`）；
5. **广播 `awake` → `start`**（`:127-128`；分派实现 `:651-696`：awake/start 顺序为 技能 → 被动 → 主武器，stop 为**逆序**）；
6. 起 **1 tick 周期**的 `update` ticker（`:130-134`）；
7. 渲染一次热键栏（`:136`）。

清除（`RoleInstance.clear()`，`RoleInstance.java:840-869`）：`stop` 逆序 → 框架兜底取消组件登记的全部任务（`:846`）→ 取消 ticker（`:848-851`）→ 清热键栏（`:853`）→ 移除生命修饰符（`:855`）→ **只回收本系统记账过的药水效果**（`:857-861`）→ 清 buff（`:863`）→ 清两张冷却表与上下文（`:866-868`）。

**触发清除的入口**：`/role clear`、死亡（`listener/PlayerListener.java:21-28`）、**掉线（`:39-43`）**、换角色（`RoleManager.java:34`）、插件卸载（`ShadowHunterRolesPlugin.java:92-101` → `RoleManager.clearAllPlayersRole()` `RoleManager.java:100-105`）。

**行为**：

## 5. 两角色共用组件

### 5.1 自动恢复能量 `autoRecoverEnergy_passive`（仅 `meiqihezi` 挂）

- 显示名/描述：`自动恢复能量` / `周围10格没有敌人时，每秒恢复3点能量`（`roleComponent/AutoRecoverEnergyPassive.java:15`）。
- 实现（`:19-36`）：每 tick 用 `SkillUtil.hasEnemyInRange(instance, player.getLocation(), 10)` 判"半径 10 内是否有敌人"；有敌人则把计时器清零，无敌人则累加，**累计到 200 ticks（=10 秒）**后开始按 `20 ticks` 一次 `increaseEnergy(3)`。

### 5.2 自动恢复 SanTE `autoRecoverSanTEPassive`（两角色都挂）

- 显示名/描述：`自动恢复SanTE` / `当周围10格没有敌人五秒后, 开始自动恢复SanTE, 每秒3`（`roleComponent/AutoRecoverSanTEHealthPassive.java:15`）。

- ⚠️ 代码的等待门槛是 `noEnemySurroundTime >= 200`（10 秒），与描述里的"五秒"不一致，见 §6。

### 5.3 SanTE 归零惩罚 `default_san_te_zero_punishment`（两角色都挂）

- 构造器把显示名与描述都传 `null`（`roleComponent/DefaultSanTEZeroPunishment.java:19-25`），即该被动**没有玩家可见名称**（它也不在热键栏里）。
- 触发：`onSanTEChange(player, instance, pre, new)` 中 `newSanTE <= 0`（`:31-32`）；**先取消仍在跑的旧任务**再起新任务（`:37`，O-6 重入保护）。
- 任务：`runRepeating(task, 0L, 40L)`，**共 3 次**（`count >= 3` 取消，`:56-59`）：
  - 第 1 次（`:64-102`）：置"惩罚中"状态、`addBuff(BuffType.STUN, 100)`（= 眩晕 5 秒）、`Sound.ITEM_TOTEM_USE`、`TOTEM_OF_UNDYING` + `SCULK_SOUL` 粒子，并按阵营显示标题：
    - `Faction.HUNTER` → `⊠恐惧正在注视着你⊠`（`NamedTextColor.LIGHT_PURPLE`，显示 5000 ms）
    - `Faction.SHADOW` → `⊠痛苦摸上脊背⊠`（`NamedTextColor.YELLOW`，5000 ms）
    - 其它阵营 → 空标题（`Component.empty()`）
  - 第 2、3 次（`:104-108`）：`Sound.ENTITY_WITHER_HURT` + `SCULK_SOUL` 粒子
  - 每次都结算 `DamageUtil.dealtTrueDamage(player, null, 最大生命 × 0.3 × 0.33333)`（`:109`）≈ 最大生命的 10%；**施动者为 `null`**
  - 第 3 次结束（`:111-115`）：复位惩罚状态并把 SanTE **回满**（`setCurrentSanTE(getMaxSanTE())`）
- `stop()` 取消任务（`:133-136`）。

## 6. 通用机制（数值真值所在）

### 6.1 能量 Energy
| 项 | 事实 | 出处 |
|---|---|---|
| 初始值 | `= role.getMaxEnergy()`（满值） | `core/RoleInstance.java:103` |
| 上限 | `role.getMaxEnergy()` | `:553-555` |
| 写入 | `setCurrentEnergy(int)`：`Math.clamp(amount, 0, maxEnergy)` → 刷新热键栏 → 发 `EnergyChangeEvent` | `:560-568` |
| 增减 | `decreaseEnergy` / `increaseEnergy` 都只是 `setCurrentEnergy` 的包装 | `:570-576` |
| 端口形态（新侧） | `EnergyPort.current()/tryConsume(n)/gain(n)`；`tryConsume` = 判断+扣减合一，`amount <= 0` 视为成功 | `core/ports/EnergyPort.java:4-11`、`core/EnergyPortImpl.java:20-29` |

### 6.2 理智 SanTE
| 项 | 事实 | 出处 |
|---|---|---|
| 初始值 | `= role.getMaxSanTE()`（满值） | `RoleInstance.java:104` |
| 上限 | `role.getMaxSanTE()` | `:597` |
| 写入 | `setCurrentSanTE(int)`：`Math.clamp(amount, 0, maxSanTE)` → 发 `SanTEChangeEvent` | `:581-587` |
| 变化回调 | 事件 → `listener/RoleEventListener.java:17-21` → `RoleInstance.triggerSanTEChange`（`:745-766`）→ 逐组件 `SanTEChangeAware.onSanTEChange(player, instance, pre, now)` | — |
| 归零后果 | 见 §5.3（3 次惩罚伤害 + 眩晕 5 秒 + 回满） | `DefaultSanTEZeroPunishment.java:31-118` |

### 6.3 生命 Health
- 装配时：给 `Attribute.MAX_HEALTH` 挂一个**加法修饰符** `role.getMaxHP() - 20`（key = `role_health_modifier`，由 `platform/KeyFactory` 生成），随后 `setHealth(getMaxHealth())` 满血（`RoleInstance.java:115-124`）。
- `heal(double)`：`min(当前 + amount, Attribute.MAX_HEALTH)`（`:541-544`）；`setCurrentHealth(double)` 做 `0..MAX_HEALTH` 夹取（`:532-535`）。
- `clear()` 移除该修饰符（`:855`），因此**清角色后最大生命回到服务端原值**。

### 6.4 阵营 Faction 与敌对判定
- 枚举：`SHADOW` / `HUNTER` / `UNKNOWN`（`core/Faction.java:3-7`）。
- 角色实例的阵营默认来自模板（`RoleInstance.java:102`），可被 `setFaction` 覆盖、`resetFaction` 复位（`:621-627`）。
- 敌对判定（`:644-647`）：`thisFaction != otherFaction || thisFaction == UNKNOWN` ⇒ **不同阵营互为敌人；UNKNOWN 对任何人都是敌人**。
- 按玩家对象判定走平台查询（`:640-642` → `ShadowHunterRolesPlugin.java:41-54` 的匿名 `FactionLookup`）：**没有选角色的玩家 → `UNKNOWN` → 敌对**。
- `RoleManager.areHostile(p1, p2)`：任一方没有角色 → `true`（`manager/RoleManager.java:79-95`）。
- 组件用的"周围有没有敌人"判定：`SkillUtil.hasEnemyInRange`（`roleComponent/SkillUtil.java:17-30`），语义同上（未选角色也算敌人）。

### 6.5 Buff / 控制效果
- 类型：`SILENCE`（沉默）、`STUN`（眩晕）、`IMMUNE`（免疫）（`core/BuffType.java:3-7`）。
- 闸门：`canCastSkill() = 非 STUN 且非 SILENCE`；`canUseMainWeapon() = 非 STUN`（`manager/BuffManager.java:86-92`）⇒ **沉默只挡技能，不挡主武器**。
- 加 `STUN` 时：给 `Attribute.MOVEMENT_SPEED` 挂 `-1`（`MULTIPLY_SCALAR_1`）修饰符 + 施加 `BLINDNESS`/`DARKNESS`（时长 = 传入时长，amplifier 1）（`:52-57`、`:113-124`）；移除时逐项回收（`:126-133`）。
- `IMMUNE`：加免疫时**先移除** `SILENCE` 与 `STUN`（`:65-79`）；免疫期间其它 buff 一律不加（`:42`）。
- 计时：`BuffManager` 自己起一个 **1 tick** 的 updater 任务逐 tick 递减并在到期时移除（`:135-158`）；`clearAll()` 会取消该任务（`:160-170`）。

### 6.6 冷却
- 两张表：`skillCooldowns`、`mainWeaponCooldowns`，值都是**结束刻** `Bukkit.getCurrentTick() + ticks`（`RoleInstance.java:56-57`、`:279-287`、`:378-384`）。
- 就绪/剩余：`isSkillReady(id)` = `当前刻 >= 结束刻`（`:274-277`）；`getRemaining*Ticks` 用 `max(0, 结束刻 - 当前刻)`（`:289-293`、`:386-389`）；`getRemaining*Seconds` = ticks / 20f（`:295-297`、`:391-393`）。
- 启动冷却时会**立即刷新热键栏**并在剩余时长后再刷新一次（`:283-285`、`:381-383`）。
- 组件侧的新形态是 `CooldownPort.isReady()/remainingTicks()/start(ticks)/end()`，且**构造期已绑定本组件 id 与 kind**（`core/ports/CooldownPort.java:8-17`、`core/CooldownPortImpl.java:16-51`）；`end()` 目前是**有意留空**（`:43-50`，理由：今天的冷却条目永不清除）。

### 6.7 热键栏（图标、刷新、保护）
- 槽位来源：角色模板的 `slotMap`（`core/Role.java:280`），`updateHotbar()` 遍历它逐槽 `inv.setItem(slot, ...)`（`RoleInstance.java:437-463`）。
- 图标内容由组件的 `createIconItem(RoleInstance)` 生成：技能见 `core/Skill.java:43-88`，主武器见 `core/MainWeapon.java:52-96`。状态与材质/颜色：
  | 状态 | 材质 | 名字颜色 | 名字后缀 | lore |
  |---|---|---|---|---|
  | 冷却中 | `STRUCTURE_VOID` | 灰 | 技能：`<x.x>s`；主武器：无 | `Skill is on cooldown.` / `MainWeapon is on cooldown.` |
  | 被禁用（沉默/眩晕） | `BARRIER` | 红 | ` DISABLED` | `… has been disabled.` |
  | 能量不足（**仅两个技能覆写里有**） | `STRUCTURE_VOID` | 灰 | ` ENERGY LACK` | 无（该分支不加 lore） |
  | 就绪 | 组件自己的图标 | 绿 | 无 | `Skill is ready.` / `MainWeapon is ready.` |
  > **"技能冷却名带秒数、主武器不带"是冻结的可见差异**（设计 `docs/组件系统设计-Unity风格.md` §4.2 kind 差异表）。
- 周期性刷新：ticker 每 tick 调两次轮询 ——
  - `shouldUpdateHotbar()`（`RoleInstance.java:820-828`）：只要**存在冷却已结束**的技能或武器，就整栏重建（`updateHotbar()`）；
  - `shouldUpdateItemMeta()`（`:830-837`）：只要**存在仍在冷却**的技能，就逐个刷新它们的显示名（`updateAllSkillItemMeta()` → `updateSkillItemMeta()`，`:466-497`）。
  两者都为假时**不写物品**（这是"空闲 tick 零 setItem"的现行实现；阶段 5 会换成脏标记帧末 flush）。
- **物品保护**：技能/主武器物品带 PDC 标记（`Skill.Utils.SKILL_KEY` = `skill_id`，`core/Skill.java:112-136`；`MainWeapon.Utils.MAIN_WEAPON_KEY` = `main_weapon_id`，`core/MainWeapon.java:123-143`）；`Q` 丢弃会被取消并转成技能触发（`SkillListener.java:108-141`、`MainWeaponListener.java:116-148`）；容器点击会被取消（`SkillListener.java:145-159`、`MainWeaponListener.java:151-165`）。
- 清理：`clearHotbar()` 清空快捷栏 0–8 中所有带上述 PDC 标记的物品（`RoleInstance.java:500-520`），在死亡/重生/清角色时调用（`PlayerListener.java:26/33`、`RoleInstance.java:853`）。

### 6.8 药水记账（防泄漏）
- 只有经 `RoleInstance.applyPotionEffect(PotionEffect)` 施加的效果会被记入 `appliedPotionTypes`（`RoleInstance.java:609-613`）；`clear()` 时**只移除记账里的类型**（`:857-861`），不再无条件清空玩家身上的所有药水效果（阶段 1 的 O-7 修复）。
- 因此**新写的组件如果要给自己/别人加药水，必须走这条记账入口**（新侧端口对应 `BuffPort` 的扩展，见 `docs/阶段4-交付小结.md` §5.18 的裁定 R-1）。

### 6.9 组件异常隔离
- 每 tick 逐个组件独立 `try/catch`：单个组件抛异常只跳过它，首次报 `SEVERE`、恢复正常后报一次 INFO（`RoleInstance.java:801-817` 的 `runComponentUpdate`）。
