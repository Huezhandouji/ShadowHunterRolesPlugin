# 口径澄清 · F1 链的「项序列」必须与本批实际比较的项同写

> **用途**：消除一个**已经导致假失败**的口径歧义。本件不改任何既有证据，只规定**今后怎么写、怎么判**。
> **触发**：队长对 t5 做独立复核时，按 `[jar, log, 物证, 报告]` 的顺序比较，第三环得 `False` ⇒ 看似违规；查证后确认 **t5 合规**，问题在判据写法。

---

## §1 事实：同一个概念在四处写法不同

| 出处 | 项序列 |
|---|---|
| `接任者交接-总账.md` §9 | `jar < log < 说明` |
| 本计划的**多张卡面** | `jar < log < 物证` |
| `阶段5-4.4接管-独立复核报告.md`（t4） | `jar < log < 物证 < 报告`（四环） |
| `阶段5-4.4外观取证-停服物证.txt` §7（t5） | `jar < log 内容终点 < 转录 < 冻结动作 < 报告 < 本件`（六项） |

四种写法**都能自洽成立，但互不等价** —— 拿其中一种去核另一种，就会得到**假失败**（本次即如此）。

## §2 规定

**必备环（这才是判据）**：

1. `jar mtime < log 内容终点` —— 证据晚于它所覆盖的制品（**这是 F1 的全部要义**）；
2. `jar mtime < 该批**每一件覆盖该制品的证据件**的产生时刻`；
3. `log 内容终点 ≤ 冻结动作时刻` —— 冻结不得早于内容终点。

**适用范围（重要，否则会被误判）**：必备环只约束**覆盖该制品的证据件**（起服日志、停服物证、复核/取证报告、交付说明等）。
**输入类文档不在其列** —— 需求/判据冻结件、设计预案、前置清单等都是**制品之前**产生的**输入**，`jar < 它` 天然为假，那是**正常且必须**的。

**实例（防误判）**：`阶段5-需求与验收.md` 的 mtime = `12:47:52.247`，**早于**本代 jar 的 `12:54:07.286` —— **不构成违规**：它是 t2 施工所依据的**判据冻结件**，不是覆盖制品的证据。

**不构成判据**：证据件**彼此之间**的先后（物证 / 报告 / 说明谁先谁后）。它们的书写顺序是实现细节，不承载语义。

**写法要求**：声明 `ORDER = True` 时，**必须同时列出它实际比较的项序列与逐项 mtime**。t5 做到了这一点 —— 这正是它**未被误判**的原因（它把 `log 内容终点` 与 `冻结动作` 分列，比四环写法更精确）；而队长那次比较**没有先问"比较的是哪几项"**，属队长侧判据写法缺陷。

## §3 三批的现算复核（队长）

| 批 | jar | log 内容终点 | 冻结动作 | 其余证据件 | 必备环 |
|---|---|---|---|---|---|
| t2 | 12:54:07.286 | — | log 13:00:33.240 | 物证 13:01:37.789 · 说明 13:03:28.719 | ✅ |
| t4 | 12:54:07.286 | — | log 13:11:59.139 | 物证 13:15:01.821 · 报告 13:16:23.880 | ✅ |
| t5 | 12:54:07.286 | 13:23:59.207 | 13:24:24.242 | 转录 13:24:00.398 · 报告 13:28:50.458 · 物证 13:29:09.079 | ✅ |

⇒ **三批全部合规，不存在 F1 违反。** 队长报出的「第三环 False」是**假失败**。

## §4 给后来者

- 判 F1 **先问「你比较的是哪几项」**，再逐项比 mtime；
- **不要**用 `jar < log < 物证 < 报告` 这种**未经声明的固定序列**去套别人的证据件；
- 本项目真正的 F1 语义只有一句：**证据必须晚于它所覆盖的制品**；其余顺序不承载意义。

---

**给后来者的一句话**：**判据必须与测量口径同写** —— 连"比较哪几项"都算口径的一部分；不写，就会有人（包括队长）拿另一套序列判出**假失败**。
