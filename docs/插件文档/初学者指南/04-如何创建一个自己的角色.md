# 04 · 如何创建一个自己的角色

## 目标

做完这一篇，你会得到一个**自己的角色**：

- 能用 `/role set myrole` 选出来；
- 选完之后快捷栏第 1 格出现一个技能，图标是一个铁锭；
- 按键能放技能（放的时候有音效、回 2 点血），放完图标变灰、倒数 3 秒后恢复。

这一篇是整组文档的**终点**：前面三篇（`01` `02` `03`）都是为了让你看懂这里要写的代码。

## 你要做的事，一共五步

| 步骤 | 做什么 | 涉及文件 |
|---|---|---|
| 1 | 写一个新的技能（一个类） | 新建 `src/main/java/com/shadowHunterRolesPlugin/roleComponent/myRole/MyFirstSkill.java` |
| 2 | 在角色清单里登记 | 修改 `src/main/java/com/shadowHunterRolesPlugin/registry/RoleLoader.java` |
| 3 | 构建 | 命令行 |
| 4 | 起服务端 | 命令行 |
| 5 | 进游戏验证 | `/role set myrole` |

> **开工前先备份**：把要改的 `RoleLoader.java` 复制一份放到别处（例如桌面）。第 5 步之后如果发现改坏了，「改坏了怎么退回」一节有三种退回方法。

## 第 1 步：写一个技能

### 文件放哪、叫什么

新建文件：

```
src/main/java/com/shadowHunterRolesPlugin/roleComponent/myRole/MyFirstSkill.java
```

规矩是：**类的名字 = 文件的名字**。这里的类叫 `MyFirstSkill`。`myRole` 是你自己的文件夹（现有的角色组件放在 `roleComponent/meiqiHezi/`、`roleComponent/red/` 这类文件夹下，你也建一个自己的）。

### 把下面整份内容抄进去

> 这是一份**完整文件**，可以整段复制；改一改文字和数值就是你自己的了。

```java
package com.shadowHunterRolesPlugin.roleComponent.myRole;

import com.shadowHunterRolesPlugin.core.Skill;
import com.shadowHunterRolesPlugin.core.dispatch.CastResult;
import com.shadowHunterRolesPlugin.core.dispatch.CastSignal;
import com.shadowHunterRolesPlugin.core.ports.ComponentServices;
import net.kyori.adventure.text.Component;
import org.bukkit.Material;
import org.bukkit.Sound;
import org.bukkit.entity.Player;

public class MyFirstSkill extends Skill {

    public MyFirstSkill(String id, ComponentServices services){
        super(
                id,
                services,
                Component.text("我的第一招"),
                Component.text("放一次，回 2 点血"),
                60,
                0,
                Material.IRON_INGOT
        );
    }

    @Override
    public CastResult onCast(CastSignal signal){
        if(!svc().buffs().canCastSkill()) return CastResult.NO_COOLDOWN;

        Player caster = svc().self().player();
        caster.getWorld().playSound(
                caster.getLocation(),
                Sound.ENTITY_EXPERIENCE_ORB_PICKUP,
                1f,
                1f
        );
        svc().vitals().heal(2);

        svc().cooldowns().start(getCooldownTicks());
        return CastResult.SUCCEED;
    }
}
```

### 每一块在说什么

**第一块：住在哪里 + 有哪些工具箱零件**

```java
package com.shadowHunterRolesPlugin.roleComponent.myRole;

import com.shadowHunterRolesPlugin.core.Skill;
...
```

- `package` 那行必须和文件所在的文件夹路径一致：文件夹是 `roleComponent/myRole`，那行就写 `com.shadowHunterRolesPlugin.roleComponent.myRole`；
- `import` 是"从别的文件借东西用"：`Skill`（技能的模板）、`CastResult`（施放结果）、`CastSignal`（这次触发的信息）、`ComponentServices`（工具箱）、`Component`（游戏里的文字）、`Material`（图标物品）、`Sound`（音效）、`Player`（玩家）。**照抄就行。**

**第二块：声明这是一个技能 + 构造函数（名字与数值）**

```java
public class MyFirstSkill extends Skill {

    public MyFirstSkill(String id, ComponentServices services){
        super(
                id,
                services,
                Component.text("我的第一招"),
                Component.text("放一次，回 2 点血"),
                60,
                0,
                Material.IRON_INGOT
        );
    }
```

- `extends Skill` 读作"这是一个技能"。继承之后，框架才认得它、才会在按键时调用你写的函数；
- `public MyFirstSkill(String id, ComponentServices services)` 是**构造函数**，两个参数必须长这样：**第一个是名字（`String id`），第二个是工具箱（`ComponentServices services`）**。框架需要造这个技能时，会把这两样东西交给你（框架那边干这件事的地方叫 `ComponentFactory`，你可以把它理解成"按图纸造零件的工人"）；
- `super(...)` 把这七样东西交给技能的模板去存：

| 顺序 | 是什么 | 你这里填的 |
|---|---|---|
| 1 | 名字 | `id`（框架传进来的，不写死） |
| 2 | 工具箱 | `services`（框架传进来的） |
| 3 | 显示名（图标上的字） | `Component.text("我的第一招")` |
| 4 | 描述（图标下面那行字） | `Component.text("放一次，回 2 点血")` |
| 5 | 冷却（单位 tick，1 秒 = 20 tick） | `60` = 3 秒 |
| 6 | 能量消耗 | `0`（不耗能量） |
| 7 | 图标物品 | `Material.IRON_INGOT`（铁锭） |

**第三块：玩家按下技能时做什么**

```java
    @Override
    public CastResult onCast(CastSignal signal){
        if(!svc().buffs().canCastSkill()) return CastResult.NO_COOLDOWN;

        Player caster = svc().self().player();
        caster.getWorld().playSound(
                caster.getLocation(),
                Sound.ENTITY_EXPERIENCE_ORB_PICKUP,
                1f,
                1f
        );
        svc().vitals().heal(2);

        svc().cooldowns().start(getCooldownTicks());
        return CastResult.SUCCEED;
    }
```

- `@Override` 是"我在重写模板里的同名函数"的标记；
- 第一行问"现在允许放技能吗"（被沉默或眩晕时不允许），不允许就直接返回 `CastResult.NO_COOLDOWN`（什么都没做、也不进冷却）；
- `svc().self().player()` 拿到**你自己**（施放者）。规矩是**每次现取**，不要存进字段；
- `playSound(...)` 放一个音效，让你知道技能确实触发了；
- `svc().vitals().heal(2)` 给自己回 2 点血（`vitals` 是工具箱里管"生命"的那一格）；
- `svc().cooldowns().start(getCooldownTicks())` **开始冷却** —— 这一步要在你自己的代码里写，不会有人替你写；`getCooldownTicks()` 读出来的就是构造函数里那个 `60`；
- `return CastResult.SUCCEED;` 告诉框架"这次施放成功了"。

## 第 2 步：在角色清单里登记

打开 `src/main/java/com/shadowHunterRolesPlugin/registry/RoleLoader.java`。这个文件是"**照清单把角色做出来**"的地方：里面有一个列表，每一项是一个角色；每个角色的清单由一句一句的 `.addSkill(...)`、`.addPassive(...)`、`.addMainWeapon(...)` 填出来。

你要改**三个地方**，都是往现有代码里加，不删不改别人的东西。

### 顶部加一个名字常量

在文件顶部那一串 `private static final String ID_...` 的后面，加一行（照抄这一串的写法）：

```java
    private static final String ID_MY_FIRST_SKILL = "myrole_skill_first";
```

这个字符串是**你组件的名字**：它在整个角色里必须唯一（技能、被动、主武器共用一个名字空间，不能重名）。别去改别人已有的名字。

### 加一个"我的角色"的清单方法

在 `meiqiheziBuilder()` 或 `redBuilder()` 旁边，照着它们的样式加一个自己的：

```java
    private static Role.Builder myRoleBuilder() {
        return new Role.Builder("myrole")
                .displayName(Component.text("MyRole"))
                .description(List.of(
                        Component.text("我的第一个角色"),
                        Component.text("一技能：放一次，回 2 点血")
                ))
                .maxHP(40)
                .baseATK(10)
                .maxEnergy(100)
                .maxSanTE(100)
                .faction(Faction.HUNTER)
                .addSkill(ID_MY_FIRST_SKILL, MyFirstSkill::new, 1)
                .icon(Material.IRON_INGOT);
    }
```

逐句读：

| 这一句 | 意思 |
|---|---|
| `new Role.Builder("myrole")` | 开始填一张角色清单，`myrole` 是**角色 id**（就是 `/role set myrole` 里的那个词；只能有一段文字，不能有空格） |
| `.displayName(Component.text("MyRole"))` | 角色的显示名 |
| `.description(List.of(...))` | 角色的描述（几行字，用列表装） |
| `.maxHP(40)` | 生命上限（必须大于 0） |
| `.baseATK(10)` | 基础攻击力（不能是负数） |
| `.maxEnergy(100)` | 能量上限（不能是负数） |
| `.maxSanTE(100)` | 理智上限（不能是负数；理智是这套系统的另一个数值） |
| `.faction(Faction.HUNTER)` | 阵营，只能填 `Faction.HUNTER` 或 `Faction.SHADOW`；不写就等于 `UNKNOWN`（谁都是敌人） |
| `.addSkill(名字, 用哪个类来造, 放第几格)` | 把一个技能放进清单：`MyFirstSkill::new` 的意思是"需要的时候，用这个类的构造函数造一个" |
| `.icon(Material.IRON_INGOT)` | 角色的图标（别的插件可以读它；这里先填纸） |

`Role.Builder` 是一支"**逐句填表的笔**"：每调一次就填一格，最后交给框架时它会把整张表收下。这些 `add...` / `max...` 方法的真实定义在 `src/main/java/com/shadowHunterRolesPlugin/core/Role.java` 的 `public static class Builder` 里。

### 把新角色加进"启动时读的清单"

同一个文件里有个方法叫 `defaultDefinitions()` —— 服务端启动时会读它，得到"有哪些角色"。把原来那一行改成三项：

```java
    public List<Definition> defaultDefinitions() {
        return List.of(
                new Definition("meiqihezi", RoleLoader::meiqiheziBuilder),
                new Definition("red", RoleLoader::redBuilder),
                new Definition("myrole", RoleLoader::myRoleBuilder)
        );
    }
```

`Definition` 可以读成"一张小纸条"：上面两样东西 —— **角色 id** 和 **用哪个函数来装配它**（`RoleLoader::myRoleBuilder` 就是"用上面刚加的那个方法"的意思；这种"把函数名交出去"的写法，`03` 里解释过）。

### 别忘了 import

在 `RoleLoader.java` 顶部的 `import` 区，加上你自己技能的位置（否则文件里的 `MyFirstSkill` 找不到）：

```java
import com.shadowHunterRolesPlugin.roleComponent.myRole.MyFirstSkill;
```

## 第 3 步：构建

```powershell
cd ShadowHunterRoles
$env:GRADLE_USER_HOME = "$PWD\.gradle-work"
.\gradlew build -x copyPluginJar --console=plain
```

看到 `BUILD SUCCESSFUL` 就说明代码翻译并打包成功，成品是 `build/libs/ShadowHunterRolesPlugin-1.0.0.jar`。

- 如果这一行没出现，而是打印了一串红字 —— 那是**代码本身写错了**（多半是拼写错、少了一个分号、括号没配对）。报错里会写**哪个文件的哪一行**，照着去看就行。这一步不需要起服务端。

## 第 4 步：起服务端

```powershell
.\gradlew runServer
```

- 拉起一个 Minecraft 1.21.11 的调试服务端，文件夹是仓库里的 `run/`；
- 连接的号码是 **25566**（写在 `run/server.properties` 的 `server-port` 里，客户端填 `localhost:25566`）；
- 控制台出现 `ShadowHunter Character System enabled.` 表示插件加载完成；
- 结束服务端：在它的控制台里输入 `stop` 回车。

## 第 5 步：进游戏验证

1. 进服后输入：

```
/role set myrole
```

2. 屏幕下方应该看到回显：

```
Your role has been set: myrole
```

3. 看快捷栏：
   - **第 1 格**是一个铁锭图标，名字是「我的第一招」；
   - 0 号位是空的 —— 这个角色只有技能，没有主武器，这是正常的；
4. 按 `1` 选中它，**右键**放一次：
   - 听到音效、回一点血（如果你当时血不满）；
   - 这一格图标立刻变灰，名字后面开始倒数（约 3 秒）；
5. 数完 3 秒，图标恢复原样 —— 可以再放一次。

做到这里，**你的角色就完成了**：`/role set` 能选出来、按键能放技能、有图标。

## 第 6 步（可选）：再挂一个主武器或被动

清单方法可以继续往后接。下面两句是真实存在的写法（`Role.Builder` 里定义的方法），你需要先写好对应的组件类再挂上去：

```java
                .addMainWeapon(ID_MY_MAIN_WEAPON, MyMainWeapon::new, 0)
                .addPassive(ID_MY_PASSIVE, MyPassive::new)
```

| 这一句 | 与技能的区别 |
|---|---|
| `.addMainWeapon(名字, 用哪个类来造, 放第几格)` | 主武器**要写格子号**，习惯放 `0`；组件类要 `extends MainWeapon`，构造函数参数顺序是"显示名、描述、图标、冷却"（图标在冷却**之前**，与技能相反） |
| `.addPassive(名字, 用哪个类来造)` | 被动**没有格子号**（它不占快捷栏）；组件类要 `extends PassiveSkill`，构造函数是"名字、工具箱、显示名、描述" |

想抄现成的写法：`roleComponent/meiqiHeZi/mainWeapon/MeiqiheziJuejueMainWeapon.java`（主武器）、`roleComponent/AutoRecoverEnergyPassive.java`（被动）。

## 规则与常见报错

### 这些规则由代码强制检查，违反就装不上

| 规则 | 也就是说 | 源码位置 |
|---|---|---|
| **槽位只能是 0 到 8，而且不能冲突** | `.addSkill(..., 1)` 里的 `1` 必须在 0..8 之间，且同一个角色里两个组件不能抢同一格 | `core/Role.java` 的 `Role.Builder.validateSlot(int slot)`（由 `addSkill` / `addMainWeapon` 调用） |
| **组件 id 跨类型唯一** | 技能、被动、主武器**共用同一个名字空间**：`myrole_skill_first` 只能出现一次，也不能和别人的重名 | `core/Role.java` 的 `Role.Builder.ensureIdNotRegistered(String type, String id)` |
| **角色 id 不能为空** | `new Role.Builder("myrole")` 里的名字不能是空的 | `core/Role.java` 的 `Role.Builder(String id)` |
| **数值要合法** | `maxHP > 0`；`baseATK`、`maxEnergy`、`maxSanTE` 不能是负数 | `core/Role.java` 的 `Role.Builder.maxHP` / `baseATK` / `maxEnergy` / `maxSanTE` |
| **某个角色装不上，不影响别的角色** | 你写错的那一个会被跳过，其它角色照常可用 | `registry/RoleLoader.java` 的 `loadInto(...)` |

### 起服时日志里可能出现的报错

服务端会把发生的事情一行行打印在控制台，同时写进 `run/logs/latest.log` 这个文件（这叫**日志**）。挨着看就能找到原因：

| 日志里看到 | 意思 | 怎么办 |
|---|---|---|
| `Role 'myrole' failed assembly validation and was NOT registered` | 你填的清单里有一格不合规则，这个角色没被收下 | 往上看几行，紧跟在这条后面的原因就是下面某一条 |
| `Slot must be between 0 and 8, got: 9` | 格子号超出了 0..8 | 把那个数字改成 0 到 8 |
| `Slot 1 is already occupied by '...'` | 两个组件抢了同一格 | 给新组件换一个空格子 |
| `Skill already registered: myrole_skill_first` | 组件的名字撞车了（技能 / 被动 / 主武器共用一个名字空间） | 换一个没人用过的名字 |
| `Role maxHP cannot be negative.` | `maxHP` 填了 0 或负数 | `maxHP` 必须大于 0 |
| 构建阶段就报错（没走到起服） | 代码写错了 | 照报错里的文件名 + 行号检查 |

### `/role set` 打出去没反应，或提示别的

| 屏幕上看到 | 意思 | 怎么办 |
|---|---|---|
| `Your role has been set: myrole` | 成功 | — |
| `Role 'myrole' not exist!` | 这个 id 没被登记（清单没加上、或起服日志里它被跳过了） | 检查第 2 步的三处改动，并看日志 |
| `Wrong arguments. Use /role help to learn how to use.` | 命令打错了（例如 `/role set` 后面没跟 id） | 照用法重打 |
| 什么都没打印 | `/role` 不带参数时本来就是静默的 | 补上 `set myrole` |

## 改坏了怎么退回

三种方法，从最省事到最彻底：

**方法一：用开工前的备份盖回去。** 把之前复制到桌面的 `RoleLoader.java` 覆盖回原位置（以及删掉你新建的 `MyFirstSkill.java`），然后重新构建。

**方法二：让版本库还原一个文件。** 如果你用 git 管理这份代码，而你想还原的文件在**上次提交**时是好的：

```powershell
git checkout -- src/main/java/com/shadowHunterRolesPlugin/registry/RoleLoader.java
```

（这会丢掉你自己在这个文件里的改动 —— 只在确实想还原时用。）

**方法三：全部撤销，回到加角色之前。** ① 删掉新建的文件 `roleComponent/myRole/MyFirstSkill.java`；② 用方法一把 `RoleLoader.java` 还原（或删掉你加的那三处：名字常量、`myRoleBuilder()`、`defaultDefinitions()` 里的那一项）；③ 重新构建、重启服务端。

**三种方法做完都要：重新构建 + 重启服务端**，改动才会生效。
