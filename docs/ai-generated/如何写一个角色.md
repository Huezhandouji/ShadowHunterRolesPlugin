# 如何写一个角色

本文面向想给本插件加一个新角色的开发者。假定你懂 Java 与 Bukkit，但不熟悉本仓库的内部结构 —— 本文只讲**怎么用**，照着抄就能跑。

一个角色由三类组件拼成：

| 类型 | 基类 | 占热键栏 | 有冷却 |
| --- | --- | --- | --- |
| 技能 | `Skill` | 是（`setSlot`） | 是 |
| 主武器 | `MainWeapon` | 是（`setSlot`） | 是 |
| 被动 | `PassiveSkill` | 否（无 `setSlot`） | 否 |

出处：`roleComponent/base/Skill.java:32` · `roleComponent/base/MainWeapon.java:37` · `roleComponent/base/PassiveSkill.java:17`。

## 1. 先定 id

每个组件**自己**声明一个 `public static final String ID`，值是装配键（注册时用它把描述符挂到角色上）：

```java
/** 本组件的登记 id。 */
public static final String ID = "my_role_skill_slash";
```

出处：`roleComponent/builtin/ExampleSelfRefreshingSkill.java:46` · `roleComponent/custom/meiqiHezi/skill/MeiqiheziCircleSlashSkill.java:26`。

角色本身也有一个 id，写在 `new Role.Builder("...")` 里，例如 `"meiqihezi"`（`registry/RoleLoader.java:139`）。

约定：角色 id 用 `my_role`，组件 id 用 `my_role_xxx`，避免和既有角色撞。

## 2. 写一个技能

技能占热键栏，所以它必须有栏位。

```java
package com.example.myplugin;

import com.shadowHunterRolesPlugin.core.ports.ComponentServices;
import com.shadowHunterRolesPlugin.roleComponent.ActiveComponent.CastSignal;
import com.shadowHunterRolesPlugin.roleComponent.DamageKind;
import com.shadowHunterRolesPlugin.roleComponent.base.Skill;
import com.shadowHunterRolesPlugin.roleComponent.builtin.BuffComponent;
import com.shadowHunterRolesPlugin.roleComponent.builtin.EnergyComponent;
import com.shadowHunterRolesPlugin.roleComponent.builtin.VitalsComponent;
import net.kyori.adventure.text.Component;
import org.bukkit.Material;
import org.bukkit.entity.Player;

public class MySlashSkill extends Skill {

    public static final String ID = "my_role_skill_slash";

    private BuffComponent buff;
    private EnergyComponent energy;
    private VitalsComponent vitals;

    public MySlashSkill(String id, ComponentServices services, Specification specification) {
        super(id, services, specification);
    }

    /** 描述符：表现值都在这里声明；栏位由注册处用 setSlot 指定。 */
    public static final class Specification extends Skill.Specification {

        public Specification() {
            super(
                    Component.text("斩击"),
                    Component.text("对附近敌人造成 20 点物理伤害"),
                    200,
                    15,
                    Material.GOLD_INGOT
            );
        }

        @Override
        public MySlashSkill create(String id, ComponentServices services) {
            return new MySlashSkill(id, services, this);
        }
    }

    /** 解析本组件要用到的其他组件，缓存进字段。 */
    @Override
    public void start() {
        buff = svc().components().get(BuffComponent.class);
        energy = svc().components().get(EnergyComponent.class);
        vitals = svc().components().get(VitalsComponent.class);
    }

    /** 施放入口：右键/左键/Q 触发时由框架调用。 */
    @Override
    public void onCast(CastSignal signal) {
        Player caster = svc().self().player();

        if (!buff.canCastSkill()) return;
        if (!energy.tryConsume(getEnergyCost())) return;

        for (Player victim : caster.getLocation().getNearbyPlayers(5)) {
            if (!svc().roleInfo().isHostile(victim)) continue;
            vitals.damage(victim, 20, DamageKind.PHYSICAL);
        }

        startCooldown();
    }

    /** 闸门：能否施放（被沉默/眩晕时返回 false，物品会灰显）。 */
    @Override
    protected boolean canUse() {
        return buff.canCastSkill();
    }

    /** 当前能量：用于判断"能量不足"态。 */
    @Override
    protected int currentEnergy() {
        return energy.current();
    }
}
```

| --- | --- | --- |
| `Specification.create(String, ComponentServices)` | `roleComponent/base/Skill.java:121` | 编译不过（抽象方法） |
| `canUse()` | `roleComponent/base/Skill.java:48` | 编译不过（抽象方法） |
| `currentEnergy()` | `roleComponent/base/Skill.java:57` | 编译不过（抽象方法） |

### 描述符构造参数

`super(displayName, description, cooldownTicks, energyCost, icon)` —— 出处 `roleComponent/base/Skill.java:108`。

| 参数 | 含义 | 备注 |
| --- | --- | --- |
| `displayName` | 物品显示名 | `Component.text(...)` |
| `description` | 物品描述（lore） | 一行 |
| `cooldownTicks` | 冷却时长（游戏刻） | 200 = 10 秒 |
| `energyCost` | 施放消耗的能量 | 0 = 不耗能 |

### 可选覆写

| 方法 | 出处 | 默认行为 |
| --- | --- | --- |
| `start()` | `roleComponent/RoleComponent.java:73` | 空实现。取其他组件**只能**在这里做 |

| `onAttack(AttackSignal)` | `roleComponent/ActiveComponent.java:247` | 空实现，技能一般不用 |

## 3. 写一个主武器

主武器与技能同构，差异只有两处：**没有能量消耗**、**冷却名不带秒数**（出处 `roleComponent/base/MainWeapon.java:27-31`）。

```java
public class MyBlade extends MainWeapon {

    public static final String ID = "my_role_main_weapon";

    private BuffComponent buff;
    private VitalsComponent vitals;

    public MyBlade(String id, ComponentServices services, Specification specification) {
        super(id, services, specification);
    }

    public static final class Specification extends MainWeapon.Specification {

        public Specification() {
            super(
                    Component.text("我的刀"),
                    Component.text("普攻造成 15 点物理伤害"),
                    Material.DIAMOND_SWORD,
                    100
            );
        }

        @Override
        public MyBlade create(String id, ComponentServices services) {
            return new MyBlade(id, services, this);
        }
    }

    @Override
    public void start() {
        buff = svc().components().get(BuffComponent.class);
        vitals = svc().components().get(VitalsComponent.class);
    }

    /** 左键/右键的施放入口。 */
    @Override
    public void onCast(CastSignal signal) {
        if (!buff.canUseMainWeapon()) return;
        // ... 你自己的效果 ...
        startCooldown();
    }

    /** 攻击玩家时的入口（右键攻击走这里）。 */
    @Override
    public void onAttack(AttackSignal signal) {
        Player victim = signal.victim();
        vitals.damage(victim, 15, DamageKind.PHYSICAL);
    }

    @Override
    protected boolean canUse() {
        return buff.canUseMainWeapon();
    }
}
```

### 与技能的差异

| 项 | `Skill` | `MainWeapon` |
| --- | --- | --- |
| 描述符构造参数 | `(displayName, description, cooldownTicks, energyCost, icon)` | `(displayName, description, icon, cooldownTicks)` |
| 出处 | `base/Skill.java:108` | `base/MainWeapon.java:97` |
| 能量消耗 | 可声明 | 恒为 0（`base/MainWeapon.java:42`） |
| `currentEnergy()` | **必须**覆写 | **不要**写（没有这个抽象方法） |
| 攻击入口 | `onAttack` 一般不用 | `onAttack(AttackSignal)` 是主要入口 |

`AttackSignal` 定义在 `roleComponent/ActiveComponent.java:66`，取值用 `signal.victim()`。

## 4. 写一个被动

被动**不占热键栏** —— 它的描述符类型里**没有** `setSlot`（出处 `roleComponent/base/PassiveSkill.java:34`）。

```java

        public Specification() {
            super(Component.text("流血"), Component.text("攻击附带流血"));
        }

        @Override
        public MyBleedPassive create(String id, ComponentServices services) {
            return new MyBleedPassive(id, services);
        }
    }

    @Override
    public void update() {
        // 每 tick 的被动效果
    }
}
```

### 与技能/主武器的差异

| 项 | `Skill` / `MainWeapon` | `PassiveSkill` |
| --- | --- | --- |
| 基类 | `ActiveComponent` | `RoleComponent` |
| 描述符构造 | 五个/四个参数（含冷却、图标） | **只有** `(displayName, description)` |
| 出处 | `base/Skill.java:108` · `base/MainWeapon.java:97` | `base/PassiveSkill.java:46` |
| `setSlot` | 有 | **没有** |

| 出处 | `base/Skill.java:70` | `base/PassiveSkill.java:22` |
| 冷却 / 施放 / 攻击入口 | 有 | **没有**（被动不施放） |

出处（被动示例）：`roleComponent/custom/red/RedBleedPassive.java:71`。

## 5. 在 RoleLoader 里注册

打开 `registry/RoleLoader.java`，照着既有角色加一段：

```java
private static Role.Builder myRoleBuilder() {
    return withBuiltIns(new Role.Builder("my_role"))
            .displayName(Component.text("我的角色"))
            .description(List.of(
                    Component.text("第一行描述"),
                    Component.text("第二行描述")
            ))
            .faction(Faction.HUNTER)
            .addComponent(MyBlade.ID, new MyBlade.Specification().setSlot(0))
            .addComponent(MySlashSkill.ID, new MySlashSkill.Specification().setSlot(1))
            .addComponent(MyBleedPassive.ID, new MyBleedPassive.Specification())
            .icon(Material.DIAMOND_SWORD);
}
```

然后把这条定义加进 `defaultDefinitions()`（出处 `registry/RoleLoader.java:68-74`）：

```java
return List.of(
        new Definition("meiqihezi", RoleLoader::meiqiheziBuilder),
        new Definition("red", RoleLoader::redBuilder),
        new Definition("selfUpdateExample", RoleLoader::selfUpdateExampleBuilder),
        new Definition("my_role", RoleLoader::myRoleBuilder)
);
```

### `withBuiltIns` 是必须的

每个角色的 builder **开头**都要调 `withBuiltIns(...)`，它把六个内建组件加进模板（出处 `registry/RoleLoader.java:127-135`）：

```java
private static Role.Builder withBuiltIns(Role.Builder builder) {
    return builder
            .addComponent(HotbarRenderComponent.ID, new HotbarRenderComponent.Specification())
            .addComponent(EnergyComponent.ID, new EnergyComponent.Specification())
            .addComponent(SanTEComponent.ID, new SanTEComponent.Specification())
            .addComponent(VitalsComponent.ID, new VitalsComponent.Specification())
            .addComponent(BuffComponent.ID, new BuffComponent.Specification())
            .addComponent(TaskComponent.ID, new TaskComponent.Specification());
}
```

这六个 id 分别是 `"hotbarRender"` · `"energy"` · `"sante"` · `"vitals"` · `"buffs"` · `"tasks"`。

它们各自来自本组件的 `public static final String ID`，例如：

| 组件 | id 值 | 出处 |
| --- | --- | --- |
| `HotbarRenderComponent` | `"hotbarRender"` | `roleComponent/builtin/HotbarRenderComponent.java:70` |
| `EnergyComponent` | `"energy"` | `roleComponent/builtin/EnergyComponent.java:54` |
| `SanTEComponent` | `"sante"` | `roleComponent/builtin/SanTEComponent.java:55` |
| `VitalsComponent` | `"vitals"` | `roleComponent/builtin/VitalsComponent.java:58` |
| `BuffComponent` | `"buffs"` | `roleComponent/builtin/BuffComponent.java:37` |
| `TaskComponent` | `"tasks"` | `roleComponent/builtin/TaskComponent.java:47` |

注意 `withBuiltIns` 在 `RoleLoader` 里是 `private static`（出处 `registry/RoleLoader.java:127`）—— 如果你在别的类里注册，把这段抄一份即可。

## 6. 三个最容易踩的坑

### 坑一：被动不占栏位

`PassiveSkill.Specification` **没有** `setSlot`（出处 `roleComponent/base/PassiveSkill.java:34`）。

```java
// 正确
.addComponent(MyBleedPassive.ID, new MyBleedPassive.Specification())

// 编译不过：PassiveSkill.Specification 里没有 setSlot
.addComponent(MyBleedPassive.ID, new MyBleedPassive.Specification().setSlot(2))
```

反过来，技能与主武器**必须**给栏位 —— 不给的话装配期抛异常：

```text
A hotbar specification of kind Skill must be given a slot (setSlot) before assembly.
```

出处：`roleComponent/RoleComponent.java:390-393`。

### 坑二：栏位是 0..8，且不能两件占同一格

栏位合法范围是 **0 到 8**（含两端）。越界抛：

```text
Slot must be between 0 and 8, got: 9
```

出处：`roleComponent/RoleComponent.java:331` · `core/Role.java:329`。

同一栏位被两件占，抛：

```text
Slot 1 is already occupied by 'my_role_skill_slash'.
```

出处：`core/Role.java:333-336`。

所以一个角色最多 9 件占栏组件。上面的注册段里主武器占 0、技能占 1，各不冲突。

### 坑三：冷却与能量都由组件自己管

**冷却**分两半：

- **时长**写在描述符里（`cooldownTicks` 参数，出处 `roleComponent/base/Skill.java:108`）；
- **启动点在你自己的施放成功处** —— 在 `onCast` 里显式调 `startCooldown()`（出处 `roleComponent/ActiveComponent.java:158`）。

```java
@Override
public void onCast(CastSignal signal) {
    if (!buff.canCastSkill()) return;
    if (!energy.tryConsume(getEnergyCost())) return;
    // ... 效果 ...
    startCooldown();   // 到这一行才算施放成功
}
```

注意：**施放失败时不要调 `startCooldown()`**，否则失败也会进冷却。上面两行 `return` 就是为了这个 —— 与既有技能写法一致（出处 `roleComponent/custom/meiqiHezi/skill/MeiqiheziCircleSlashSkill.java:86-87` · `:126`）。

其他冷却读口：`isCoolingDown()`（`ActiveComponent.java:194`）· `remainingCooldownTicks()`（`ActiveComponent.java:199`）· `stopCooldown()`（`ActiveComponent.java:182`）。

**能量**走能量组件：

| 你要做的事 | 怎么写 | 出处 |
| --- | --- | --- |
| 读当前能量 | `energy.current()` | `roleComponent/builtin/EnergyComponent.java:206` |
| 读上限 | `energy.max()` | `roleComponent/builtin/EnergyComponent.java:211` |
| 扣能量（不足则不扣） | `energy.tryConsume(n)` | `roleComponent/builtin/EnergyComponent.java:237` |
| 加能量 | `energy.increase(n)` | `roleComponent/builtin/EnergyComponent.java:249` |
| 直接设置 | `energy.set(n)` | `roleComponent/builtin/EnergyComponent.java:230` |

读当前能量时，**必须**在 `start()` 里先把组件取到字段（`energy = svc().components().get(EnergyComponent.class);`），再在 `currentEnergy()` 里用它。声明耗能为 0 的技能可以直接返回声明值：

```java
@Override
protected int currentEnergy() {
    return getEnergyCost();   // 声明耗能 0 ⇒ 不参与能量维度
}
```

出处：`roleComponent/builtin/ExampleSelfRefreshingSkill.java:162-165`。

## 7. 速查表：必填与可省

| 项 | 必填？ | 不写会怎样 |
| --- | --- | --- |
| 组件的 `public static final String ID` | 是 | 注册时没有键可用 |
| 嵌套 `Specification` 类 | 是 | 编译不过（`create` 抽象） |
| `Specification.create(...)` | 是 | 编译不过 |
| 技能的 `canUse()` | 是 | 编译不过 |
| 技能的 `currentEnergy()` | 是 | 编译不过 |
| 技能的 `onCast(...)` | 否 | 点了没反应（基类空实现，`ActiveComponent.java:236`） |
| 主武器的 `onAttack(...)` | 否 | 攻击没反应（基类空实现，`ActiveComponent.java:247`） |
| `start()` | 否 | 取不到其他组件（字段为 `null`） |
| `stop()` | 否 | 自己起的任务不会被取消 |
| `update()` | 否 | 没有每 tick 逻辑 |
| `buildItem()` | 否 | 用基类默认画法（`base/Skill.java:152` · `base/MainWeapon.java:131`） |
| 技能/主武器的 `setSlot(n)` | 是 | 装配期抛异常 |
| 被动的 `setSlot` | —— | 不存在这个方法 |
| `.faction(...)` | 否 | 默认 `Faction.UNKNOWN`（`core/Role.java:303`） |
| `.displayName(...)` / `.description(...)` / `.icon(...)` | 否 | 角色列表里显示为空 |

把 `Xxx` 换成你的类名即可。三个组件 + 注册段：

```java
// 需要的 import（与第 2 节技能段相同，另加 MainWeapon / PassiveSkill）：

// ────── 技能 ──────
public class XxxSkill extends Skill {

    public static final String ID = "xxx_skill";

    private EnergyComponent energy;

    public XxxSkill(String id, ComponentServices services, Specification specification) {
        super(id, services, specification);
    }
```

| 成员 | 可见性 | 说明 |

## 9. 检查清单

1. 三个组件各有 `public static final String ID`，值不重复。
2. 技能与主武器都调了 `.setSlot(n)`，`n` 在 0..8 内且互不相同。
3. 被动**没有** `.setSlot(...)`。
4. builder 开头调了 `withBuiltIns(...)`。
5. 新角色加进了 `defaultDefinitions()`。
6. 技能的 `canUse()` / `currentEnergy()` 都写了。
7. `startCooldown()` 只在施放成功的那条路径上。
8. 进服后用 `/role set xxx` 试一下，看物品是否出现在你指定的栏位。
