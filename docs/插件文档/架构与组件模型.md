### 3.1 新基类 `RoleComponent`（已落地）

`roleComponent/RoleComponent.java` 只允许出现三样东西：① `svc` 字段 ② 钩子方法 ③ `getComponent`——任何"顺手加个 helper"都属越界（`:5-16`、设计 `debug-logs/组件系统设计-Unity风格.md` §2 基类纪律）。

**5 个 default 钩子（框架无条件广播）**：

| 钩子 | 语义 | 出处 |
|---|---|---|
| `awake()` | 装配阶段：只解析跨组件依赖并缓存引用；**幂等**，不得改动任何玩家可见状态 | `RoleComponent.java:72-74` |
| `start()` | 开始生效：初始化数据、发放装备、登记定时器 | `:76-78` |
| `stop()` | 停止生效：**与 start 严格对称**；返回后框架自动回收本组件登记的资源 | `:80-82` |
| `update()` | 20 Hz；禁止阻塞、**禁止直接写热键栏**（渲染由框架负责） | `:86-88` |
| `onSanTEChange(int pre, int now)` | **事件钩子**（不是每 tick 广播）：只在 SanTE **真变化**时派发（`pre == now` 不派发）；派发期间的重入写入合并为**末次一次补发**（见 §3.3 的派发契约） | `RoleComponent.java`、`RoleInstance.java` |

### 3.3 组件启停机制（**单一机制：容器广播新钩子**）

> **一句话（截至 commit `bbab886`，阶段 4 收尾后）**：**组件启停 = 容器对全部已注册组件无条件广播** `awake()` / `start()` / `stop()` / `update()`；**`onSanTEChange(int,int)` 是事件钩子**（只在 SanTE 真变化时派发，契约见下）；**`stop()` 严格早于 `cancelAllAndClear()`**。**legacy 的 `*Aware` 接口与 `instanceof` 扇出已全部删除**（t44/t47 收尾）—— 不再存在"两套机制"。

> **SanTE 钩子的派发契约（阶段 4 追补 `fix1` 现状）**：`setCurrentSanTE(...)` → **先发布 `SanTEChangeEvent`（对外挂点保留）** → **容器直接派发** `dispatchSanTEChange(pre, now)`（**不经 Bukkit 事件总线**）：
> 1. `pre == now` ⇒ **不派发**；
> 2. **重入护栏**：派发期间组件再次改写 SanTE ⇒ 只记"末次待发值"并立即返回；本次派发返回后对末次值**补发一次**（中间态合并）—— 当前两个实现者（`DefaultSanTEZeroPunishment` / `RedDeeplySorrowSkill`）都不在钩子内同步写 SanTE ⇒ 该护栏**在当前组件集下不可达**，属防御性设施；
> 3. 派发顺序 = **注册表顺序**；异常隔离沿用 `runComponentUpdate`（单组件抛异常不影响其余）。
> **已删除**：`RoleInstance.triggerSanTEChange` / `triggerEnergyChange`、`RoleEventListener` 的两个转发 handler（该类现**无 handler**，类与注册点保留）；**红线**：`SanTEChangeEvent` / `EnergyChangeEvent` 的**对外发布不变**（第三方挂点）。

**广播点与兜底回收的顺序**（`core/RoleInstance.java`，实测）：

| 顺序 | 广播/动作 | 语义 |
|---|---|---|
| 1 | `component.awake()` | 装配后解析跨组件依赖（幂等） |
| 2 | `component.start()` | 开始生效 |
| 3 | `component.stop()` | 停止生效，**在兜底回收之前** |
| 4 | `componentRegistry.cancelAllAndClear()` | 框架兜底取消该组件资源表里的任务（`clear()` 路径） |

> **幂等说明**：若组件在 `stop()` 里自行取消任务，随后 `clear()` 的 `cancelAllAndClear()` 仍会清其资源表条目 —— 两者**不会对同一组件双触发同一逻辑**（重复取消是幂等的）。

> **历史（迁移期形态，已删除）**：四类 `*Aware` 接口（`LifecycleAware` / `UpdateAware` / `SanTEChangeAware` / `EnergyChangeAware`）**接口文件已删除**（`core/RoleComponentAware/` 目录现不存在）、`RoleInstance` 内的 `instanceof` 扇出已删除。**现算**：`git grep -c 'implements .*Aware' -- src` = **0**；仅少数组件 javadoc 里仍留有"去 legacy `XxxAware`"的历史说明（t47 的注释清理项）。设计判据与实证见 `debug-logs/组件系统设计-Unity风格.md` §3 `Aware` 判据。
