**三条根因（逐条给现场证据 + 修法）**

| # | 根因 | 现场证据 | 下一轮修法 |
|---|---|---|---|
| **1** | 探针 SETUP 先把 red 的 held slot 设成 **3（技能槽）**再攻击 ⇒ 攻击路径读到的是技能物品（无 `main_weapon_id`）⇒ **流血层从未写入** | 冻结件 `ATTACK n=1..3` 之后**始终无 `+4`**；转录 `d=4` 命中 0 | 攻击前 `setHeldItemSlot(0)`（武器在槽 0），攻击后再切回 3 施放 |
| **2** | **角色不跨登录持久**（t6 已证），而探针只在首次 SETUP 时 dispatch 一次 `/role set red` ⇒ 机器人重登后无角色/无实例 ⇒ `SanTE=-78` | 转录 **2808 行** `sante=-78`；冻结件 `WAIT_PLAYERS red=false` | 在 `getPlayerSanTE == -78` 时**自动重发** `/role set red`（并把 −78 视为"无数据"而非合法值） |
| **3** | **客户端工具链阻塞**：mineflayer 4.39.0 / minecraft-data 3.116.0 解析 Paper 1.21.11 的 **DUST 粒子包**失败（`PartialReadError @ packet_world_particles`）⇒ red 侧机器人**恰在流血结算成粒子的瞬间崩溃退出** | 客户端转录 `PartialReadError: Read error for undefined : undefined … Object.Particle` | 三选一：① 修 minecraft-data 的 particle 定义（工具区，零 src）；② 换用不受该包影响的客户端版本；③ 让"承受方"由**服务端合成**（本卡不具备）—— 注意 **+4 需要受害者在线**（`canReceiveBleed`），故不能简单断开机器人 |
