### 5.8 字符串多重集指纹的**规则原文**（口径定案：36 条 / `74D9FAF0…66D4`）

> 队长已裁定：**以此规则为准**（两人独立复算一致）；队长自拟规则得到的 35 条 / `00BB2701…` **作废**，仅作"口径差异"记录（与数值侧 381/382 同类）。规则必须书面固定，否则后来者无法复现。

**完整命令**（PowerShell；与 §7.2 数值口径同构，唯一区别是"保留字符串/字符字面量"而不是"保留数值"）：

```powershell
$p = 'ShadowHunterRoles\src\main\java\com\shadowHunterRolesPlugin\command\RoleCommand.java'
$t = [System.IO.File]::ReadAllText($p)                     # 读为 UTF-8（无 BOM 源码，ReadAllText 默认 UTF-8）
# 单遍扫描：块注释 | 行注释 | 双引号字符串 | 单引号字符；只保留后两者
$ms = [regex]::Matches($t, '(?s)/\*.*?\*/|//[^\r\n]*|"(?:\\.|[^"\\])*"|''(?:\\.|[^''\\])*''')
$lits = @(); foreach ($m in $ms) { $v = $m.Value; if ($v.Length -gt 0 -and ($v[0] -eq '"' -or $v[0] -eq "'")) { $lits += $v } }
$lits.Count                                                # → 36
$joined = ($lits | Sort-Object) -join "`n"                 # 规则：Sort-Object 默认排序（不去重），LF 连接
$sha = [System.Security.Cryptography.SHA256]::Create()
[System.BitConverter]::ToString($sha.ComputeHash([System.Text.Encoding]::UTF8.GetBytes($joined))) -replace '-',''
# → 74D9FAF0260A139FF80F02104F1933045153155B3BC296DD138710D64DB066D4
```

**规则要点（逐条固定）**
> **★ 规范命令（2026-09-17 队长书面固定，指南 §6.2「文案指纹法」`:666-667`）**：以**工装**为准 ——
> `powershell -NoProfile -ExecutionPolicy Bypass -File .scratch\bot\numeric-multiset.ps1 -BaseDir "<快照根>" -Mode string -Tag <tag>`，产出 `string-before/after-<tag>.txt`（`<相对路径>\t<字面量原文>`），取路径前缀 `command\RoleCommand.java` 的行 → **36 条**，排序后 `"\`n"` 连接、UTF-8、SHA256 = **`74D9FAF0…66D4`**。
> **规则差异（必须写明，避免日后混用）**：① 工装/规范规则**只保留双引号串**（`"(?:\\.|[^"\\])*"`）；② 下面我列的自拟命令**保留双引号 + 单引号**两类。**在本文件上二者结果相同（36 / `74D9FAF0…`）**，因为 `RoleCommand.java` 的**真实字符字面量 = 0**；但**对含真字符字面量的文件两者会分叉** → 跨文件比对时**一律用规范命令**，本节的自拟命令仅作“同一口径下的第二个独立实现”。
> **⚠️ 已知陷阱（队长实测）**：**不要"先剥字符字面量、再取双引号串"**（两遍法）—— `'(?:\\.|[^'\\])*'` 不校验单字符长度，会把 `"Role '" + roleId + "' not exist!"` 里的 `' + roleId + '` 误吞，得 **35 条 / `00BB2701…`（错值）**。正确做法 = **单遍 alternation**（上面两条命令都是单遍）。

1. **剥注释**：块注释 `(?s)/\*.*?\*/` 与行注释 `//[^\r\n]*` 整体丢弃（与字符串同处一条 alternation，扫描到谁先算谁，故字符串里的 `//` **不会被误剥**）；
2. **保留字面量**：双引号 `"(?:\\.|[^"\\])*"` 与单引号 `'(?:\\.|[^'\\])*'` —— **含两端的引号本身**，**含转义序列原样**（不 unescape）；
3. **匹配顺序**：`[regex]::Matches` 单遍从左到右；`(?s)` 只影响块注释的跨行；
4. **编码**：`ReadAllText`（UTF-8）+ `Encoding.UTF8.GetBytes` 计算哈希；
5. **排序**：`Sort-Object` **默认排序、不去重**（保留重复计数 = 多重集）；
6. **连接**：`-join "`n"`（单个 LF，非 CRLF）；
7. **指纹**：拼接串的 SHA256，十六进制**去连字符、大写**；
8. **范围**：**单文件**（本判据只对 `RoleCommand.java` 用；全树字符串比对见 §5.6 的 205→218 口径，同样是 1–7 的规则、只是遍历整树并带相对路径列）。

**判据（⑤ 落地后照此写）**：① `RoleCommand.java` **前后 SHA256**（必然变化，非判据）；② 按上面命令复算的**条数 = 36** 且**指纹 = `74D9FAF0…66D4` 不变**；③ `" has no role!"` **两处都在**（`:108` / `:124`）；④ 结论 = "玩家可见回执串零改动"。
