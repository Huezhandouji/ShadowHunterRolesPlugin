================================================================================
协同规范 · **起服 / 取证 / 停机**（团队级可复用；本文件本身即"物证「协同规范」小节"的落点）
—— 立规来源：2026-09-18 的两起真实事故 + 三条仪器陷阱（均已入台账）
—— 适用：任何需要独占 `runServer`（25566）做 Mode B / 探针取证的成员
================================================================================

§0 一句话
--------------------------------------------------------------------------------
**端口空闲 ≠ 对方取证窗口已结束。** 起服方必须**等停机方明确广播"已释放（物证已落）"**；
停机方必须**在服务器仍在线时就冻结日志**（`Done` + 空闲点 → `Copy-Item` → **然后才** `job_kill`）。
两条一起，才消除"停机与复制之间的竞态窗口" + "后继起服覆盖他人证据"这两个缺口。

§1 起服方（谁要起服，谁执行）
--------------------------------------------------------------------------------
[1.1] **起服前广播**：说明预计占用时长、证据用**新文件名**、并声明"**你若正在取证请回我一句，我等你**"。
[1.2] **窗口三路核查**（缺一不可）：
      ① `TcpClient.Connect('127.0.0.1',25566)` 应**失败**；
      ② `netstat -ano | Select-String ":25566"` 应**无 LISTENING**（仅 `TIME_WAIT` 残影可接受）；
      ③ `Get-Process java` 的**进程数与启动时间**应看不出"最近起过一个服务器"（例如只剩 19:01 的 Gradle daemon）。
[1.3] **不得把"端口空闲"当作放行** ✗：**等停机方的"已释放（物证已落）"广播** ✓。
      （依据：`026915a` 记录的事故 —— 停机方 20:18:0x 停服、我 20:18:05 起服，`runServer` **立刻重写 `run/logs/latest.log`**，
        使对方"停机后复制日志"的取证窗口被覆盖 ⇒ 那一轮集合差结论**只能作废并如实声明**。）

§2 停机方（谁停服，谁执行；**顺序不可颠倒**）
--------------------------------------------------------------------------------
[2.1] **先冻结，后停机（"双点冻结"）** ✓ —— 由 `eng-验证` 精化、`eng-平台` 采纳（2026-09-18）：
      ① **主冻结（权威、抗并发）**：在 Mode B 的 `Done` + 空闲点、**服务器仍在线时**执行
         `Copy-Item run\logs\latest.log → debug-logs\测试记录\<本批名>.log`，并**当场**记录 `长度 / mtime / SHA256`。
         ⇒ 此后任何后继起服都**污染不到它** ✓（本团队三代证据实测有效）。
      ② **补冻结（尽力而为，不得喧宾夺主）**：停机后**再尝试**复制一份，用于捕获"空闲点 → 停机之间"可能出现的行
         （例如延迟初始化后抛出的异常）。**若该副本已被后来的起服覆盖 ⇒ 一律以主冻结为准**，并在物证里
         **如实标注"补冻结失败"** ✗ —— **绝不**把补冻结当必需，也**绝不**用补冻结去覆盖主冻结 ✓。
      ③ **记录要求（可自证）**：物证里必须写明**主冻结的时刻 + 该冻结件的身份**，并附一句**可核事实**：
         **"冻结件早于停机/端口释放"**（例："在服务器仍在线时冻结，随后才 `job_kill`"）✓ ——
         读者据此可自行验证顺序，不会再像 20:18 那起事故一样把"端口已空闲"误读为"对方取证已完成" ✗。
[2.2] **只 `job_kill` + 等待** ✓：不对 java 进程动手；等作业终结。
[2.3] **停服三路互证**（判据）：
      ① `TcpClient.Connect` **失败**；② `[System.IO.File]::Open('run\logs\latest.log','Open','Read','None')` **成功**（无持有者）；
      ③ `netstat` 中 `25566` **无任何条目**（连 TIME_WAIT 都应清空）；④ `Get-Process java` 只剩常驻 daemon。
[2.4] **广播"已释放（物证已落）"** ✓ —— 这一句才是放行信号 ✓。

§3 取证与制品身份（与 §2 配套）
--------------------------------------------------------------------------------
[3.1] **证据必须晚于其制品**（F1）：`jar mtime < log mtime < 物证 mtime`，且**物证内写明本代 jar 身份**（自证绑定，不止靠 mtime）。
[3.2] **jar 的 SHA256 不是"同一份代码"的稳定指纹** ✗：`jar` 记录的 `.class` 时间戳与 `LineNumberTable` 行号会随**重编译**变化
      （实测：同一平台层代码出现 `A74A5747…` / `CD4FD3B2…` / `CDAA4F63…` 三份不同 SHA，而 `javap -c -p` 反汇编 **79/79 行全等**）。
      ⇒ 判"同代码"用**反汇编**或**源码非注释内容**；判"制品身份"才用 jar SHA + mtime 自证链。
[3.3] **改注释的零行为变化**可用两条机械证明（本团队已用过三次）：
      ① 剥块注释 + 行注释 → 逐行 `Trim()` → 丢空行 → 与 HEAD 版**整串逐字比较** = True（**非注释行改动 = 0**）；
      ② 受控 javac A/B：同一编译器编译新旧源码 ⇒ `.class` 的 `javap -c -p` 反汇编**相同**（差异只允许出现在 `LineNumberTable`）。
[3.4] **★ 重建的时机纪律（由 `eng-验证` 提出、我采纳）** ✗：**"删除 jar + 重建"只允许发生在一代证据【尚未取证】之前** ✓；
      **早已冻结证据的代次上绝不可再跑重建** ✗ —— 重建会改该 jar 的 **mtime** ⇒ 把 F1 链 `jar 20:58:55 < log 20:59:50 < 说明` 变成
      "**新 jar mtime > log mtime**"的自相矛盾 ✗（字节可能相同，链却断了 ✗）。
      若确要验证"重建后逐字节相同" ✓ ⇒ **在 `build/` 的副本上做删除+重建比对**（或先复制 jar 到临时目录），
      **工作树制品零接触** ✓ —— 既不破坏 F1 链、又能得到 `identical=True` 的证据 ✓。
      （我早前的 t53/t59 重建之所以合法，是因为那时**该代证据尚未冻结** ✓；顺序永远是"**先定源 → 重建 → 起服 → 停机前冻结 → 归档**" ✓。）

§4 事后补记（post-hoc）的硬约束
--------------------------------------------------------------------------------
若原始日志已被覆盖/不可再取，必须在**文件名与文首双标注**："**事后补记（post-hoc）、内容为当轮逐字转抄、非可二次读取的原始物证**" ✗
—— **不得**冒充原始物证 ✓（本轮我有一条会话 1 的控制台堆栈就是按此标注的 ✓）。

§5 仪器口径（三连 + 第 4/5/6 族）
--------------------------------------------------------------------------------
| # | 陷阱 | 纪律 |
|---|---|---|
| 1 | `Get-NetTCPConnection -State Listen` **在服务器确在监听时也可能返回 0** ✗ | 停服判定用 **TCP connect + `latest.log` 独占打开 + netstat** 三路互证 ✓ |
| 2 | 行数口径：按 `\r?\n` 切分会**多算文件尾 1 个空元素** ✗ | 行数 = **换行符计数**（`read` 工具 / `Get-Content` 一致）✓ |
| 3 | `Get-Content … \| Select-Object -Skip N` 对含 CJK 的 UTF-8 无 BOM 文件会**静默行号漂移**（取到别的方法体却不报错 = 假数据）✗ | 行号定位一律用 **`git grep -n`（可带 `-A`）** 或 **`read` 工具** ✓ |
| 4 | **git 路径引用**：`git ls-files` 默认对非 ASCII 路径输出**外层双引号 + 八进制转义** ⇒ 直接喂 `Test-Path` 报 `Illegal characters in path` ✗ | 非 ASCII 路径一律 `-LiteralPath` ✓；或 `git -c core.quotepath=false ls-files` / `git ls-files -z` ✓ |
| 5 | **工具不存在 ⇒ 空输出比较 = 假 `True`** ✗（`javap` 不在 `PATH`、`JAVA_HOME` 未设时，两侧都得到空串 ⇒ 任何"逐字相同"判定都会**假通过**） | 任何"两侧比较"必须**先断言工具可用且输出非空** ✓（例：`Get-Command javap` + `$a.Count -gt 0 -and $b.Count -gt 0` 再比较）；比较类结论**必须打印两侧行数** ✗ —— 由 `eng-验证` 在独立复现 class 级等价时实测踩到并**自曝作废重做** ✓ |
| 6 | **格式导致误读**：登记册里 `key =` 与**值分两行**时，按"`key = value` 同行"解析会**把上一条的值配给本条** ✗（实测于 `回滚快照/jars/MANIFEST.txt` 第二条登记） | 机器可解析的登记一律 **一行一值** ✓；人读的续行块必须显式标注"续行" ✗ |

§7 使用方式
--------------------------------------------------------------------------------
后续任何卡片的**物证**只需引用本文件：`debug-logs/测试记录/协同规范-起服停机取证.txt`（并把本卡实际执行到的行（§1.2/§2.1/§2.3/§2.4）逐条打勾说明 ✓）。
[7.1] **引用纪律（引用证据/制品/规范时必须三件齐）** ✓：**① 权威路径**（例：`回滚快照/jars/<规范命名>.jar` —— **不要**引用已撤的临时副本路径 ✗）·
      **② 引用当时的 rev/身份**（本规范自身也要带 rev：`≤本次提交后的 SHA256`）；**③ "按测量时刻读"** ✓ ——
      报文/消息里的历史引文**只是那一刻的读数**，不代表当前值 ✗（已三次出现"引了更新前那一版"的错位 ✓）。
[7.2] **引用前先现算一次（`eng-验证` 的实践，我采纳）** ✓：对要引用的**路径**做 `Test-Path`、对**跟踪态**做 `git ls-files --error-unmatch`，
      **再**引用 ✓ —— "引身份/路径"与"按测量时刻读"这两条必须**一起**用才不互相拆台 ✗（否则会按一份**已撤或未跟踪**的路径去执行 ✗）。
