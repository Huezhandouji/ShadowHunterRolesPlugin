## 1. 新增一个技能（Skill）

### 1.1 文件放哪里
`src/main/java/com/shadowHunterRolesPlugin/roleComponent/<角色包>/skill/<名字>Skill.java`
（例：`roleComponent/meiqiHezi/skill/`、`roleComponent/red/`；**同角色包内**才允许互相 `getComponent`，跨角色引用是设计错误 —— `docs/组件系统设计-Unity风格.md:326`）

### 1.2 骨架 A：**当前生效**的写法（旧回调）

```java
package com.shadowHunterRolesPlugin.roleComponent.meiqiHezi.skill;

import com.shadowHunterRolesPlugin.core.DamageUtil;
import com.shadowHunterRolesPlugin.core.RoleInstance;
import com.shadowHunterRolesPlugin.core.Skill;
import net.kyori.adventure.text.Component;
import org.bukkit.Material;
import org.bukkit.entity.Player;

/** 示例技能：3 格内敌人吃 6 点物理伤害，自己回 2 点生命。 */
public class MeiqiheziSampleSkill extends Skill {

    private static final int COOLDOWN_TICKS = 100;   // 5 秒；必须与构造器第 4 个实参保持一致
    private static final int ENERGY_COST = 10;
    private static final double RADIUS = 3;
    private static final double DAMAGE = 6;
    private static final double HEAL = 2;

    public MeiqiheziSampleSkill() {
        super("meiqihezi_skill_sample",                 // id：角色内跨类型唯一（见 §5.2）
              Component.text("示例技能"),                 // 显示名
              Component.text("3 格内敌人受伤，自身回血"),  // 描述
              COOLDOWN_TICKS, ENERGY_COST, Material.PAPER);
    }

    @Override
    public void onRightClick(Player caster, RoleInstance instance) {
        if (instance.getCurrentEnergy() < getEnergyCost()) return;   // 能量门槛：不足则直接 return
        if (!instance.getBuffManager().canCastSkill()) return;       // 沉默/眩晕门槛

        instance.decreaseEnergy(getEnergyCost());                    // 扣能量
        instance.startSkillCooldown(getId(), getCooldownTicks());    // 自己启冷却（旧路径由组件负责）

        for (Player victim : caster.getLocation().getNearbyPlayers(RADIUS)) {
            if (!instance.isHostileTo(victim)) continue;             // 阵营判定（未选角色也算敌人）
            victim.setNoDamageTicks(0);
            DamageUtil.dealtPhysicalDamage(victim, caster, DAMAGE);  // 物理伤害；真伤用 dealtTrueDamage
        }
        instance.heal(HEAL);                                         // clamp 到最大生命
    }
}
```
可用入口一览（都在 `core/RoleInstance.java`，行号见该文件）：能量 `getCurrentEnergy/decreaseEnergy/increaseEnergy`、SanTE `getCurrentSanTE/increaseSanTE/decreaseSanTE/setCurrentSanTE/getMaxSanTE`、生命 `heal/setCurrentHealth/getMaxHealth`、阵营 `isHostileTo(Player)/getFaction`、冷却 `isSkillReady/startSkillCooldown/getRemainingSkillCooldownTicks`、buff `getBuffManager()`、上下文 `setContext/getContext`（**仅过渡期**，设计要删，见 §7）。伤害原语在 `core/DamageUtil.java:31-90`。

### 1.3 骨架 B：阶段 4 的新管道写法（**现在还不生效**）

```java
    public MeiqiheziSampleSkill() {
        super("meiqihezi_skill_sample", Component.text("示例技能"), Component.text("…"),
              COOLDOWN_TICKS, ENERGY_COST, Material.PAPER);
        markMigrated();                                              // 只由迁移批次调用（见下）
    }

    @Override
    public CastResult onCast(CastSignal signal) {                    // core.dispatch.CastSignal / CastResult
        if (!svc().buffs().canCastSkill()) return CastResult.NO_COOLDOWN;        // 今天是"直接 return、不启冷却"
        if (!svc().energy().tryConsume(ENERGY_COST)) return CastResult.REJECTED_NO_ENERGY;

        Player caster = svc().self().player();                       // 每次现取，不存字段
        for (Player victim : caster.getLocation().getNearbyPlayers(RADIUS)) {
            if (!svc().factions().isHostile(victim)) continue;
            svc().damage().physicalDamage(victim, caster, DAMAGE);
        }
        svc().vitals().heal(HEAL);
        return CastResult.CAST;                                      // 冷却由框架按 getCooldownTicks() 启动
    }
```
- 端口白名单见 `docs/插件文档/架构与组件模型.md` §2；**一个端口方法都不许多用**。
- `markMigrated()` 是迁移批次的标记（`roleComponent/ActiveComponent.java:44-52`），**不要**顺手给你新写的组件打上 —— 打了它就会在开关翻起后被送进新管道，而新管道的运行期等价需要单独验证。
- ⚠️ 现在**两套都写会重叠**：若同时保留 `onRightClick` 与 `onCast`，则开关 `false` 时走旧的、翻起后走新的 —— 这是迁移期的既定形态（B① 就是删旧留新），新组件请**先按 A 写**，等阶段 4 收尾块 T 翻开关后再统一改。

### 1.4 需要"延时/周期任务"的技能
- 现有约定：字段持有句柄（`platform/Task`），在 `stop(Player, RoleInstance)` 里取消（`implements LifecycleAware`）。样板：`MeiqiheziCircleSlashSkill.java:26`（`private Task castTask`）+ `:96-102`（`stop` 取消）。
- 取调度器：`instance.rolesContext().scheduler().runLater/runRepeating(...)`（`platform/Scheduler.java:7-13`）。**不要**直接 `Bukkit.getScheduler()`（全仓唯一允许的点是 `platform/BukkitSchedulerAdapter.java:17-29`）。
- 任务体里要做"实例已失效"守卫：`if (!instance.isValid()) { task.cancel(); return; }`（`MeiqiheziCircleSlashSkill.java:62-65`）。
- 新侧写法（终态）：`svc().timers().runLater(...)` / `runRepeating(...)`，框架会在 `stop()` 返回后兜底取消（`core/ports/TimerPort.java:5-19`）。

### 1.5 不要覆写渲染
组件的 `createIconItem` / `getDisplayName(RoleInstance)` 属于**待删除**的旧渲染（设计 §4.3 明确把它们移出 `ActiveComponent`）。新组件**不要**再写这两处覆写；只有两个历史组件（`MeiqiheziBloodySlashSkill`、`MeiqiheziCircleSlashSkill`）还有，属 T 块清理对象。

## 2. 新增一个被动（Passive）

文件：`roleComponent/<角色包>/<名字>Passive.java`（现有被动在 `roleComponent/` 根与 `roleComponent/red/`、`roleComponent/meiqiHezi/passive/` 三处，按角色归属放置）。

```java
package com.shadowHunterRolesPlugin.roleComponent.red;

import com.shadowHunterRolesPlugin.core.PassiveSkill;
import com.shadowHunterRolesPlugin.core.RoleComponentAware.LifecycleAware;
import com.shadowHunterRolesPlugin.core.RoleComponentAware.UpdateAware;
import com.shadowHunterRolesPlugin.core.RoleInstance;
import net.kyori.adventure.text.Component;
import org.bukkit.entity.Player;

/** 示例被动：开始生效时打一条标记，每 tick 做点小事。 */
public class RedSamplePassive extends PassiveSkill implements LifecycleAware, UpdateAware {

    public RedSamplePassive() {
        super("red_sample_passive", Component.text("示例被动"), Component.text("被动描述"));
    }

    @Override
    public void start(Player player, RoleInstance instance) {
        // 初始化数据 / 发放装备 / 登记资源。注意：这里是被动唯一"开始生效"的时机。
    }

    @Override
    public void stop(Player player, RoleInstance instance) {
        // 与 start 严格对称：start 里创建的资源必须在这里全部回收或清空。
    }

    @Override
    public void update(Player player, RoleInstance instance) {
        // 20 Hz。禁止阻塞；要改热键栏/能量/SanTE 请走 instance 的对应方法（它们自己会刷新）。
    }

```

要点：
- 被动**不实现** `HotbarItem`/`HotbarActionable` ⇒ 它天然不能被施放（`core/PassiveSkill.java:10-11` 的注释）。
- `LifecycleAware.awake` 是 **default 空方法**（`core/RoleComponentAware/LifecycleAware.java:12`），需要"解析跨组件依赖并缓存"时才覆写；`awake` 必须幂等、不得改玩家可见状态（`:10-11`）。
- 想在 SanTE 归零时做点什么：`implements SanTEChangeAware`，覆写 `onSanTEChange(Player, RoleInstance, int pre, int new)`（样板 `roleComponent/DefaultSanTEZeroPunishment.java:31-118`）。
- **有 `start` 必有对称 `stop`** —— 本工程已经因为"只发不收"踩过坑（装备被动 stop 回收是阶段 0 的收口项，见 `docs/阶段0-交付小结.md`）。

## 3. 新增一个主武器（MainWeapon）

文件：`roleComponent/<角色包>/mainWeapon/<名字>MainWeapon.java`。

```java
package com.shadowHunterRolesPlugin.roleComponent.red;

import com.shadowHunterRolesPlugin.core.DamageUtil;
import com.shadowHunterRolesPlugin.core.MainWeapon;
import com.shadowHunterRolesPlugin.core.RoleInstance;
import net.kyori.adventure.text.Component;
import org.bukkit.Material;
import org.bukkit.entity.Player;

/** 示例主武器：攻击造成 8 点物理伤害并击退 1。 */
public class RedSampleMainWeapon extends MainWeapon {

    private static final int COOLDOWN_TICKS = 100;   // 5 秒

    public RedSampleMainWeapon() {
        // 注意参数顺序：icon 在 cooldown 之前（与 Skill 相反，且这个顺序被冻结）
        super("red_mainWeapon_sample", Component.text("示例之刃"),
              Component.text("攻击造成物理伤害"), Material.IRON_SWORD, COOLDOWN_TICKS);
    }

    @Override
    public void onAttack(Player attacker, Player victim, RoleInstance instance) {
        DamageUtil.dealtPhysicalDamage(victim, attacker, 8, 1);      // 4 参重载 = 物理伤害 + 击退
        instance.startMainWeaponCooldown(getId(), getCooldownTicks());
    }
}
```

要点：
- 主武器**只受眩晕限制**（不受沉默），由 `BuffManager.canUseMainWeapon()` 决定（`manager/BuffManager.java:90-92`）。
- 攻击入口在 `listener/MainWeaponListener.java:29-60`：**框架无条件先启动冷却**，然后依次调用 `weapon.onAttack(...)` 与 `weapon.onLeftClick(...)`；所以组件里的那句 `startMainWeaponCooldown` 是"重复写同一个键"（保留是为了与既有代码一致）。
- 左键/右键/`Q` 三个入口分别在 `MainWeaponListener.java:63-113` 与 `:116-148`，转发到 `RoleInstance.castMainWeaponLeftClick/RightClick/QDrop`。
- 主武器**没有 `energyCost`**：`MainWeapon` 构造器恒把 energyCost 传 `0`（`core/MainWeapon.java:33-35`），这样武器图标不会多出一个今天不存在的 `ENERGY LACK` 状态。

## 4. 新增一个角色（Role）

角色是**代码定义的**（没有 `roles.yml`，那是**未排期的阶段 6.1**，见 §8），唯一装配点是 `registry/RoleLoader.java:52-57` 的 `defaultDefinitions()`。

### 4.1 步骤
1. 实现该角色的组件类（§1–§3）；
2. 在 `RoleLoader` 里加一个 `private static Role.Builder <id>Builder()`，照 `meiqiheziBuilder()`（`:90-116`）或 `redBuilder()`（`:118-142`）的样式写；
3. 在 `defaultDefinitions()` 的 `List.of(...)` 里加一条 `new Definition("<id>", RoleLoader::<id>Builder)`（`:53-56`）；
4. 构建 + 起服 + 在游戏里 `/role set <id>` 验证（§6）。

### 4.2 抄一份最小模板

### 4.3 硬规则（违反会在装配期抛异常、该角色**不会被注册**）
| 规则 | 事实 | 出处 |
|---|---|---|
| 组件 id **跨类型唯一** | 技能/被动/武器共用一个命名空间，重复即抛 `IllegalArgumentException(type + " already registered: " + id)` | `core/Role.java:232-237`（O-10 修复） |
| 槽位只能是 `0..8`，且不可冲突 | 非法槽位/冲突都抛异常，**不再"告警 + 覆盖"** | `core/Role.java:240-247`（O-12 / 裁决 1） |
| 角色 id 非空 | `new Role.Builder(id)` 里校验 | `core/Role.java:118-123` |
| 数值必须合法 | maxHP > 0、baseATK/maxEnergy/maxSanTE ≥ 0 | `core/Role.java:141-171` |
| 装配失败按角色隔离 | 某个角色装配抛异常 → 记 `SEVERE`、**跳过该角色**，其余照常注册；不让异常冒泡成 `ExceptionInInitializerError` | `registry/RoleLoader.java:68-88` |
| 装配顺序 = 注册顺序 | 同一类型内部按 `add*()` 的调用顺序（`LinkedHashMap`） | `core/Role.java:111-114`、设计 `:501-521` |

### 4.4 一个容易踩的坑：**组件构造器会被执行多次**
`Role.Builder.addSkill/addPassive/addMainWeapon` 为了拿 id 与做校验，会**先实例化一次**（`Skill temp = supplier.get();`，`core/Role.java:179`、`:196`、`:210`），真正装配时 `Role.createComponent` 会**再实例化一次**（`core/Role.java:91-93`，唯一创建点）。
⇒ **组件构造器必须是纯的**：不要在构造器里改玩家状态、发起任务、写静态状态。要"开始生效"请写在 `start`。

## 5. 注册与自检

### 5.1 组件不需要注册到别处

### 5.2 新增角色/组件后的自检清单

| # | 检查 | 怎么做 |
|---|---|---|
| 1 | 编译 | `.\gradlew build -x copyPluginJar --console=plain`；看 `BUILD SUCCESSFUL` + 最新 `.class` mtime |
| 2 | 装配无异常 | 起服看控制台；若出现 `Role 'xxx' failed assembly validation and was NOT registered` 就是 §4.3 的校验拦下了（`RoleLoader.java:82-84`） |
| 3 | 改装配代码没把别的角色带崩 | 起服应看到 `ShadowHunter Character System enabled.`（`ShadowHunterRolesPlugin.java:87`） |
| 4 | 角色可选 | 进游戏 `/role set <id>`；回显 `Your role has been set: <id>` |
| 5 | 热键栏正确 | 0 号位主武器、1–3 号位技能；图标为角色 `.icon(...)` 或组件图标（`RoleInstance.updateHotbar`） |
| 6 | 施放正确 | 左/右/`Q` 各试一次；冷却是否按声明值启动（技能名带 `x.xs` 说明用的是 `getCooldownTicks()`） |

## 7. 禁忌清单（照抄设计 §12 的纪律，逐条可 grep）

1. **不 import 插件主类、不调 `ShadowHunterRolesPlugin.getInstance()`**（设计 `:695`）。当前 `getInstance()` 已**零调用**（`docs/插件文档/架构与组件模型.md` §6.3）。
2. **不直接 `Bukkit.getScheduler()` / 不写裸 `BukkitRunnable` 作为唯一调度手段** —— 走 `instance.rolesContext().scheduler()`（过渡期）或 `svc().timers()`（终态）。
3. **有 `start` 必有对称 `stop`**；`stop` 里把缓存的组件引用置空。
4. **`Player` 不得存进长生命周期字段或长任务闭包** —— 只能存 `UUID`，或每次 `svc().self().player()` 实时取（设计 `:466-469`）。
5. **数值提成类顶部命名常量**（几何/特效参数除外）：抄 `RedSanctifiedBladeMainWeapon.java:19`、`RedBleedPassive.java:29-41` 的做法。
6. **组件不碰热键栏**：不造 `ItemStack`、不请求刷新（`markDirty()` 是框架内部 API，设计 `:700`）。
7. **不要用 `instanceof ActiveComponent` 当"是否已迁移"的判据** —— 10 个组件改基后都会 `instanceof`；唯一判据是 `markMigrated()`（`roleComponent/ActiveComponent.java:24-31`）。
