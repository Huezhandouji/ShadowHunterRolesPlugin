# 02 · 面向对象基础

## 这份文档只讲六个词

读这个仓库的代码，你只需要补六个词：**类 · 对象 · 方法 · 字段 · 继承 · 接口**。本文只讲这六个，别的一概不讲 —— 你现在不需要它们。

每个词都分三步：先打比方 → 再给一个**本仓库真实文件里的最短例子** → 最后给一条能亲手跑的命令。

> 想亲眼看到例子里的那一行：把命令粘进 PowerShell，在仓库根目录执行。`--` 后面的 `src/main/java` 表示"只在这个文件夹里找"。
>
> 代码里还会有一些像 `public`、`private`、`final`、`void` 这样的短词 —— 它们是 Java 的固定写法（写着"这东西谁能用、能不能改、有没有返回值"），**你现在不用管它们为什么这么写，照着抄就行**。下面遇到时不会再逐个解释。

## 一、类（class）

**打比方**：你写过函数 `计算伤害(目标, 数值)`。**类是一张"表格模板 + 造物机"的合体**：它既说明"这种东西内部有哪些变量、能调用哪些函数"，又能照着自己造出一个一个具体的这种东西。

**真实例子**（`src/main/java/com/shadowHunterRolesPlugin/roleComponent/RoleComponent.java`）：

```java
public abstract class RoleComponent {
```

（开头的 `abstract` 是固定写法，意思是"这张模板不能直接拿来造东西，只能被别的类继承"。）

**命令**：

```powershell
git grep -n "public abstract class RoleComponent" -- src/main/java
```

**写角色时它在哪里**：你要写的技能本身就是一个类，文件名与类名一致。

## 二、对象（object）

**打比方**：类 = 表格模板，对象 = 照模板填出来的一张具体的表。你写循环 `for 每个物品 in 列表`，列表里存的每一项就是一个对象。

**真实例子**（`src/main/java/com/shadowHunterRolesPlugin/core/hotbar/HotbarRenderer.java`）：

```java
ItemStack stack = new ItemStack(material);
```

`new` 这个动作就是"照模板造一个出来"，`stack` 是用来接住它的变量。

**命令**：

```powershell
git grep -n "new ItemStack(material)" -- src/main/java
```

**写角色时它在哪里**：你写的技能类，会在玩家选这个角色时被"造"出来一次（造的时候会调用你写的构造函数，见 `03`）。

## 三、方法（method）

**打比方**：方法**就是函数**，唯一的区别是它挂在某个对象（或类）身上，用点号调用 —— `对象.方法(参数)`。你写的 `回血(玩家, 4)` 在这里会写成 `vitals.heal(4)`。

**真实例子**（`roleComponent/RoleComponent.java`）：

```java
public final String getId() {
```

**命令**：

```powershell
git grep -n "public final String getId" -- src/main/java
```

**写角色时它在哪里**：你最常写的那个方法叫 `onCast(...)` —— 玩家按下技能时被调用的函数（见 `03`）。

## 四、字段（field）

**打比方**：字段**就是变量**，只是它不写在函数里面，而是写在类里面，跟着对象一起存在。函数里的局部变量，函数一结束就没了；字段会一直留着。

**真实例子**（`roleComponent/RoleComponent.java`）：

```java
private final String id;
```

每个组件对象都有自己的一份 `id`（比如 `meiqihezi_skill_unconcern`）。

**命令**：

```powershell
git grep -n "private final String id;" -- src/main/java
```

**写角色时它在哪里**：你的技能要有 `id`、显示名、描述、冷却、图标 —— 这些都由你写在构造函数里，框架替你存进字段。

## 五、继承（inheritance）

**打比方**：**继承 = "把别人的定义整个拿过来，再写自己不同的部分"**。你写过一个通用函数 `伤害计算(目标, 数值)`；继承就像新函数默认就拥有它，你只要再补额外步骤。被继承的那份定义俗称**父类**（父 → 子：子从父那里拿东西）。

**真实例子**（`src/main/java/com/shadowHunterRolesPlugin/roleComponent/meiqiHezi/skill/MeiqiheziUnconcernSkill.java`）：

```java
public class MeiqiheziUnconcernSkill extends Skill {
```

读作"`MeiqiheziUnconcernSkill` 是一种 `Skill`（技能）"。因为是技能，它自动就有了技能该有的东西（例如上面那个 `getId()`），自己只要写"这个技能具体干什么"。

**命令**：

```powershell
git grep -n "class MeiqiheziUnconcernSkill" -- src/main/java
```

**写角色时它在哪里**：你的技能要写 `extends Skill`，这样框架才认得它、才会在按键时调用你写的 `onCast(...)`。

## 六、接口（interface）

**打比方**：**接口是一张"必须提供的函数清单"**，只写函数名和参数，不写做法。谁照着它写，谁就必须把这些函数都提供出来。

**真实例子**（`src/main/java/com/shadowHunterRolesPlugin/core/ports/VitalsPort.java`）—— 整个接口只有一行函数：

```java
public interface VitalsPort {
    void heal(double amount);
}
```

**命令**：

```powershell
git grep -n "interface VitalsPort" -- src/main/java
```

**写角色时它在哪里**：你现在**不会直接写接口** —— 框架已经把它实现好了，你只是通过 `svc()` 借用它（`03` 会讲 `svc()`）。认识这个词，只是为了看得懂代码里出现的 `interface`。

## 小结

| 词 | 一句话 | 仓库里的例子 |
|---|---|---|
| 类 | 模板：描述这种东西里有什么、能做什么 | `roleComponent/RoleComponent.java` 的 `public abstract class RoleComponent` |
| 对象 | 照模板造出来的一个具体东西 | `core/hotbar/HotbarRenderer.java` 的 `new ItemStack(material)` |
| 方法 | 就是函数，用点号调用 | `roleComponent/RoleComponent.java` 的 `public final String getId()` |
| 字段 | 写在类里、跟着对象存的变量 | `roleComponent/RoleComponent.java` 的 `private final String id;` |
| 继承 | 把父类的定义拿过来再补充 | `meiqiHezi/skill/MeiqiheziUnconcernSkill.java` 的 `extends Skill` |
| 接口 | 一张"必须提供的函数清单" | `core/ports/VitalsPort.java` 的 `interface VitalsPort` |
