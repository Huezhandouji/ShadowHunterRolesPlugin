## 2. API 形态差异清单（逐条，适配层要吸收的差异）

| # | Bukkit（现状） | GlobalRegionScheduler（目标） | 适配处理 |
|---|---|---|---|
| D1 | `runTask(Plugin,Runnable)` → `BukkitTask` | `execute(Plugin,Runnable)`（**无返回值**）/ `run(Plugin,Consumer<ScheduledTask>)`（**有句柄**） | 取句柄 ⇒ 用 `run(...)`，**不用** `execute`（否则拿不到 `Task` 句柄 ✗）；`execute` 与 `run` 的差别 = **是否有回调句柄**（`run` 把 `ScheduledTask` 交给 Consumer） |
| D2 | 回调类型 `Runnable` | `Consumer<ScheduledTask>` | 适配层内部忽略参数：`task -> runnable.run()` |
| D3 | `BukkitTask.cancel()` → `void` | `ScheduledTask.cancel()` → **`CancelledState`** | **吞掉返回值**（适配层 `public void cancel()` 保持不变 ✓）；`CancelledState` 可用于探针打印 |
| D4 | `isCancelled()` | `isCancelled()` **是 default 方法** | 直接调用 ✓（注意：任何 default 实现的语义要以探针实测为准） |
| D5 | 无 | **`isRepeatingTask()`** / `getExecutionState()` | **新增能力** ⇒ 探针实测并记录；适配层**暂不使用**（接口面不变 ✓） |
| D6 | `runTaskLater` / `runTaskTimer`（period 单位 = tick） | `runDelayed(...,long delay)` / `runAtFixedRate(...,long initialDelay,long period)`（单位 = tick ✓） | 单位与**实测触发**均等价 ✓，但 **`initialDelay <= 0` 的入参校验不同** ✗（Global 抛 `IllegalArgumentException`）⇒ **原判"语义应等价"已被证伪**，改判见 §2.1 |
| D7 | `BukkitScheduler.cancelTasks(Plugin)`（全部取消） | `GlobalRegionScheduler.cancelTasks(Plugin)` | 适配层**不需要**（`RoleInstance.clear()` 按句柄取消 ✓）；探针可打印 |
| D8 | `BukkitScheduler.isQueued/isCurrentlyRunning` 等 | 无对应 | 适配层未使用 ✓（现算 F3 佐证） |

## 3. 适配层设计（目标：接口面不变 ⇒ 调用方零改动）

1. **`Scheduler` 接口保持不变** ✓（3 方法、签名不动 ⇒ 全仓调用方零改动；这是本项的硬约束）。
2. **`Task` 接口保持不变** ✓（`cancel()` 仍 `void`、`isCancelled()` 仍 `boolean`）⇒ `ScheduledTask` 的 `CancelledState` 在实现类里**吞掉** ✓。
3. **实现替换（**已落地** `cba1488`，不再是"下一张卡"）**：`BukkitSchedulerAdapter` 内部三处调用已改为：
   - `run` → `getGlobalRegionScheduler().run(plugin, st -> task.run())`
   - `runLater` → `runDelayed(plugin, st -> task.run(), delayTicks)`
   - `runRepeating` → `runAtFixedRate(plugin, st -> task.run(), Math.max(1L, initialDelayTicks), periodTicks)`
   其中 `wrap(...)` 返回一个 `Task` 实现（持 `ScheduledTask`，`cancel()` 调 `ScheduledTask.cancel()` 并**吞掉 `CancelledState` 返回值**、`isCancelled()` 转发）。
   **禁项复核**：未用 `execute(Plugin, Runnable)` 替代 `run(...)` ✓（该 API 无句柄 ⇒ 任务无法回收）；**类名未改** ✓；`Scheduler`/`Task` 接口逐字未改 ✓。
4. **是否需要平台探测/开关**：**结论已出（见 §2.1）⇒ 不需要开关** ✓ ——
   - 线程 / 周期 / 延时 / 取消**四项实测全部等价** ⇒ **直接替换**（回滚靠单文件 revert ✓）；
   - 唯一差异是**入参校验**（`initialDelay <= 0`）⇒ 由**适配层归一**吸收；**不**引入"D2 待裁定"、**不**保留 Bukkit 兜底实现。
5. **不做的事** ✗：不引入 `runOnEntity`/`RegionScheduler`（Folia 另行评估，见 §6）；不改 `ComponentServices`/`api/`；不新增 ticker。

## 6. 风险与红线

| 级 | 风险 | 处置 |
|---|---|---|
| **blocker** | 把 `run(...)` 误用为 `execute(...)` ⇒ **拿不到句柄** ⇒ `Task.cancel()` 失效（组件任务无法回收 = 泄漏 + 可能的双触发） | 适配层**只用 `run/runDelayed/runAtFixedRate`** ✓；探针须打印"句柄可用性"证据 |
| **blocker** | 时序不等价（`runAtFixedRate` 的 period 语义 vs `runTaskTimer`） | **由探针实测**"实际触发 tick 间隔"（§2 D6）⇒ 不通过则**不切** ✓ |
| **high** | 取消语义差异（`CancelledState`/`isCancelled()` default 实现） | 探针逐条打印（返回值、`isCancelled()`、`getExecutionState()`、重复 cancel）✓ |
| **high** | 组件定时器（`timers()`）承载副作用（惩罚伤害、流血结算）⇒ 时序变化 = 数值可见变化 | 等价性判据 §4 第 5 行；必要时保留 Bukkit 实现 |
| **medium** | Folia 环境下 `GlobalRegionScheduler` 行为不同 | **本项只做 Global** ✓；`RegionScheduler`/`EntityScheduler` **另行评估** ✓（决策变更登记见 F9） |
| **medium** | 与阶段 5（RoleTicker 合并）抢代码 | 本项**不合并 ticker** ✓；t17 只改刷新源 |
| **low** | 文档仍写"用 `BukkitTask` 包装" | 迁移卡须同步 `platform/Task`/`Scheduler` 的 javadoc（决策变更留痕 ✓） |
| **红线** | `api/` 只增不改 ✓ · `ComponentServices` **10 成员** ✓ · 两事件对外发布不变 ✓ · **冷却语义与既有调度时序一字不改** ✓ | 逐条现算 diff = 0 |

## 7. 探针（本轮交付物二）与"原始输出"归属

- **形态**：扩展现有 op 门控调试入口 ⇒ `/role debug sched …`（**不新增注册路径** ✗、**不在 `onEnable` 做常驻副作用** ✗）。
- **逐条打印**（Adventure `Component`，op 可见）：
  1. `GlobalRegionScheduler.execute` 回调内的 `Thread.currentThread().getName()`；
  2. `run` / `runDelayed` / `runAtFixedRate` 各自的**线程名 + 实际触发 tick**（与 `Bukkit.getCurrentTick()` 比对声明值）；
  3. **对照任务**：同一时刻用 `Bukkit.getScheduler().runTaskTimer(...)` 起一个同周期任务 ⇒ 打印**两者线程名与触发 tick**，回答"是否同一主线程 / 周期是否等价"；
  4. **取消语义**：`ScheduledTask.cancel()` 的**返回值**、随后 `isCancelled()` / `getExecutionState()`、**重复 `cancel()`** 的行为；
  5. **一句话结论**：能否直接把适配器切到 `GlobalRegionScheduler` 且保持零可见差异（能/不能 + 依据）。
- **原始输出归属** ⚠️：本取证环境**无玩家登录** ⇒ 命令类探针**无法自行产生输出** ✗ ⇒ **原始输出（线程名 + tick 值逐条）由用户游戏内 op 执行给出**；本轮我交付的是**探针本体 + 构建/Mode B/物证**，并把"原始输出待用户冒烟"**如实写进报告**（不伪造、不推断 ✓）。
  > 若后续要求"无需玩家即可拿到原始输出"，可选方案 = 增加一个**仅本轮启用、一次性**的 enable 期探测（打印后自删/自取消）—— 但与本项"不在 `onEnable` 做副作用"的约束冲突 ✗ ⇒ **需队长裁定后再做**，本方案不擅自引入。
