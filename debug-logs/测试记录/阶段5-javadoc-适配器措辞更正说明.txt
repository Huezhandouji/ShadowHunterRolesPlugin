§4 ★ 新发现的机制事实：**jar 的 SHA256 不是"语义指纹"**（建议入台账）
--------------------------------------------------------------------------------
[4.1] 现象：本次会话里同一份平台层代码出现过**三份不同 SHA 的 jar** ——
      build E `A74A5747…`（20:26:27）· 他人重建 `CD4FD3B2…`（20:32:52）· 本卡重建 `CDAA4F63…`（20:33:19/20:33:50，两次相同）。
[4.2] 机制（受控实验，本卡实测）：
      · 分别用**同一 javac** 编译 **HEAD 版源码**与**本卡源码**（仅注释不同）⇒
        `.class` = 2768 B / `9ECC39D7…`（HEAD）vs 2768 B / `48F9959D…`（本卡）⇒ **字节不同**；
      · 但 **`javap -c -p` 反汇编逐字相同（79/79 行）** ✓ ⇒ **字节码语义零变化**；
      · 差异定位：`javap -c -p -l` 下有 **20 行不同，全部是 `LineNumberTable` 的行号**（例：`line 37: 0` → `line 38: 4`）
        —— 因为 javadoc 变长 ⇒ 方法体的源码行号整体位移 ⇒ 编译器写入行号表 ⇒ **jar 字节随之变化**。
      · ⇒ 结论：**"改注释不会改变 jar"只在"未触发重编译"时成立**（Gradle 增量编译判定无变化 ⇒ `compileJava UP-TO-DATE` ⇒ jar 逐字节不变）；
        一旦重编译，jar 的 SHA **必然**变化，而**语义未变**。
[4.3] **对 F1 纪律（"证据必须覆盖它自己的制品"）的直接影响**：
      build E 的 Mode B 物证覆盖的制品是 `A74A5747…`；**本卡的 jar 是 `CDAA4F63…`** ⇒ **制品身份不同** ✗
      ⇒ 按 F1 纪律**不得声称**"build E 的运行证据覆盖本制品"。
      **可替代的（更强的）等价证明**：① 非注释行 = 0（§2.2）；② 字节码反汇编逐字相同（§4.2）；③ 仅 1 个源文件改动（§2.4）
      ⇒ **语义零变化**成立；**唯一可能的可观察差异 = 异常栈里打印的行号**（行号表变了）。
[4.4] 建议（供队长/验证者裁定）：**若要"制品身份级"覆盖本 jar**，需补一次 Mode B（约 2–3 分钟；**卡面 inScope 未含新日志名，我不擅自扩围**）。
      或按"语义等价 + 唯一差异 = 栈行号"接受；由 t56（迁移批独立验证）按其口径决定更合适。
[4.5] 由此得出可复用口诀（建议入台账）：**"同代码"要用 *反汇编/源码非注释内容* 判定，不要用 jar SHA 判定** ——
      jar SHA 受 `.class` mtime 与 `LineNumberTable` 影响，**重启构建即变**。
