## §3 「精简」的可操作定义（用户原话要求）

### 3.1 同义重复句的合并规则（3 条）

1. **`⇒` 后的解释与前半句重复** ⇒ 删后半（保留前半的**事实**），或反之；**禁止**两处都留。
   例（模板）：`X 未命中 ⇒ 不做任何事` + 下一行 `未命中 ⇒ 无事发生` ⇒ 合并为一行。
2. **同一段里"括号补语 + 正文"表达同一件事** ⇒ 保留**更具体**的那一处（通常是括号里的**判据/例证**）。
3. **"旧形态…现改为…"** 的成对陈述：若"旧形态"已无下文依赖 ⇒ 可收缩为「现形态 + 一句为什么」；**不得**删掉"为什么"（那是判据）。

### 3.2 冗长排比 / 自问自答的收缩规则（3 条）

1. `为什么…？因为…` ⇒ 收缩为「**因为…（所以…）**」一句；**问句可删，因果不可删**。
2. 三连排比（`A ✓ B ✓ C ✓`）⇒ 若三者同类，改为「A / B / C 三点逐字保留」；**逐条语义保留**。
3. 箭头密集行（≥3 个，18 行）⇒ 拆句或改 `<ol>`；**顺序语义保留**（顺序是判据，例 `判脏 ⇒ 写 ⇒ 清脏`）。

### 3.3 删除上限与「删了就丢信息」清单

★ **删除上限（硬规矩）**：**每件注释行数不得低于其承载的技术信息下限** —— 具体判据 = 下列**五类内容在删改后必须仍可被 grep 到**（每件结卡前逐类跑，命中数**不得下降**）：

| 类别 | 模式（不得减少） |
|---|---|
| ① 判据原文 / 口径声明 | `唯一|不得|禁止|必须|逐字|等价|不变量` |
| ② 覆写者须知 | `buildItem|dependsOnLiveState|覆写` |
| ③ 文件身份与真实路径 | `core/…|roleComponent/…|frameworkLevel/…`（★ 且路径必须**实测存在**，见 §2.1 的死串教训） |

| ⑤ 例外申报 | `例外|已裁定|不属残余|如实申报|已知代价` |
