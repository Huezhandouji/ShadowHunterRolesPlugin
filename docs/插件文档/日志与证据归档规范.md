# 日志与证据归档规范（debug-logs/ vs 仓库内的冻结证据）

> **时点**：2026-09-17（目录调整后）。本文中的**枚举数、字节数、mtime、SHA256 都是写作时点的现算读数**；引用时**一律重算**，不要照抄。
> **一句话**：**调试日志放 `debug-logs/`（不入库、不引用）；一旦某段日志被写进交付小结/验证报告/评审报告当作"结论依据"，它就升级为"冻结证据"，必须放到 `debug-logs/测试记录/` 并正常 `git add` 入库。**
> **目录**：**冻结日志、验证/评审报告、测试与演练记录、agent 过程记录统一位于 `debug-logs/测试记录/`**；**agent 间交流的信息记录在该目录下，不得写进项目介绍文档**（`debug-logs/README-文档索引.md` / `docs/插件文档/README.md` 只描述项目本身）。

## 1. 二分法（唯一判据）

| 类别 | 位置 | 是否入库 | 引用方式 | 例子 |
|---|---|---|---|---|
| **调试日志**（可重复生成、非结论） | `debug-logs/` | ❌ **被忽略** | **不引用**；只在排查时自己看 | `debug-logs/baseline-runserver-B0a-2026-09-17-0040.log` |
| **冻结证据**（一次性、结论依据） | **`debug-logs/测试记录/`**（含起服日志与构建日志；同目录还会放验证/评审报告、测试与演练记录、过程记录） | ✅ **必须入库**；该目录**已加否定规则**（`!debug-logs/测试记录/**/*.log`）⇒ **正常 `git add` 即可，无需 `-f`** | **必须带 SHA256 + 时点**；身份一律现算 | `debug-logs/测试记录/阶段4-起服日志-B0a.log` |

来源：`debug-logs/README.md:6-14`（该 README 是本规范的**原始出处**，本文件是它的展开版）。

**判定口径**（原文，`debug-logs/README.md:13`，位置名已按新布局更新）：

> 一段日志若被写进交付小结/验证报告/评审报告当作"结论依据"，它就升级为**冻结证据**，必须移到 `debug-logs/测试记录/` 并入库；其余一律留在本目录，不入库。

## 2. 规则在仓库里怎么落地（`.gitignore` 的两条 + 一条通用）

| 规则 | 行 | 效果 |
|---|---|---|
| `*.log` | `.gitignore` | **所有** `*.log` **默认**都被忽略 —— 所以**放在其它位置**的日志想入库必须 `git add -f` |
| **`!debug-logs/测试记录/**/*.log`** | `.gitignore`（否定规则） | **例外**：`debug-logs/测试记录/` 下的日志**不被忽略** ⇒ **正常 `git add` 即可**（冻结证据的默认落点） |
| `debug-logs/*` | `.gitignore` | 调试日志目录的内容全部忽略 |
| `!debug-logs/README.md` | `.gitignore` | **例外**：该目录的 README 要入库（它就是"二分法"的说明书） |

复算：
```powershell
cd ShadowHunterRoles
git check-ignore -v debug-logs/测试记录/阶段4-起服日志-B0a.log   # 期望：无输出（= 不被忽略，正常 add）
git check-ignore -v docs/tmp-probe.log                    # 期望命中 `*.log`（其它位置仍被忽略）
git check-ignore -v debug-logs/README.md                  # 期望：无输出
git check-ignore -v debug-logs/t6-build.log               # 期望命中 `debug-logs/*`
```

**副作用（事实）**：早期有两份构建日志是 UTF-16LE 编码，被工具判为 binary 无法直接阅读，于是把**可读副本**另存成了 `.txt`（`debug-logs/测试记录/t2-build-x.utf8.txt`、`debug-logs/测试记录/t2-build.utf8.txt`）；`.txt` 不在忽略列表里，因此**天然可入库**（出处：`debug-logs/阶段0-交付小结.md` §11.2 构建日志留存）。

## 4. 操作手册：如何新归档一份"起服证据"

> 适用场景：跑完一次 `runServer`、拿到控制台输出，准备把它作为某个批次/阶段的合格线证据。

**步骤 0（起服前）**：若还需要"改动前基线"，先把 `run/logs/latest.log` 复制走 —— 它会被下一次起服**轮转覆盖**（工程口径：`debug-logs/最终重构指南.md` §6.3 构建与起服验收（锚点留存） 明写"必须在下次起服前留存副本"）。
```powershell
Copy-Item run/logs/latest.log "docs/阶段N-起服锚点-<块名>.log"   # 或先放 debug-logs/ 过渡
```

**步骤 1**：起服（写清**模式**）。本项目稳态用 **Mode B**（不装 `SHDFGamePlugin`）：
```powershell
.\gradlew runServer        # 端口见 run/server.properties:61（当前 25566）
```
合格线（`debug-logs/最终重构指南.md` §6.3 构建与起服验收）：
- Mode B = **三行 + 无新增 ERROR/Exception + 第 3 行（下游依赖发现行）的替代证据**；
- Mode A（装下游 jar）= 期望四行齐；
- **禁止**把"三行"当作"四行等价"通过；「无新增错误」必须**锚定明确的基线文件**（同一 run 环境下、改动前最后一次起服日志），只贴控制台 tail 不算证据闭合。

**步骤 2**：把**完整**控制台输出存成 **`debug-logs/测试记录/阶段N-起服日志-<块名>.log`**（UTF-8；命名沿用 `阶段N-…-<块名>.log`，例：`debug-logs/测试记录/阶段4-起服日志-B0b3.log`）。**不要**只存 tail。

**步骤 3**：现算身份（**这一步不能省**）：
```powershell
Get-FileHash "debug-logs/测试记录/阶段N-起服日志-<块名>.log" -Algorithm SHA256
Get-Item     "debug-logs/测试记录/阶段N-起服日志-<块名>.log" | Select-Object Length,LastWriteTime
```

**步骤 4**：入库（**该目录有否定规则 ⇒ 正常 `git add`，无需 `-f`**）：
```powershell
git add "debug-logs/测试记录/阶段N-起服日志-<块名>.log"
git status --porcelain        # 确认该文件出现在暂存/已跟踪状态
git ls-files debug-logs/测试记录 | Select-String -Pattern '\.log$'   # 确认它现在被跟踪
```

**步骤 5**：在交付小结/验证报告/评审报告里**这样引用**（四个要素缺一不可）：
```
证据：debug-logs\测试记录\阶段4-起服日志-B1.log = 6076 B / mtime 2026-09-17 17:41:00 /
      SHA256 A693B72D…43F4C2（现算于 2026-09-17 17:48）；
      模式 = Mode B；三行位于 :NN/:NN/:NN；与锚点 docs\…-t2ModeB.log 的正序集合差 = 新增 0
```
> 上面这行本身只是**格式示例**；里面的数字会过期，引用时请重算。

**步骤 6**：若同一段日志你还留了副本在 `debug-logs/`（很常见），**引用只能写 `debug-logs/测试记录/` 那份**；写"见 debug-logs/…"等于引用了一份不入库、随时可能消失的文件。

## 6. 复算命令（把 §3 的盘点现场核一遍）

## 7. 常见错误（照抄会被评审打回）

1. **把起服日志留在 `run/logs/latest.log` 就写进小结** —— 下次起服即被轮转覆盖，证据灭失。
2. **放进了仓库却忘了 `git add`** —— 文件在本地看着"在文档里"，`git ls-files` 里却没有。**本项目真的发生过三次**（`阶段4-起服日志-B1.log`、`t2-build.log`、`t2-阶段0-build.log`），已于 2026-09-17 全部升格入库（见 §3.1 的"升格记录"）。**注**：放进 `debug-logs/测试记录/` 的日志有否定规则，正常 `git add` 即可；**其它位置**的 `*.log` 仍需 `git add -f`。
3. **只贴控制台 tail** —— 工程口径要求"无新增错误"必须锚定基线文件并给集合差。
4. **用仓库里的旧副本冒充本次证据** —— 身份（字节/mtime/SHA256）对不上。
5. **把调试日志抄进交付小结当证据，却不入库** —— 违反 §1 判定口径；要么升格到 `debug-logs/测试记录/` 并入库，要么在正文里明确写"该文件不入库、仅作排查记录"。
6. **把 agent 间交流信息写进项目介绍文档** —— 介绍文档只描述项目本身；过程性内容一律放 `debug-logs/测试记录/`（见 §5 第 5 条）。
6. **忘记写模式（Mode A / Mode B）** —— 工程硬要求："交付小结与验证/评审报告都必须明写模式；不写 = finding"（`debug-logs/最终重构指南.md` §6.3 构建与起服验收（模式必写））。
