# 01 · 插件简述

## 这个插件在游戏里做了什么

先完全不看代码，只看玩家能看见的四步：

1. 玩家进服，输入一条命令选角色，例如 `/role set meiqihezi`；
2. 屏幕下方的**快捷栏**立刻被摆好：第 0 格是主武器，第 1、2、3 格是三个技能；
3. 玩家拿着某个技能，按右键（或左键、或丢弃键 `Q`）就能把它放出去，屏幕上有音效与粒子；
4. 放完之后，那一格的图标**变灰**、名字后面开始**倒数**；数到 0 之后图标恢复原样，又能再放一次。这个"暂时不能再放"的状态就是**冷却**。

所以一句话：**这个插件给玩家一套技能包**，并负责技能什么时候能放、放完要等多久、图标长什么样。

## 它在服务端里处在什么位置

- 它是一段**在服务端上运行的代码**。服务端是玩家连进来的那台程序（Minecraft 的服务端软件），玩家的动作由服务端处理。
- 服务端启动时会去自己的 `plugins/` 文件夹里找插件文件（`jar`，即打包好的代码）并加载它们。本插件加载完成后，控制台会打印一行 `ShadowHunter Character System enabled.`；看到这一行就说明它在跑了。
- 加载之后它做两件事：**记住每个玩家的角色**，以及**响应玩家按键**。也就是说，玩家在游戏里做的动作 → 插件收到 → 插件做出反应（放技能、进冷却、改图标）。

> 装到服务端的完整步骤、命令清单、已知问题：见上一层的 `../README.md`（本文档组不复述）。

## 与配套插件的依赖关系

同一个工作区里还有一个配套插件 `SHDFGamePlugin`，它的配置里写了这样一行：

```yaml
depend:
  - ShadowHunterRolesPlugin
```

意思是"我依赖 ShadowHunterRolesPlugin"。所以：**两个插件一起用时，必须先有本插件**（先把它放进 `plugins/`），否则配套插件无法启动。

本插件同时通过服务端提供的接口把自己的能力开放出去（其它插件可以借此读写玩家的角色、能量等），这层细节等你写完自己的角色、想看更多时再翻 `../架构与组件模型.md` 即可。

## 一个角色由哪些东西组成

### 先看一张清单

想象你写过一个函数来管理背包：

```
背包 = 空列表
背包.添加("铁剑", 位置=0)
背包.添加("火球术", 位置=1)
```

这个插件里的**角色**就是这种东西：一张清单。清单上写着"这个角色的 0 号位放哪个主武器、1 到 3 号位放哪些技能、另外还挂上哪些被动"。

清单本身真的写在代码里，位置是 `src/main/java/com/shadowHunterRolesPlugin/registry/RoleLoader.java`。打开它，最先看到的是一个列表，里面每一项是一个角色：

```java
return List.of(
        new Definition("meiqihezi", RoleLoader::meiqiheziBuilder),
        new Definition("red", RoleLoader::redBuilder)
);
```

`List.of(...)` 就是"造一个列表"（读法：一个列表，里面有两张"小纸条"，每张写着角色 id 和"用哪个函数来装配它"）。往下看 `meiqiheziBuilder()`，就能看到那张清单是怎么被一句句填出来的：

```java
return new Role.Builder("meiqihezi")
        .addSkill(ID_MEIQIHEZI_UNCONCERN, MeiqiheziUnconcernSkill::new, 1)
        .addSkill(ID_MEIQIHEZI_BLOODY_SLASH, MeiqiheziBloodySlashSkill::new, 2)
        .addSkill(ID_MEIQIHEZI_CIRCLE_SLASH, MeiqiheziCircleSlashSkill::new, 3)
        .addMainWeapon(ID_MEIQIHEZI_JUEJUE_MAIN_WEAPON, MeiqiheziJuejueMainWeapon::new, 0)
        .addPassive(ID_MEIQIHEZI_EQUIPMENTS, MeiqiheziEquipmentsPassive::new);
```

一行行读：`addSkill(某个名字, 用哪个类来造, 放在第几格)`；`addMainWeapon` 最后也多写一个数字 `0`，意思是"放 0 号位"；`addPassive` 后面没有格子号 —— 被动不占快捷栏，它是一直在后台干活的东西。

> 这三句现在**仍然能用**（框架保留的旧写法）。新的写法把三句合并成一句 `.addComponent(某个名字, 用哪个类来造, 放在第几格, 这是什么组件)`，`04` 第 2 步用的就是它。

### 三层关系

| 层 | 是什么 | 在哪里 |
|---|---|---|
| 角色 | "清单"本身：有哪些技能、哪些被动、哪个主武器、血量与能量上限 | `registry/RoleLoader.java` |
| 组件 | 清单上的每一件东西（技能 / 被动 / 主武器） | `roleComponent/` 文件夹下 |
| 关系 | 玩家输入 `/role set meiqihezi` 时，程序照清单给**这个玩家**每一件东西各造一份挂上去 | `manager/RoleManager.selectRole` → `core/RoleInstance` |

三类组件的分工：

- **技能**：玩家按键才动，有冷却、可能有能量消耗；
- **被动**：玩家不按键也一直在后台干活（例如"周围没有敌人时每秒回能量"）；
- **主武器**：占 0 号位，攻击玩家或左键时动。

`04-如何创建一个自己的角色.md` 要做的，就是给这张清单**加一行**，并写出那一行需要的新组件。

## 动手看一眼（可选）

把这两条命令粘进 PowerShell（在仓库根目录执行），就能看到上面提到的清单与技能：

```powershell
git grep -n "new Definition(" -- src/main/java
git grep -n "addSkill(" -- src/main/java
```

两条都会打印出源码里的行号与内容 —— 你看到的就是本文说的那张清单。
