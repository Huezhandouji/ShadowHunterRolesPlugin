# debug-logs/测试记录/ · 文件级台账与阅读指引

> **本件是什么**：`debug-logs/测试记录/` 的**文件级台账**（逐文件一行）＋**分类阅读指引**＋**新增文件命名规范**。
> 它与 `debug-logs/README-文档索引.md` §4 的**文档地图**分工不同：文档地图按用途列**代表性条目**；本件是"这一百多个文件**各自**是什么、**能不能引**、**怎么引**"的**逐件清单**。
> **身份一律现算**：台账里的 bytes / mtime / SHA256 均为**生成时刻**用 `Get-Item` + `Get-FileHash` 现算（见 §6 口径声明）；引用任何一件时请**重算**，不要照抄本件的数字。
> **硬约束（本件为什么要存在）**：本目录多为**冻结证据** —— 已入库的报告引用它们时带 bytes + SHA256 + 时点 ⇒ **移动 / 改名 / 合并都会让既有引用悬空**（工程纪律：历史记录里的旧路径视为『当时路径』，引用以**当前位置**为准并注明）。所以对这批文件的整理**只能只增不改**：本件**没有**移动、改名、删除或**改写**任何既有文件；判据与原始输出见同目录 `阶段5-测试记录整理-说明.txt`。
> **写作时刻**：2026-09-19（阶段 5 结案后）。

## §1 怎么用本件（三步）

1. **先定类别**：在 §2 找到目标文件所属的**类别章节**，读它的三句话（这是什么 / 能不能引 / 怎么引）—— 这一步决定"这份文件是不是证据、引它要不要带身份"。
2. **再查台账**：在 §3 的**文件级台账**里按文件名定位那一行，拿到 `bytes / mtime / SHA256` 与**一句话用途**，以及**谁引用了它**。
3. **要引用就先重算**：台账里的身份**只是生成时刻的读数**；正式引用前按 §6 的命令重跑一遍，并写明**统计范围**（哪个目录、含不含子目录）。

> 若目标文件**不在** §3：说明它是在本台账生成**之后**新增的 —— 请按 §4 的命名规范起名，并在**本次提交**里为本件补一行（**只增行，不改既有行**）。

## §2 分类（8 类；每类给「这是什么 / 能不能引 / 怎么引」）

### 2.1 冻结证据 · 日志（`*.log`：起服 / 构建 / 探针）
- **这是什么**：一次**起服（Mode B）或构建**留下的**原始控制台全量输出**，是"这一代制品跑起来是什么样"的**证据本体**；名字里带 `阶段N` / 批次（`B3` / `T2b` / `t15复跑2`）。
- **能不能引**：**能，而且必须带身份** —— 它是**冻结件**，引用要写 `bytes + SHA256 + 时点`，且**以现算为准**。
- **怎么引**：`「文件名 + 身份(现算) + 时点 + 来源轮次」`；做集合差时要点名**锚件**（如 `阶段1-起服锚点-t2ModeB.log`）。

### 2.2 停服物证（`*-停服物证.txt` / `*-停服证据*.txt` / 控制台记录）
- **这是什么**：**停机动作**的物证 —— 通常含"停机前先在仍在线时冻结 / 只杀进程 / 停服后三路互证（端口不再监听、连接被拒、jar 可独占打开、无残留 java）"。
- **能不能引**：**能，必须带身份**；它是**停机纪律**是否被遵守的判据，通常与同轮日志**成对**引用。
- **怎么引**：`「日志件 + 物证件」成对引`（判据 = 日志/物证 的 **F1 序**：制品 → 冻结件 → 物证 → 报告；项序列口径见 `口径澄清-F1链的项序列.md` §1）。

### 2.3 独立验证 / 评审 / 复核报告（`*验证报告.md` / `*评审报告.md` / `*独立复核*.md`）
- **这是什么**：由**非实现者**独立现算后写下的**判据结论**（verdict + 分级 findings）。
- **能不能引**：**能**；但它们是**结论件**，不是证据本体 ⇒ **引用结论时要点到它背后的证据件**（日志 / 物证 / 源码取证）。
- **怎么引**：`「文件名 + 章节」`（如 `阶段5-4.4接管-评审报告.md` §13 的卡面映射表）；**行号只作定位**（移动靶），**不要**只引行号。

### 2.4 判据 / 需求 / 规范（判据集、归档规范、协同规范、卡编写指南）
- **这是什么**：**冻结的判据集**（期望值 + 命令 + 口径）与**长期规范**（归档二分法、起服停机纪律、任务卡写法）。
- **能不能引**：**能，且优先级最高** —— 判据集是"期望值"的唯一来源；引用规范件时引**章节**。
- **怎么引**：`「文件名 + 章节 + 内容片段」`；判据集还需写明**它的 before 值绑定在哪一代**（点名 `commit` / `tree`）。

### 2.5 取证 / 勘误 / 口径说明件（`*说明.txt` / `*勘误*` / `口径澄清*` / `开放项*` / `工具缺陷注记*`）
- **这是什么**：**解释性**文件 —— 交付说明、勘误与读法、口径澄清、开放项、仪器缺陷注记；多数是**活文档**（可被追加/取代）。
- **能不能引**：**能，但按活文档口径**：引 `§章节 + 内容片段`，**不要挂易变哈希**；被**取代**的版本只能作**留痕**引用并显式标注『已作废 / 仅存留痕』。
- **怎么引**：`「文件名 + §章节」`；若该件声明了"就地修订 + 取代申报"，引用一律按**新版身份**。

### 2.6 冒烟 / 演练 / 转录记录（`*冒烟清单*` / `*演练记录*` / `*转录*` / `*-console.txt`）
- **这是什么**：**人在环**或**探针在环**的行为记录：双角色冒烟清单（填表）、回滚演练、mineflayer 探针的 chat 侧转录。
- **能不能引**：能；转录属**运行级证据**（可作证据本体），冒烟清单属**待执行清单**（未填 = 未执行，**不得**当"已冒烟"引用）。
- **怎么引**：`「文件名 + 身份(现算) + 该轮的起服日志/物证」`；清单类要写明"谁执行、是否已填"。

### 2.7 过程记录（进度 / 交接 / 运行清单 / before-after 读数）
- **这是什么**：**项目过程**的滚动记录：重构进度与交接、接任者交接总账、执行清单、双口径 before/after 读数。
- **能不能引**：能；属**滚动件** ⇒ **不挂身份**，引用用 `「文件名 + 章节 + 内容片段」`；其中的数字会漂移，引用前**复算**。
- **怎么引**：`「文件名 + §章节」`；引"代"必须**点名 commit / tree**（**不得**用"当前 HEAD 所指的那棵树"这类相对说法）。

### 2.8 工装副本与脚本（`*.ps1` / `*.js`）
- **这是什么**：**仪器**本身（措辞检查、判据工具、冒烟探针）。多数原版在仓库外（`.scratch/`），本目录的副本是**受管留痕**。
- **能不能引**：能；引用要写明**版本身份**（bytes + SHA256）与**自检结果**（`--selftest` 之类），否则"工具说 OK"不成立。
- **怎么引**：`「文件名 + 身份(现算) + 自检输出」`；**不得**用它的自报结果替代判据（仪器必须**双向自证**）。

## §4 新增文件命名规范（**只对新增生效**）

**模式**：`<阶段或批次>-<主题>-<体裁>.<扩展名>` —— **三段式**，主题内部用 `-` 连接。

- **一段** = 阶段或批次：`阶段5` / `阶段4` / `批次名`（如 `清理批`）；
- **二段** = 主题：**谁**（`调度器迁移` / `控制台输出` / `4.4接管`）+ 可选**轮次**（`复核` / `外观取证` / `取证`）；
- **三段** = 体裁**闭集**：`起服日志` / `停服物证` / `评审报告` / `验证报告` / `独立复核报告` / `说明` / `勘误` / `转录` / `工装` / `需求与验收`。

**正例（均为存量真名 ✓）**：
1. `阶段5-起服日志-控制台输出-取证.log` —— 阶段 + 体裁 + 主题 + 轮次，四段仍可读；
2. `阶段5-调度器迁移-评审报告.md` —— 阶段 + 主题 + 体裁（结论件）；
3. `阶段4-T块独立验证报告.md` —— 阶段 + 批次块 + 体裁；
4. `阶段5-需求与验收.md` —— 阶段 + 体裁（判据集）。

**反例（均为存量真名 ✗，**不改名** —— 仅作新件避坑）**：
1. `t2-build-x.utf8.txt` —— 内部代称 `t2` + 无阶段号 + 双扩展语义（`.utf8.txt`），读者无法判断体裁；
2. `阶段4-起服日志-t15复跑3-误捕（属20-18-07那一次他人起服）.log` —— **括号注记与时间戳片段入名**，名字长度失控、且"误捕"这类**结论**写进了文件名（结论应写在正文，不写进名字）；
3. `platform-wording-check.ps1` —— 英文工装名，无阶段 / 主题 / 体裁，无法与仓库内其它件排序对照；
4. `阶段5-4.4外观取证-停服物证.txt` 与 `阶段5-4.4接管-外观取证报告.md` —— **同一主题两种写法**（`4.4外观取证` vs `4.4接管-外观取证`）⇒ 检索时容易漏掉其中一件。

**明文纪律**：
- **存量文件一律不改名** ✗ —— 它们是**冻结引用**的目标；改名会让既有引用悬空。
- **新件不得**把**结论**（如"误捕""修正版""最终版"）写进文件名；结论写在正文，名字只写**阶段 / 主题 / 体裁**。
- **新件不得**使用**括号注记**、**空格**、**大写扩展**；扩展按体裁固定（日志 `.log`、物证与说明 `.txt`、报告与台账 `.md`、工装 `.ps1` / `.js`）。
- **同一主题同一轮次**只允许一件：轮次写在**二段**（如 `-复核` / `-外观取证`），不要靠"修正版 / 最终版"递增。

## §6 口径声明（必读）

- **身份现算时刻**：台账三列（bytes / mtime / SHA256）在**本件生成时刻**用 `Get-Item` + `Get-FileHash -Algorithm SHA256` 现算；行数口径 = `[System.IO.File]::ReadAllLines(..., UTF8)`。**任何引用前请重算**。
- **统计范围**：**仅本目录顶层**；`debug-logs/测试记录/` 下**没有子目录**（顶层文件数 = 递归文件数，两者都打印在 `阶段5-测试记录整理-说明.txt` §3）。

- **引用列来源**：对 `debug-logs/**` + `docs/**` + 仓库根 `*.md` 做**一次性字面横扫**（扫描发生在本台账落盘前）；**本台账自身不在扫描集内**，复核时必须扣除本件（否则每个文件名都会"被本件引用"）。
- **`git` 口径**：`debug-logs/**` 被 `.gitignore` 忽略 ⇒ 本目录新增件**不会**出现在常规 `git status --porcelain` 里（要看得加 `--ignored` 或 `--untracked --no-exclude-standard`）；入库需维护者显式 `git add -f`。
- **不内嵌自身哈希**：本台账**自身的身份不写进本件**（避免自指失效，与 `阶段5-勘误与读法说明.txt` §6 同一条纪律）；它的结卡身份记录在 `阶段5-测试记录整理-说明.txt` §3。
